# DS 直接回答链路验证（2026-10-11）

## 当前默认逻辑

用户原文与对话 → 并行提取流程意图/用户资料、检测缺口、检索 → 程序处理报价/资格等确定性路由 → DS根据原问题与证据直接生成普通文本短答 → 护栏/重试/兜底。

默认 `Pipeline(direct_answer=True)`。Qwen只保留流程意图与用户资料提取，不执行责任/主题/待答项规划请求。DS输入没有逐项JSON槽位、没有外部问题清单；不再拼接槽位答案。旧模式 `direct_answer=False` 仅用于回归比较。

检索直接使用用户原文；当地责任目录的词法检索与别名匹配补充对应条款，避免“靶向药”漏检“特定药品”。这些是证据检索，不是模型拆题。流程、报价引擎、确定性资格规则保留。STT/TTS未改。

首次直接路径漏检R06，导致把靶向药只说成重疾医疗；已补证据别名并复跑。早期记录留在 `exp25_direct_chain.json`，最终比较使用 `exp25_direct_chain_v2.json`。结果保存改成临时文件后原子替换，支持中断续跑，避免Windows并发读取影响写入。

## 实调用对照

模型 DeepSeek Flash，thinking关闭，temperature=0.3。8题×2版本×2轮，共32个完整文字链路回答。第二轮反转版本顺序。两个版本分别运行各自理解和检索，测的是整套文字链路；不是固定证据的prompt消融。

|指标|旧拆题/槽位模式|直接回答模式|
|---|---:|---:|
|有效回答数|16|16|
|文字链路中位耗时|2.473秒|1.536秒|
|最终字数中位数|97|88|
|整段兜底次数|4|0|
|两版均正常回答的12组配对样本：中位字数|184.5|95.5|

所有回答的字数统计包含兜底，旧版短兜底会压低中位数；故另列正常回答配对统计。兜底减少不代表正确率100%，也不能把小样本收益外推到全量或语音首声。

实际记录的DS请求确认：直接版没有逐项槽位格式要求、没有response_format JSON；trace首项mode=direct、obligations为空。跟踪包含原问题、检索责任/证据ID、每轮校验、放行来源，原始模型请求另存answer_messages。

## 人工检查与剩余问题

- 门急诊加油包与基础版对比不再多次重复同一免赔/比例，直接版两轮127/141字，旧版265/264字。
- 特药与基因检测题两轮均回答特药600万额度及投保社保身份条件；仍有重复、较长，178/198字。第二轮未明确说增值服务基因检测不限额。
- 家庭共享题两轮保留需另购、同一投保人同一订单、一般门急诊不共享和4人15%优惠；第二轮还主动介绍2人5%，留白仍不稳定。
- 护工题两轮仍漏“指定或认可机构提供服务”前提。护栏未拦住；一轮先被“一天”数字误判后重试，重试也没有补齐机构条件。
- 简单月上限题缩到29/30字，但仍带另购说明，没有稳定做到仅给一个数字。

因此本次验证支持切换回答结构、减少外部拆题与重复，但不能宣称条件完整性已全部解决。保留直接路径为当前实现，后续针对遗漏必需条件修提示词并回归。
