# 原文页码与行号定位

2026-10-11。已生成 `data/clean/locations/pdf_source_index.json`，覆盖4份PDF、248段提取文字。

每段包含原PDF路径与SHA256、PDF页码、该页提取文本起止行、提取文件起止行、MD行号，以及页内去空白字符的精确范围。正文仍取自原文，未做模型摘要或保险事实改写。

## 示例

`投保须知#5`（有医保身份投保但未医保结算的60%条款）现在对应：

```json
{
  "raw_path": "data/raw/尊享百万/尊享E生百万医疗2026投保须知.pdf",
  "page": 1,
  "page_text_line_start": 10,
  "page_text_line_end": 12,
  "clean_path": "data/clean/text/尊享E生百万医疗2026投保须知.md",
  "md_line": 10,
  "extracted_file_line_start": 11,
  "extracted_file_line_end": 13
}
```

行号从1开始，表示pdfplumber提取文本的行，**不是PDF印刷行号或页面像素坐标**。一段清洗文字可能横跨多个原提取行，或与另一段共用一行；页内字符范围可以进一步确定对应内容。

Excel保留工作表、责任行范围和单元格，例如ICU500元条款对应原责任Excel的`保障责任!D118`，所属责任行117–119。费率PDF这里只定位能提取的文字说明，图片表格数字继续使用CSV行号；未生成图片格子的像素坐标。

## 接入

- `knowledge._text_chunks()`保留原有Chunk ID和正文，在meta与source中补定位；原检索链路可读取页码/提取行号。
- 实验`Evidence`新增location，模型证据文本包含简洁定位。文件哈希保留在trace中，不逐条占用模型上下文。
- 模型选择source_ids后，canonical引用同时带原文和location；责任bundle内单元格引用保留父责任上下文及具体单元格。
- 原有实验输出和冻结源快照未重写；当前位置仅作用于新生成证据。
