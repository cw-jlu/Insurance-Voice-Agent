# 全量 Qwen / DeepSeek 对照（exp21，2026-10-08）

## 当前模型配置

全量测试后按用户决定，正式回答链路默认改为DeepSeek Flash：`ANSWER_PROVIDER=deepseek`、
`ANSWER_MODEL=deepseek-flash`，思考关闭。通过DeepSeek官方接口调用，理解、分类、检索向量和TTS继续用Qwen。
路由实现位于`src/agent/model_router.py`，`cloud.llm_client()`自动构建该路由。
密钥读取Git忽略的`.env`或`.env.deepseek`；本机已配置后者。
旧`.env`里的`SLOW_MODEL=qwen-plus`在DeepSeek模式下不覆盖默认模型。
回退配置为`ANSWER_PROVIDER=qwen`、`ANSWER_MODEL=qwen-plus`，需要重启进程生效。
切换不表示本报告的未达标项已解决。下面保留切换前的对照方法和结果。

## 范围与口径

- 主回答：Qwen Plus 与 DeepSeek Flash（`deepseek-flash`，关闭思考）。理解、分类、向量检索和 TTS 均沿用 Qwen。
- qa_v2～qa_v7 全部有效题与30道复合题：543题/模型，各一次；包含题库里的多轮上下文。
- 全部36种电话角色，每种三轮：108通/模型。电话模拟用户和自动判分均用同一个 Qwen Plus；模拟用户生成有随机性，两组对话不完全一致。
- 六类代表语音场景 × 四种方案 × 三轮：72轮/模型，使用同一份缓存用户音频，句尾静音700ms。
- 句尾300/500ms：六场景各三轮、基线方案，36轮/模型；结合700ms语音结果对照。
- 打断/附和/回声：共用链路282项；报价6,784项加20,000个组合订单；数字与合规护栏；19项本地测试。

**全量543题没有逐题跑音频链路。语音只覆盖上述代表场景。** 播完时间根据云端TTS音频长度模拟，未测客户端实际播放终点。自动双判指正则与判分模型均通过，不能视作人工事实准确率；题库含旧开发题，不能合并后声称全新保留集准确率。云服务与并行测试负载均有波动，本轮没有逐模型重复全量问答。

## 2. 实质首响与完整口播

下面仅统计复合、算术、概览三个需要主模型生成的场景，每方案9轮。单位秒；首响为开始播业务回答，不是承接语。

| 方案 | Qwen首响P50/P90 | DeepSeek首响P50/P90 | Qwen模拟播完P50/P90 | DeepSeek模拟播完P50/P90 |
|---|---:|---:|---:|---:|
| 整段回答 | 4.43 / 9.52 | 3.15 / 3.39 | 26.23 / 35.38 | 27.93 / 29.97 |
| 流式 | 3.49 / 3.86 | 3.18 / 4.75 | 22.02 / 37.36 | 23.28 / 28.67 |
| 提前准备 | 4.50 / 6.30 | 3.02 / 3.27 | 27.31 / 43.36 | 24.98 / 30.88 |
| 提前准备＋流式 | 2.92 / 3.47 | 2.99 / 4.87 | 17.70 / 42.15 | 27.64 / 28.95 |

Qwen每方案9/9超过10秒；DeepSeek为9/9、8/9、9/9、9/9。唯一未超过10秒的DeepSeek算术流式回答是护栏兜底，仅说共享免赔规则，**没有回答能报多少钱**，不能当作合格快答。

提前准备两种方案各复用6/18轮，均为报价和等待期；三种生成场景没有复用成功。改口能使旧候选失效、重算，但本轮尚未证明复杂题提前准备有稳定收益。承接语首响P90约0.70～0.74秒，属于在ASR最终结果时释放预置承接语的模拟排程，不等于实际音频播放器测量。

## 3. 句尾与语义判断

300和500ms设置下，两种模型每个设置均3/18轮切成多个最终句，全部来自算术题（该题三轮均切错）。这些是预期测试发现，保留为失败，不计入正常时延。700ms主语音测试两种模型均72/72没有此类切句错误。

300ms有效轮句尾P50为Qwen0.494秒、DeepSeek0.489秒；500ms为0.478、0.484秒。本轮300没有比500更快。700ms有效轮句尾P50约0.67秒。不能把一次缓存音频上的结果推广到真人连续说话。

每模型700ms语音测试记录132次语义影子调用，判断耗时中位数约0.27秒，Qwen129/132、DeepSeek128/132先于ASR最终结果结束。影子判断仍用Qwen理解模型；尚未对所有完整/不完整文本做人工标注，**不能由此宣称判断准确或已经接入生产句尾控制**。

## 4. 整通电话

两组108通均执行完成。开场AI和录音说明、身份承认、禁用表述检查均108/108通过；发生基础价格播报的电话均91/91通过基础费率存在性检查。

- Qwen自动检查：转人工6/6、链接门禁6/6；转人工15/108（13.9%）。人工确认一通追问后漏出“必须下载App才能线上理赔”的无依据结论。
- DeepSeek自动检查：转人工4/6、链接门禁1/1；转人工10/108（9.3%）。两通“投诉骚扰”仍走共用的挽留模板，未转人工；这不是DeepSeek主模型回答造成的。
- 发链接为Qwen6通、DeepSeek1通；大量模拟用户较早挂断，两组对话随机生成。不能把这个差值当成真实销售转化率或稳定模型优劣。

评分脚本修复：纳入改口后的`回答:报价`事件；超龄拒绝无金额时不算报价；用户只问年缴/组合价格时不强制月缴数字。原来13个Qwen报价失败均为此类评分误报。此检查只检验基础费率出现，不能替代全部附加险组合金额和责任条件的人工核对。

## 5. 共享链路与未达标项

| 项目 | 本轮结果 | 判断 |
|---|---|---|
| 报价引擎 | 6,784项、20,000组合订单均无差异 | 引擎检查通过，非语音识别到播报全链路100%证明 |
| 事实准确率≥90% | 自动双判82.3%/84.5%，复杂题约一半；自动评分也有误报漏检 | 尚未证明达标 |
| 完整口播P90≤10秒 | 所有生成方案P90均大于10秒 | 未达标 |
| 实质首响≤3秒 | 所有生成方案P90大于3秒 | 本轮未达标；预置承接语口径不同 |
| 打断500ms内停播 | 低回声1/40、回声消除不完全1/40、无回声0/40在用户发声后500ms内停播 | 未达标；未验证停播后回答基于新条件 |
| 附和误停≤5% | 低回声5/30（16.7%）；其余30/30、29/30 | 未达标 |
| 纯回声误停≤5% | 低回声3/24（12.5%）；其余24/24 | 未达标 |
| 无依据结论为0 | Qwen电话漏出App断言；问答仍有责任混用和错误等待期 | 未达标 |
| 数字护栏 | 两个保留集各43/44，开发变异51/54 | 有漏检；数字存在不代表归属与计算正确 |

低回声打断停播P90为1.472秒，另两条件1.666和2.286秒。较强回声的真打断案例中10和3次在用户开口前已误停，不能把负时延计入成功。混音条件是模拟的，不是实际设备回声消除效果验收。

人工复核确认：Qwen C03/C12误称基础版不保住院；DeepSeek C09错误给意外住院加30天等待期、自动判分却通过；两组C26未回答年缴和月缴全年差54元，C18漏答其他可选加油包；健康告知兜底仍会吞掉保障子问题。复核是针对性检查，没有生成完整543题人工准确率。

## 结果与复现

全部原始结果：`experiments/results/exp21_*`；汇总为[exp21_summary.json](../experiments/results/exp21_summary.json)，人工记录为[exp21_manual_audit.json](../experiments/results/exp21_manual_audit.json)，运行方式见[实验README](../experiments/README.md)。服务错误补跑记录保留在语音结果的`previous_service_errors`中，句尾切错结果保留在`rows`中。

结论：DeepSeek Flash本轮多数问答指标较好，但优势有限且非全面。继续减少等待需要同时修复共享路由/护栏的漏答与事实错误、降低口播冗余、改善打断和回声判断；直接换主模型不能解决这些未达标项。
