# 准确率与首响验收（2026-10-11）

## 结论

DS Flash 直接回答模式未通过准确性验收。已经恢复 `Pipeline.direct_answer=False` 为默认；直接回答模式保留显式开关用于实验。主模型仍为 DS Flash。旧链路也存在错误，恢复默认不能视为准确率已达标。

## 方法和原始记录

- 文本：71题（30道复合题、41道单轮题），新旧链路各一次，共142次实际生成。记录：`experiments/results/exp26_accuracy.json`。
- 语音：等待期、住院/门诊/ICU复合题、共享免赔算术、保障概览，各两轮，新旧共16次。记录：`experiments/results/exp26_first_audio.json`。
- 同一缓存合成用户音频，实际腾讯云 ASR、DS Flash 回答、Qwen 实时 TTS。VAD 700ms；Cherry，语速1.2；TTS连接预热；没有垫话或提前生成。STT/TTS参数未调。
- 首响为输入语音结束至收到实际首个 TTS PCM 的时间，不是扬声器物理播放测量。语音时长为实际生成 PCM 时长。
- 文本采用并发三任务，耗时不能当作隔离服务延迟。语音顺序第一轮旧→新、第二轮新→旧，样本不足以证明稳定收益。

## 结果

|指标|旧链路|直接回答|
|---|---:|---:|
|文本规则匹配|62/71（87.3%）|61/71（85.9%）|
|模型严格评分通过（未经完整人工校准）|38/71（53.5%）|43/71（60.6%）|
|文本链路耗时中位数|1.710秒|1.345秒|
|语音首帧PCM中位数（各8次）|2.272秒|2.054秒|
|完整生成语音时长中位数|13.593秒|16.258秒|

严格评分模型存在误判，以上通过率不能直接作为真实准确率，也不能据此声称新版准确率更高。首响数值包含错误回答；错误回答的快速出声不算验收成功。没有服务错误。

## 人工核对的明确退步

1. C01：“我妈62岁有医保，住院和看门诊分别怎么报，进ICU有没有补贴”。旧版回答基础版住院/门急诊共享1万免赔、100%/60%以及ICU需另购500元/日；新版检索 R15/R14/R13，遗漏 R01/R02，改答门急诊需另购、62岁不能买门急诊加油包。混淆基础保障与附加责任。实际音频复合题两轮也出现同类错误。
2. C03：“住院花了一万五，自己出多少，没走医保会怎样”。旧版在免赔未用、无其他补偿、合规费用假设下算5000元或3000元；新版直接15000×60%=9000元，漏扣1万元免赔。其检索遗漏 R01。
3. C14：“住院10天能拿多少津贴，进了3天ICU呢”。旧版给出普通津贴700元及ICU1500元；新版兜底只给ICU限额，漏答金额和普通津贴。
4. C20：“我有甲状腺结节，买了以后结节手术能报吗，加了住院补偿加油包呢”。旧版明确既往症限制和加油包不消除除外责任；新版只给通用核保兜底，漏答用户问题。

评分模型误判例：C03旧版已经明确有社保身份及费用假设，评分仍称缺失；Y026直接回答不确认续保年龄，评分却引入证据中没有的续保到99/100岁；Y040两版相同的续保转专员回答被误判。自动标记退步的C22旧答案本身有问题，不能计为有效退步。

## 音频中的额外发现

- 等待期题：旧版首响1.654/1.851秒，新版1.327/1.406秒；这类简单题有改善。
- 复合题：旧版1.717/1.932秒，新版2.049/2.403秒；新版更慢且误答基础门急诊。
- 共享免赔算术：急诊5000+住院20000，假设免赔未用、无其他补偿、费用符合责任且社保结算，应合并扣10000后赔15000。旧版两轮均答10000，重复扣免赔；新版两轮均给15000，但第一轮中间表述“剩余2万中的1.5万”混乱，且附带无关健康追问。
- 概览旧版第二轮触发长答案，生成语音93.78秒、首响6.718秒；新版也未稳定做到短答。不能把首响低于10秒理解为整段播放低于10秒。
