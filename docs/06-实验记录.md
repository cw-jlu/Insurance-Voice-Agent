## 二、实验 1：报价全量枚举

**做法**：枚举 0–105 岁 × 有无社保 × 年缴/月缴 × 男女 × 不选或选 7 种加油包之一，共 6,784 个组合。被测报价引擎（`src/agent/quote.py`）的结果与另一套独立实现（`experiments/exp1_quote.py` 中用 pandas 写的参照实现）逐一比对；另做边界抽查、家庭单 1–6 人测试。

**结果**：

| 项目 | 结果 |
|---|---|
| 价格不一致 | **0 / 6,784** |
| 不可投保组合被正确拒绝 | 2,360 个，误报价 0 个 |
| 边界抽查（30/31 岁、70/71 岁、出生 20 天、55/56 岁门急诊加油包、重疾关爱缺性别） | 11 项全部通过 |
| 家庭单 1–6 人折扣（0/5%/10%/15%/20%/20%） | 全部通过，均标记"折扣范围和取整待确认" |
| 月缴 ×12 是否高于年缴 | 可投保年龄段 30/30 全部高于年缴 |

**发现**：费率表里有**续保价格**——必选计划有 7 个 70 岁以上的年龄段，门急诊加油包在 56–70 岁也有价格，但投保须知规定首次投保被保人不超过 70 周岁、门急诊加油包不超过 55 周岁。**如果按"表里有价就能报"来写，会给不能投保的人报价。**资格规则必须来自投保须知，费率表只负责价格。

**局限**：参照实现和被测实现由同一人编写，读的是同一份 CSV；CSV 本身的正确性由数据管线的 OCR 逐格交叉校验保证（见 [data/README.md](../data/README.md)）。

## 三、实验 3：护栏

### 3.1 做法

- **数字护栏**：以方案附录 A 的 5 个正确回答为基础，程序逐个篡改其中的数字（翻倍、加一、数字倒序），共生成 54 个错误回答，检查护栏能否拦住；同时检查正确回答是否被误拦。
- **缺口结论拦截**：针对疾病核保、续保、社保抵扣免赔额三类数据缺口，构造"违规回答"（给了结论）和"合规回答"（以核保/条款为准），检查拦截的召回率和精确率。
- **禁用表述**、**AI 身份识别**：构造正例和反例。

为了避免"对着测试题调规则"，用了三组用例：

| 用例组 | 用途 |
|---|---|
| 开发集 | 编写和调整规则 |
| 保留集 1 | v1 规则写完后才写，用来发现 v1 的泛化问题；**发现问题后参与了 v2 调整，不再算作未见数据** |
| 保留集 2 | v2 调整前写好，**调整期间未查看结果**，只用于最终评估 |

### 3.2 v1 结果：规则在新问法上明显失效

| 指标 | 开发集 | 保留集 1 |
|---|---|---|
| 数字篡改拦截率 | 87.0%（47/54） | 81.8%（36/44） |
| 缺口拦截 召回 / 精确 | 100% / 84.2% | **40% / 40%** |
| 禁用表述正确率 | 100% | **0%（0/4）** |
| AI 身份识别召回 | 85% | **30%** |

v1 的问题：

1. 数字护栏只检查"数值是否在证据里出现过"，换成另一个合法数字（一般住院 300 万 → 600 万）拦不住；证据里的列表序号"1）""6）"也被当成了可用数字。
2. "能不能投保""如果能买"这类**谨慎表述**被误判为给了结论；"血压有点高"没被识别为病史问题。
3. 禁用表述不认识否定句（"不能保证续保"被误拦），也漏掉新说法（"大病小病都能报"）。
4. 身份问题问法多样（"你该不会是机器人吧""对面是人吗"），关键词规则覆盖不全。

### 3.3 v2 改进

- 数字护栏：去掉证据中的列表序号；单位必须一致；数字所在语境（前 24 字、后 8 字、句首主题）须与证据有共同词；客户用语与条款用语建立同义映射（"一般住院"↔"一般医疗"、"重疾"↔"重大疾病"等）；**查表得到的结构化数字（报价、年龄段、用户自述年龄）按数值放行**，不做语境匹配。
- 缺口和合规：先去掉"能不能/是否/如果/以……为准/不能保证"等谨慎和否定表述，再判断是否给了结论；病史问题改为"健康相关词 + 买/保/报"的组合识别。
- 身份：改为"指向对方的词 + 身份词 + 疑问语气"的组合，并排除"转人工""机器人手术"等。

### 3.4 v2 结果

| 指标 | 开发集 | 保留集 1 | **保留集 2（未见过）** |
|---|---|---|---|
| 正确回答被误拦 | 0/5 | 0/5 | **0/6** |
| 数字篡改拦截率 | 94.4%（51/54） | 97.7%（43/44） | **97.7%（43/44）** |
| 缺口拦截 召回 / 精确 | 100% / 100% | 100% / 100% | **100% / 100%**（13 例） |
| 禁用表述正确率 | 100% | 100% | **100%**（6 例） |
| AI 身份 召回 / 误报 | 100% / 0 | 100% / 0 | **100% / 0**（16 例） |

**仍然拦不住的**：同一责任内两个合法数字互换，例如 ICU 津贴"单次最多 30 天"写成"60 天"（60 天是同一责任的年累计上限），或者把"26 到 30 岁"写成"26 到 31 岁"（31 是下一档的边界）。规则无法区分这类错误。

### 3.5 结论与对方案的修改

1. **规则护栏可以作为快速第一道检查，但单靠规则不够**：v1 在新问法上的表现说明，规则只能覆盖写规则的人想到的说法。保留集 2 的结果虽好，但样本小（每类 6–16 例）且与规则出自同一人之手，不能代表真实 LLM 输出上的效果。
2. **方案修改**：
   - 缺口结论、禁用表述、身份识别采用"**规则快检 + LLM 判别复核**"两层；
   - 价格、保额、免赔额、天数等**高风险数字不让 LLM 自由书写**，由查表结果按模板填入（例如"单次最多{单次天数}天，一年最多{年累计天数}天"），从源头消除数字互换。

## 四、实验 2（检索部分）：条款检索

**做法**：语料为保障计划表每个单元格 + 投保须知 + 责任免除，按行切片，共 353 段，每段带出处。用客户口语写了 40 个问题，人工标注应命中的责任项或条款关键词。对比四种方法。

**结果**：

| 方法 | hit@1 | hit@3 | hit@5 | MRR@10 | 单次检索耗时 |
|---|---|---|---|---|---|
| BM25（字二元组） | 42.5% | 55.0% | 60.0% | 0.50 | 0.3 ms |
| TF-IDF（字 1–3 元组） | 52.5% | 70.0% | **75.0%** | **0.62** | 1.1 ms |
| BM25 + TF-IDF 融合 | 45.0% | 57.5% | 60.0% | 0.52 | 1.3 ms |
| 融合 + 同义改写 | 47.5% | 60.0% | 65.0% | 0.56 | 1.5 ms |

**典型失败**：

| 客户说法 | 条款用词 |
|---|---|
| 以前就有的病能报吗 | 既往症 |
| 生孩子的费用报不报 | 分娩 |
| 看牙能报吗 | 牙科疾病 |
| 得了抑郁症住院能报吗 | 精神和行为障碍 |
| 多大年纪可以买 | 被保险人年龄 |
| 能不能多买几份 | 限投保 1 份 |

**结论与对方案的修改**：

1. 字面检索对口语问题明显不够，**必须加入语义向量检索（阿里云百炼文本向量）和 LLM 查询改写**（把"以前就有的病"改写成"既往症"），接入 API 后复测。没有用这 40 个问题手工扩充同义词表，因为那等于对着测试题调优。
2. 融合反而不如单独 TF-IDF：BM25 太弱时会把融合结果拉低。融合只在两路检索都有一定水平时才有意义，接入语义向量后重新评估融合方式。
3. 失败集中在**免责和投保条件**，恰恰是最关键的部分。方案中"高频问题配置固定条款引用"的备选方案应**升级为主方案**：既往症、等待期、补偿原则、医院范围、投保年龄、职业、一人一份、生效时间等高频关键主题，由意图识别直接定位到固定条款，不经过检索。
4. 检索耗时在 2 ms 以内，本地检索不是时延瓶颈。

## 五、实验 4（部分）：句级流式播报与 TTS 首包

### 4a 离线：LLM 输出多少字后才能开始播

| 回答 | 总字数 | 第一段可播时已输出字数 |
|---|---|---|
| 题 a | 100 | 9 |
| 题 b | 124 | 7 |
| 题 c | 45 | 6 |
| 题 d | 45 | 19 |
| 题 e | 127 | 5 |
| 首句很长的回答 | 85 | 有软切分 61 / 无软切分 85 |

句级切分让播报在 LLM 输出 5–19 个字后就能开始，而不必等全文；长首句时 60 字软切分能提前切出第一段。

### 4b 联网：edge-tts 首个音频包时延（每项 3 次取中位数）

> edge-tts 是免费的微软云端 TTS，作为阿里云 TTS 接入前的替身，绝对值仅供参考。

| 回答 | 整段合成：首包 | 整段合成：完成 | 只合成第一句：首包 |
|---|---|---|---|
| 题 a | 0.98 s | 1.51 s | 1.01 s |
| 题 b | 0.97 s | 1.50 s | 1.15 s |
| 题 c | 1.01 s | 1.42 s | 1.03 s |
| 题 d | 1.04 s | 1.44 s | 1.00 s |
| 题 e | 1.13 s | 1.94 s | 1.01 s |

**发现**：

1. 首包约 1 秒，**与文本长短几乎无关**，主要是每次调用新建连接的开销；服务本身已经是流式输出。句级切分的收益在于不用等 LLM 写完，而不在于 TTS 本身变快。
2. 按"句尾判断 0.5–0.7 s + 首句车道 ≤0.8 s + TTS 首包约 1 s"估算，首响约 2.3–2.5 s，**满足赛题 3 秒但达不到方案自定的 2 秒目标**。

**对方案的修改**：

- **承接语音频预合成并缓存**：首句车道只输出少量固定的中性承接语，可以全部预先合成，现场直接播放本地音频，首句不再经过 TTS 网络调用。
- **TTS 保持长连接、连接复用**，避免每句话都新建连接。
- 接入阿里云流式 TTS 后复测首包时延。

## 六、实验 5（离线部分）：打断逻辑

### 5a 语义层：附和还是真打断

25 个附和（"嗯""好的""对对"）、25 个真打断（"等一下""我没有社保""那月缴多少"）。

| 版本 | 附和被误判为打断 | 真打断识别率 |
|---|---|---|
| 初版 | 8%（"嗯，好的""对的"） | 100% |
| 修正后 | 0% | 100% |

> 修正是针对这组用例做的，修正后的结果不代表未见数据上的效果。

### 5b 防回声：用"与当前播报的相似度"过滤

模拟免提时 ASR 把 Agent 自己的声音识别回来：从 10 句播报中随机截取片段并加入不同程度的识别噪声（每档 300 例）；同时把 25 句真实用户插话与每句播报配对（250 对），检查是否被误当成回声。

| 阈值 | 回声拦截（无噪声） | 回声拦截（轻噪声） | 回声拦截（重噪声） | 用户插话被误删（修正前） | 用户插话被误删（修正后） |
|---|---|---|---|---|---|
| 0.4 | 100% | 99% | 96% | 4.4% | 2.4% |
| 0.5 | 100% | 99% | 92% | 3.2% | 1.6% |
| **0.6** | 100% | 98% | 73% | 0.4% | **0%** |
| 0.7 | 100% | 96% | 53% | 0% | 0% |

**发现一个严重问题**：Agent 正在说"有社保的话，基础版一年 318 元……"时，用户说"**我没有社保**"，相似度达到 0.6，会被当成回声丢掉——而这正是赛题最看重的"打断并纠正"。原因是纠正语天然会重复 Agent 的用词，只多了一个否定词。

**修正**：用户话里出现播报中没有的否定或纠正词（"没有""不是""不对"等）时，一律不按回声处理。修正后阈值 0.6 下误删为 0。

**结论**：文本相似度过滤在重噪声下只能拦住约 73% 的回声，**只能作为声学回声消除（AEC）的补充**，不能替代。

### 5c 取消与播报账本

模拟流式生成（约每 20 ms 一句）和播放（约每字 10 ms），在随机时刻插入用户打断"我没有社保"，然后按新条件重新报价。共 300 次。

| 检查项 | 结果 |
|---|---|
| 打断时刻分布 | 开口前 10 次、播报中途 182 次、整段播完后 108 次 |
| 账本正确（已播是回答的前缀、已播和作废不重叠、二者合起来连续） | 300/300 |
| 旧回答的句子在打断后被播出 | 0 |
| 取消后旧任务仍产生输出 | 0 |
| 按新条件重新报价正确（679 元 / 每月 67 元） | 300/300 |
| 打断后又说出旧价格 | 0 |
| 进程内取消耗时 | 中位数 0.036 ms，P99 0.072 ms |

**结论**：取消机制和播报账本的逻辑正确，进程内取消耗时可以忽略。**真实停播时延**主要取决于 VAD 判定（设计为 300 ms）和客户端音频缓冲，需要接入音频链路后用录音测量。

## 七、实验 6（部分）：报价所需条件的抽取

30 句口语，用例在运行前写好，运行后未改规则。

| 条件 | 正确率 |
|---|---|
| 年龄 | 15/18 |
| 有无社保 | 11/12 |
| 缴费方式 | 5/5 |
| 为谁投保 | 10/10 |
| 性别 | 9/9 |
| **整句全部正确** | **26/30** |

**失败的 4 句**："我父母都七十了还能买吗""我二十九""我妈五十八了"（口语年龄不带"岁"）、"没买过社保"。

**结论与对方案的修改**：规则抽取能覆盖常见说法，但口语变化多。方案改为：**由 LLM 抽取条件，规则作为兜底**；年龄、有无社保这类决定价格的关键条件，**报价前复述确认**（"您是 29 岁、有社保，对吧？"）。复述确认还能纠正语音识别错误。

## 八、实验发现对方案的修改汇总

| 发现 | 来源 | 方案修改 |
|---|---|---|
| 费率表含续保价，按表报价会给不能投保的人报价 | 实验 1 | 资格规则以投保须知为准，报价引擎单独校验 |
| 规则护栏在新问法上效果差 | 实验 3 | 规则快检 + LLM 判别复核 |

| 每次新建 TTS 连接约 1 秒，首响 2 秒目标有风险 | 实验 4 | 承接语音频预合成缓存；TTS 长连接复用 |
| 回声过滤会误删用户的纠正语 | 实验 5 | 含否定/纠正词时不按回声处理；回声以声学回声消除为主 |
| 口语年龄抽取失败 | 实验 6 | LLM 抽取条件；关键条件报价前复述确认 |

## 十二、实验 2：端到端问答准确率

### 12.1 做法

- **测试集**：76 题（开发集 51、保留集 25），覆盖保障、加油包、价格、投保条件、免责、数据缺口、身份。标准依据全部来自赛题数据，**在编写问答流水线之前写好**；每 3 题取 1 题为保留集，编写时固定。题量少于方案计划的 200 题。
- **对比**：
  - **本方案**：快模型理解（意图、条件、相关责任、关键主题、缺口）→ 报价查表 / 责任表 / 固定条款 / 语义 + 关键词检索 → 慢模型生成 → 护栏（不通过重写一次，仍不通过用模板）。
  - **纯 RAG**：语义 + 关键词检索取 6 段（语料中加入费率表文本），大模型直接回答，无查表、无护栏。
- **判定**：回答须包含全部要点、不得出现禁止表述（正则判定）；保留集再做**人工复核**。
- **调整纪律**：共调整两轮，每轮只看开发集的错误；保留集只看汇总数字，调整结束后才查看保留集错误用于分析。

### 12.2 结果

| 轮次 | 本方案 开发集 | 本方案 保留集 | 纯 RAG 开发集 | 纯 RAG 保留集 |
|---|---|---|---|---|
| 第 1 轮 | 82.4% | 80.0% | 56.9% | 64.0% |
| 第 2 轮 | 92.2% | 88.0% | 56.9% | 64.0% |
| 第 3 轮（最终） | 100% | **88.0%** | 54.9% | **64.0%** |
| 第 3 轮，保留集人工复核后 | — | **80.0%（20/25）** | — | **44.0%（11/25）** |

开发集达到 100% 主要是针对开发集调整的结果，**应以保留集为准**。

| 指标（第 3 轮，全部 76 题） | 本方案 | 纯 RAG |
|---|---|---|
| 对缺口问题给出结论（如"高血压可以投保""到期可以续保"） | **0** | 9 |
| 禁用表述 | 0 | 3 |
| 文本回答耗时 P50 | 2.3–2.5 s | 1.1 s |

按类别（第 3 轮，全部 76 题，正则判定）：

| 类别 | 本方案 | 纯 RAG |
|---|---|---|
| 价格 | 93% | 60% |
| 保障 | 94% | 67% |
| 加油包 | 100% | 64% |
| 投保条件 | 100% | 67% |
| 免责 | 100% | 90% |
| 数据缺口 | 90% | **10%** |
| 身份 | 100% | 0% |

### 12.3 开发集调整中发现并修正的问题

| 问题 | 修正 |
|---|---|
| "门诊看病能报吗"含"病"和"报"，被当成疾病核保问题误拦 | 缺口判断以理解模型为主，规则只认"我有……病""做过……手术"等明确自述 |
| "职业病""先天性疾病能报吗"被当成核保问题 | 理解提示中区分"问某类疾病在不在保障范围"（免责）和"说自己患病问能不能买"（核保） |
| 产品名"百万医疗"被数字护栏当成金额 100 万 | 数字提取跳过"百万""千万"这类词语 |
| "一共保多少"没有引用总保额 600 万 | 新增"总保额"固定引用 |
| 特需病房属于加油包，回答未说明 | 生成规则：涉及加油包时说明需另外选购 |
| 数字护栏误拦后只能回答"转专员" | 改为用保障计划表字段直接拼出模板回答 |
| 判定规则本身的错误 2 处（"多大年纪"未计入、"不是什么病都能报"被当成违规） | 修正判定规则（不是流水线问题） |

### 12.4 保留集错误分析（调整结束后查看，未再据此修改）

| 题目 | 问题 | 类型 |
|---|---|---|
| 住院报销比例是多少 | 只说 100%，漏了未用社保结算时 60% | 回答不完整 |
| 全家五口人一起买优惠多少 | 被当成报价，反问年龄，没有回答家庭单优惠 20% | 理解路由错误 |
| 医保报销的部分能算进 1 万免赔额里吗 | 缺口部分处理正确，但另外说了"门急诊费用不参与累计"——这是家庭共享免赔额加油包的规则，被错套到基础版 | **跨责任混淆** |
| 我 30 岁有社保，按月交每月多少（正则判对） | 说"和互联网药品费用共享 1 万免赔额"，实际是与门急诊共享 | **跨责任混淆** |
| 保险期间是多久（正则判对） | 说"住院保障从等待期 30 天后开始"，忽略了意外无等待期 | 表述不准确 |

**最主要的剩余问题是"跨责任混淆"**：证据里同时有多项责任时，模型会把 A 责任的规则套到 B 责任上。数字护栏只能检查数字有没有依据，查不出这种错误。

### 12.5 结论与对方案的修改

1. 查表 + 固定引用 + 护栏的设计，相比纯 RAG 在保留集上高出 24 个百分点（正则判定）或 36 个百分点（人工复核），**对缺口问题给结论的次数从 9 次降到 0 次**——这是赛题"安全兜底、无编造"的核心。
2. 人工复核后保留集 80%，**未达到 90% 的目标**。下一步：
   - **证据按责任分组**，每组标明所属责任和是否加油包，生成时要求每句话只引用一组；
   - 增加**句子级事实核对**：用快模型检查每句话的主语（哪项责任）与引用证据是否一致；
   - 测试集扩充到 200 题以上，并加入多轮对话题。
3. 判定规则本身有误判（多判对和多判错都有），**最终结果必须人工复核**。

## 十三、实验 4：端到端语音时延

### 13.1 做法

用阿里云 TTS 合成 8 句"用户语音"（男声，覆盖报价、病史、免赔额、保障范围、价格变化、身份、等待期、加油包），按实时速度推给腾讯云实时 ASR；ASR 给出整句结果后：

- 立即播放**本地预合成的承接语**"好的，我帮您看一下。"（规则选择，不调用模型；身份问题直接回答，不加承接语）；
- 同时运行慢思考流水线，回答通过护栏后交给**持久连接**的 TTS（女声）逐句合成；
- 按真实时间把用户和 Agent 的音频放进**双声道录音**（左：用户，右：Agent），保存时间轴。

所有时延**从用户说完话算起**（按音频能量判断语音结束），与官方用录音验收的口径一致。每个版本 8 句 × 2 轮 = 16 轮。

### 13.2 单项服务

| 服务 | 结果 |
|---|---|
| 阿里云流式 TTS，持久连接 | 建连 0.23 s（一次）；每句首包约 0.2 s（对比 edge-tts 每次新建连接约 1 s） |
| 腾讯云实时 ASR | 句尾判定（用户说完 → 整句结果）P50 0.45 s，最大 0.52 s；用户还在说时已陆续返回中间结果，例如"我三十岁有社保"在说完前约 1 s 就已识别 |
| 理解（qwen-flash） | 约 0.3–0.5 s |
| 查询改写（qwen-flash） | P50 0.28 s |

### 13.3 三个版本对比

| 版本 | 做法 |
|---|---|
| v1 | 流式生成，逐句过护栏、逐句播放 |
| v2 | 语音模式：提示词要求 50 字以内，整段回答过护栏后再播放 |
| v3 | 在 v2 基础上：**程序强制**截断到 50 字（保留完整句子前缀，被截时追问"要不要我接着说说"）；报价话术精简；TTS 语速 1.15 倍 |

| 指标（从用户说完算起） | v1 P50 / P90 / 最大 | v2 P50 / P90 / 最大 | v3 P50 / P90 / 最大 | 赛题要求 |
|---|---|---|---|---|
| **首响**（承接语开始播放） | 0.46 / 0.65 / 0.93 s | 0.46 / 0.62 / 0.75 s | **0.45 / 0.65 / 0.65 s** | ≤3 s ✅ |
| 第一句实质回答开始播放 | 2.41 / 3.45 / 3.83 s | 3.05 / 3.94 / 3.98 s | 2.98 / 4.16 / 4.39 s | — |
| **完整回答音频生成完毕** | 4.31 / 5.79 / 6.34 s | 4.69 / 5.74 / 6.22 s | **4.37 / 5.70 / 6.06 s** | ≤10 s ✅ |
| Agent 把整段话说完 | 16.8 / 25.6 / 33.9 s | 14.8 / 21.0 / 25.0 s | **13.0 / 16.0 / 18.6 s** | 见下文 |

### 13.4 发现

1. **首响远低于 3 秒**。承接语预合成后，首响只取决于 ASR 句尾判定（约 0.45 s），不再受模型和 TTS 网络时延影响。
2. **完整回答在 6.1 秒内全部生成**，满足"≤10 秒"。
3. **但如果按"Agent 把话说完"计算，一段完整回答很难在 10 秒内说完**：TTS 语速约每秒 4 个字，10 秒只能说 40 字左右，再加上承接语约 2 秒和等待回答的 2–3 秒。这取决于官方对"完整回答≤10秒"的口径，需要确认。
4. **v1 逐句过护栏、丢弃不通过的句子，会让剩下的话前后不接**：例如丢掉了"首先，1万元是年度免赔额"，剩下"其次……最后……"；丢掉一句后剩下以"但"开头。v2 起改为整段过护栏再播放。
5. **提示词限制字数不可靠**：v2 要求 50 字以内，模型仍写出 82 字、108 字的回答，v3 改为程序截断。
6. **产品名"2026版"被数字护栏当成无依据数字**，已加入白名单。
7. **报价被重复**：报价引擎说过之后模型又说一遍，v2 起删去与报价金额重复的句子。

### 13.5 语音模式的准确率代价

用实验 2 的 76 题，在语音模式（程序截断 50 字）下重测：

| 模式 | 开发集 | 保留集 | 缺口给结论 | 文本回答耗时 P50 |
|---|---|---|---|---|
| 文本模式（约 100 字） | 100% | 88% | 0 | 2.3–2.5 s |
| 语音模式（50 字） | 90.2% | 80% | 0 | 2.0 s |

保留集下降约 8 个百分点，原因有两类：一是确实丢了关键信息，例如 v3 录音中"我自己先掏一万，剩下是不是全报"被答成"免赔额以保单约定为准"；二是测试题要求一次说出 2–3 个要点，而语音模式故意只说一两点、再问"要不要我接着说说"，单轮判定会把留到下一轮的内容算作错误。**要公平评估语音模式，需要多轮对话测试题**。

### 13.6 对方案的修改

| 发现 | 修改 |
|---|---|
| 承接语预合成后首响约 0.45 s | 首句快车道由"小模型生成承接语"改为"规则选择预合成承接语"，小模型只用于理解 |
| 持久连接 TTS 首包约 0.2 s | TTS 必须用持久连接 |
| 逐句丢弃会让回答前后不接 | 短回答整段过护栏后再播放；不通过则整段重写或用模板 |
| 提示词控制字数不可靠 | 语音回答由程序按句截断，被截时追问是否继续 |
| 报价确定，可最先说 | 报价由报价引擎直接播报，模型只补充，不重复金额 |
| 一段话说完往往超过 10 秒 | 一次只讲一两点、多轮展开；需向官方确认"完整回答≤10秒"的计算口径 |
| 语音模式准确率下降 | 关键纠正类问题（如"是不是全报"）的核心结论用模板给出；补充多轮测试题 |

| 打断：附和识别 | 50 句 → 240 句 | 附和误停 0% | **18.3%** | ❌ 偏乐观 |
| 打断：防回声 | 250 对 → 1,380 对（播报句改用真实模型回答） | 用户插话误删 0% | **0.51%** | ⚠️ 发现新问题 |

**总的结论**：确定性模块（报价、取消逻辑）和语义检索在扩大测试集后结论不变；**所有基于规则的语言理解模块（条件抽取、缺口识别、身份识别、附和识别）在扩大后明显变差**，说明它们只覆盖了编写者想到的说法。方案中"规则快检 + 模型复核"的设计是必要的，不能只靠规则。

## 十七、各实验详情

### 17.1 报价（实验 1 扩充）

新增 20,000 个随机订单：每单 1–6 人，每人年龄 0–80 岁、有无社保、性别随机，随机选 0–4 个加油包，重疾关爱随机 1–3 份；与独立参照实现比对含家庭单折扣后的总价，以及不可投保时是否拒绝。**不一致 0 / 20,000**。

### 17.2 条款检索（扩充到 143 题）

新增 110 题覆盖全部 16 项责任、投保须知和责任免除各条；其中 4 题在数据中找不到对应条款（打架斗殴、羁押服刑、戒烟戒酒、睡眠障碍），已剔除，实际 143 题。

| 方法 | hit@1 | hit@3 | hit@5 | MRR@10 |
|---|---|---|---|---|
| TF-IDF | 44.8% | 75.5% | 79.0% | 0.61 |

### 17.3 条件抽取（扩充到 200 句，规则抽取）

用年龄说法（阿拉伯数字 / 中文数字 × 带"岁" / "周岁" / "了" / "今年" / "快" / 不带单位）、投保对象、社保说法（含第一轮没有的说法）、缴费方式组合生成。

| 条件 | 正确率 |
|---|---|
| 年龄 | **36.0%**（72/200） |
| 有无社保 | **58.3%**（81/139） |
| 投保对象 | 100% |
| 性别 | 100% |
| 缴费方式 | 100% |
| **整句全部正确** | **26.5%（53/200）** |

年龄按说法拆开：带"岁""周岁"的 100%；"六十九了""快5了""今年14"、不带单位的"四十一"**全部 0%**。社保方面，"单位给交社保""社保停了""医保早就不交了""有城乡医保"等新说法全部识别失败。

### 17.4 护栏（扩充）

**数字护栏**：用保障计划表字段为 16 项责任各生成 2–4 句正确陈述，再加 30 句报价陈述，共 86 句；证据中混入 2 项无关责任作为干扰。

### 17.5 打断（扩充）

**防回声**：Agent 播报句改用第二轮流水线的 178 句真实回答，与 69 种用户插话配成 1,380 对。

| 阈值 | 回声拦截（无噪声） | 轻噪声 | 重噪声 | 用户插话被误删 |
|---|---|---|---|---|
| 0.5 | 100% | 97.8% | 90.6% | 1.59% |
| **0.6** | 100% | 96.4% | 78.1% | **0.51%** |

**新问题**：用户问"等待期多久"，而 Agent 正在说含"等待期"的句子时，被当成回声删掉。原因与第一轮"我没有社保"相同：用户的话重复了 Agent 的关键词。纠正词已有豁免，**提问（含"多久""多少""吗"等）也需要豁免**。
