# 完整历史默认接入与超限压缩

更新于2026-10-13。已按用户要求将默认最近6条切换为**完整已播历史**。正常请求不按轮数、长度估算或费用阈值压缩；仅服务端明确拒绝上下文超限时，压缩该次请求里的历史，原始完整通话记录继续保留。

后续版本：已在此历史策略上接入v4持续咨询待办，补条件回原咨询、金额缺条件先问，详见[持续咨询实现与验证](27-持续咨询待办与条件追问验证.md)。本文的v2结果和未修复问题是exp42当时状态，保留原始数据；exp43不改变本次历史对照结论，也未重验语音主指标。

## 版本效果结论

**完整历史在早期信息保留和历史回指上明显优于最近6条，适合作为当前默认；现有证据尚不足以证明整体效果全面领先。**

exp42覆盖3种回指场景，每种重复2次，两方案各6次真实文字续聊。原问项/必要金额正确找回从2/6提升到6/6：近期年/月差额两方案都正确；早期住院金额和癌症三项问法的4次回指，完整历史均找回，最近6条均未完整找回。这是相同13条历史下的针对性对照，不是6种独立场景，也不是全量业务准确率。

这批样本输入token中位数仅增加约0.74%，文字耗时中位数没有增加；增幅来自当前约8万token完整证据背景，不能推断更长通话也只有同等成本或时延。测试使用Windows HTTPS传输，不能据此宣称默认Python SDK或语音链路变快。

完整历史解决的是截断导致的信息丢失。复杂完整口播仍超过10秒；补条件后的优惠/全年差额漏答、未知医保或免赔条件下的错误假设、引用语义支持不足及打断误停仍需处理。68项回归和超限恢复探针证明工程行为已通过对应检查，不代表这些业务指标同时达标。要判断整体优势，仍需扩大长对话留出测试，并重验当前版本的语音完整回答和打断。

## 当前实现

- `CallSession._history_text()`默认返回全部非空历史；显式传`n=6`只用于对照。语音仍依据播放回执提交坐席历史，未播正文、排队音频和迟到回执不会混入。
- 意图识别、对话作用分类、主回答均收到完整历史。记录模型提示中历史的准确位置，避免解析用户原话中的伪提示标记；系统提示、当前问题、画像和356项证据不参与压缩。
- `cloud.chat`和流式请求共用超限恢复机制：只识别400/413/422里的上下文容量错误；认证、限流、超时及普通参数错误不触发摘要。最多两次摘要重试，不能静默删历史或证据。
- 超限后由Qwen分块压缩早期已播对话，保留对象、条件更正、数字与单位、否定、未知条件、原问项及未完成事项；最近4条消息保留原话。重复且没有新事实的确认合并。没有较早历史可压缩、摘要无效或未变短时显式失败，原始历史不改写。
- 主回答记录`context_events`，包含触发原因、模型、前后历史字节数和重试次数。正常请求无摘要调用及额外模型调用；未按估算token数提前触发。

代码入口：[会话历史](../src/agent/session.py)、[上下文恢复](../src/agent/context.py)、[证据回答](../src/agent/evidence_answer.py)、[回归测试](../tests/test_full_history.py)。

模型实际容量随服务更新，不写死成切换阈值。官方文档目前注明DeepSeek上下文包含输入与输出，`deepseek-flash`示例窗口为1,048,576；Qwen Flash窗口1,000,000、最大输入997,952。当前策略以实际服务端容量拒绝为触发依据。[DeepSeek模型元数据](https://api-docs.deepseek.com/api/list-models/)、[Qwen Flash限制](https://help.aliyun.com/en/model-studio/qwen-flash)

## 真实模型历史回指对照

使用exp38前六轮形成的同一13条已播历史和当前画像，分别询问近期年/月差额、早期住院费用、早期癌症三项问法，每种历史两次；第二次交换两方案执行顺序，共12次真实文字续聊。不注入参考答案，不重跑择优。当前DS v2、Qwen流程和全部356项证据保持一致。

| 观察项 | 最近6条 | 完整历史 |
|---|---|---|
| 原问项/必要金额正确找回 | 2/6 | 6/6 |
| 最新40岁无医保年/月差额 | 两次均242元 | 两次均242元 |
| 早期医保8000元、余额12000元、测算2000元 | 两次未完整找回；一次误称此前未提供医保金额 | 两次均找回并正确测算 |
| 早期三项癌症问项 | 两次扩展猜测成责任大类和其他先进疗法 | 两次均找回住院、靶向药、质子重离子 |
| DS请求耗时中位数 | 4.146秒 | 3.349秒 |
| 文字整轮耗时中位数 | 4.853秒 | 4.186秒 |
| DS输入token中位数 | 80,586 | 81,184 |

增加598个输入token，约0.74%。耗时包含本次Windows HTTPS传输，不能直接当作默认Python SDK的性能或真实语音首响。这里只判历史目标是否找回，不把6/6解释成全部保险事实正确：完整历史的两条癌症渠道答复仍有直接把靶向药归入特定药品渠道的过度概括风险，另有非必要的具体名单转交。

## 30条新完整对话用例

已从标准开场和空画像分别执行[新30条用例](25-复杂问题测试集与用例.md)，共49次用户交互，当前Qwen理解/分类与DS主回答均真实调用，无服务异常。外部操作者按实际问句或结构化追问匹配预定义回复，不向坐席提供隐藏条件或判分答案。

发现尚未解决的既有问题：

- MT04、MX06：提供家庭人数后，流程转去问年龄，没有回到具体优惠。
- MT05、MT06、MX05：未知医保投保身份或剩余免赔时，模型自行采用假设或给确定计算。
- MT10：模型声明追问但口播未实际询问年龄；补72岁后仍转去问医保，未完成超龄判断。
- MX01、MX10：给条件分支后没有完成实际医保/家庭条件的收集及个体落地。
- MX03：核保转交已保存，个人报价缺医保的待处理问项没有保留在待办中。
- MX04、MX07：补条件或更正后只重报年/月价格，漏掉原来问的全年差额。

MT04、MT10、MX06的用户回复触发还依赖宽泛匹配或不可听见的动作元数据，需要人工复测。每例的核心问项初步复核保存在结果汇总中，不给出正式准确率或完整逐句溯源通过率。

这30例实际最多只有6条可见消息，故其模型历史输入与最近6条对照相同；上述问题不能归因于本次完整历史切换。当前只切换记忆策略，没有改写销售路由或用正确话术修补模型输出。

## 超限恢复与工程验证

- 68项单元测试通过，涵盖全部早期消息进入理解/主回答、已播与未播隔离、正常请求不压缩、只改标记历史区间、JSON转义、用户伪标记、无关错误不压缩、摘要失败保留原文、重试次数和流式请求兼容。
- 超限探针在首次DS请求前注入一次400上下文错误，实际调用Qwen生成摘要，再实际调用DS回答。摘要保留20000/8000/12000/10000四项原值，回答2000元；历史1783字节降为747字节，原始会话记录保持不变。
- 第一版短历史注入探针因摘要没有变短而被拒绝，保留失败记录。调整重复合并及摘要目标后v2通过，没有用截断方式绕过。
- 本次未构造真实百万token超限，也未重验音频首响、真人打断、远端电话或原143题全量准确率。旧语音实测与正式主表不重算。

本机Python SDK实际访问Qwen和DeepSeek均遇到TLS EOF。第一批43条连接失败记录原样保留；后续使用Windows原生HTTPS和证书校验访问同一接口，成功完成上述真实模型测试。测试传输仅在实验脚本显式启用，未修改生产网络配置或关闭证书验证；Python TLS问题仍需单独处理。
