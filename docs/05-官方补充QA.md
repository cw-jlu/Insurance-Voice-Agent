# 保险复杂咨询全双工语音Agent —— 官方补充QA

> 本文记录官方对命题的补充答疑原文，以及对方案的影响。方案见 [02-命题解决思路.md](02-命题解决思路.md)。

## 官方答疑原文

**Q1：仅依靠官方提供的资源是否可以完成完整赛题，还是需要自行接入第三方模型/API？官方除语音交互框架和知识库外，是否提供 ASR、TTS、LLM、RAG/Embedding 等可直接调用的能力？**
A1：需要自行接入第三方模型，相关的服务可以搭在自己的电脑上，到时候现场演示，外部的asr比如说腾讯申请就有免费的，大模型、tts阿里也有免费的token数。

**Q2：是否要求基于指定 Agent 平台/框架开发？**
A2：不指定平台。

**Q3：最终的运行环境和提交形式是什么，是否提供服务器/GPU，以及现场是否允许联网调用官方服务？**
A3：最终运营环境不限定，但是需要现场可以交互。比赛不提供服务器GPU，可以使用官方服务。

**Q4：官方后续提供的数据包具体包含哪些内容？**
A4：会包含产品的条款、投保须知和费率表、场景说明及n个问题（这些问题不会在测试集中）。

**Q5："全双工""自然打断""首响≤3秒""回答准确率≥90%"等指标具体如何验收？**
A5：我们打断、时延会通过录音进行验证。回答相关，官方会准备测试集进行测试。

## 对方案的影响

| 答疑 | 影响 | 方案调整 |
|---|---|---|
| A1 自行接入第三方 | 没有可直接调用的中台能力 | ASR 用腾讯云实时语音识别；LLM、TTS、Embedding 用阿里云百炼；全部通过可替换的适配器接入 |
| A2 不指定平台 | 技术栈自选 | 沿用 Python + FastAPI + asyncio，不依赖特定 Agent 平台 |
| A3 自备环境、无 GPU、可联网 | 不部署本地模型 | 全部走云端 API，服务跑在自己的笔记本上；现场网络和免费额度是风险，需要备用方案 |
| A4 数据包含条款；示例题不在测试集 | 当前数据只有条款注册号，没有条款全文；不能只针对示例题调优 | 知识库入库流程做成通用的，新增条款不改代码；评测集覆盖全部责任和条款，并留出不参与调优的题目 |
| A5 录音验证打断和时延；测试集验证准确率 | 时延要能从录音里量出来；准确率由官方题目决定 | 演示时同步录音并打时间戳；提供文本批量问答接口，便于跑测试集 |
