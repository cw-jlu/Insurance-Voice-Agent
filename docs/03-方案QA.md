# OPEN-JS-01 方案问答（QA）

> 本文按问答形式说明：赛题要求了什么、方案如何解答，以及赛题未要求但从业务角度补充的设计。
> 详细方案见 [02-命题解决思路.md](02-命题解决思路.md)，赛题原文见 [01-赛题原始要求.md](01-赛题原始要求.md)。
> 说明：文中时延为基于已有系统参数的估算值，最终以实测为准。

## 一、赛题明确要求的

### Q1：首响 ≤3 秒怎么保证？（KR1）

A：分两条车道同时跑：

- **快车道**：用户一句话说完，首句快车道立刻出一句承接语，比如"好的，我帮您看一下"。它不调工具，提示词走缓存，超时设为 0.8 秒，超时就放弃，不拖累主链路。
- **首响估算**：句尾确认 0.5–0.7 秒，加首句 ≤0.8 秒，再加 TTS 首包约 0.3 秒，合计约 1.6–1.8 秒。

### Q2：复杂问题 10 秒内答完怎么做到？（KR1）

A：用三个办法把时间压下来：

- **边听边查**：用户话还没说完，识别出的半句文本里一出现"产品 + 病种"，就开始检索条款。
- **流式播报**：LLM 边生成边按句切给 TTS；一句话超过 60 字还没出现句号，就在逗号处先切出来播，不用等整段生成完。
- **检索限时**：检索设延迟上限，超时就用缓存结果，或者转为澄清。

估算第一句结论约 3–4 秒出来，完整回答约 6–8 秒。

### Q3：怎么支持自然打断，打断成功率怎么到 95%？（KR2）

A：分两层判断：

- **声学层**：播报中检测到用户开口超过 300 毫秒，立即停播。
- **语义层**：再判断是真打断（新问题、纠正、"等一下"），还是"嗯""对"这类附和；附和就接着播。

另外有防回声处理：外放时 ASR 会把 Agent 自己的声音识别回来，播报期间与当前播报内容高度相似的转写当作回声丢弃。

### Q4：打断后上下文怎么不丢？（KR2）

A：用"播报账本"记录每一句的状态：已播、在播、未播。

- **打断时**：已播的句子写入对话历史；未播的标记作废，暂时挂起；正在生成的回答立即取消。
- **用户纠正信息**（比如"是去年做的手术"）：更新画像里对应的字段，然后按新条件重算。
- **用户问了新问题**：先回答新问题，再问"刚才的还没讲完，要继续吗？"

### Q5：准确率 ≥90%，并且每条回答能追溯来源，怎么做？（KR3）

A：核心原则是"规则下结论，LLM 只负责表达"，链路如下：

1. **混合检索**：关键词检索和语义检索一起用，再重排，同时按产品过滤，防止串到别的产品的条款。
2. **规则裁决**：规则引擎按"条件 → 结论 → 依据"给出确定的结论。
3. **LLM 表达**：LLM 把结论说成口语，每个结论都绑定条款号。
4. **证据自检**：数字和结论与证据对不上的句子直接删掉，回退为规则的模板句。

### Q6：怎么做到条件化、个性化，而不是给通用答案？（KR4）

A：

- **用户画像**：把画像拆成一个个槽位，包括年龄、咨询对象、产品、既往病史（病种、分级、确诊时间、治疗方式）、保单号等，规则引擎按这些槽位匹配。
- **主动澄清**：关键信息缺了就先问再答，比如"结节是几级？做过手术吗？"
- **分支回答**：回答按条件分支说，例如"您这种情况是……；如果以后……则……"。

### Q7：不确定时怎么转人工、保证不编造？（KR5）

A：

- **三级置信度**：
  - 高：证据充分，直接答，并说明来源。
  - 中：信息不全，先澄清，或者给条件化回答并提示"以核保结论为准"。
  - 低：没有证据、规则冲突，或属于敏感问题，直接转人工。
- **快车道也防编造**：首句车道被严格限制，不许给结论、不许承诺、不许说"已经查到了"。
- **规则没覆盖的情况**：一律按"需人工核保"处理，不让 LLM 自由发挥。

### Q8：赛题的红线怎么避开？

A：逐条对照：

| 红线 | 方案对策 |
|---|---|
| 纯 FAQ 匹配 + 固定话术 | FAQ 只收没有条件分支的问题，有条件的问题一律走规则推理 |
| 不支持打断或打断后上下文丢失 | 两层打断判断 + 播报账本保存上下文 + 取消重算 |
| 回答无法追溯或存在编造 | 规则给结论、每句带引用、证据自检、转人工兜底 |

## 二、赛题没要求、从业务角度补充的

### Q9：为什么要单独做首句快车道，而不是直接用小模型回答？

A：保险回答说错一句就是合规风险。快车道只负责"接住用户"，不涉及任何事实，这样首响速度和"不编造"两个目标就不冲突了。另外它用独立模型、独立 API Key，避免和主链路抢限流。

### Q10：用户在"自己"和"家属"之间切换怎么办？

A：保险咨询经常出现"那我妈能买吗"这种问法。画像按咨询对象分开存，避免把母亲的年龄套到本人的病史上。

### Q11：转人工之后坐席要不要让用户重复一遍？

A：不用。转人工时推送结构化工单，包括对话摘要、画像、已检索的证据、没解决的问题和完整转写。坐席接手后，Agent 还可以切换成"坐席 Copilot"，实时给坐席提示相关条款。

### Q12：理赔进度这类查询比较慢，怎么处理？

A：走异步任务，不卡住当前对话。结果回来后，等会话空闲时再主动告诉用户，比如"您的理赔单已经进入审核环节"。

### Q13：外放、没戴耳机的时候会不会被自己的声音打断？

A：赛题没提，但电话和外放场景里这个问题很常见。播报期间的防回声守卫就是为它加的，同时服务端也开启回声消除（AEC）。

### Q14：用户只说"嗯""好的"时怎么办？

A：模型输出一个"无需回复"标记，编排层识别到后不播报，避免 Agent 没话找话。

### Q15：状态提示会不会被误当成回答？

A：不会。"正在查询条款…"这类系统消息走单独的通道，不播报成回答，也不写进对话历史，避免让用户误以为是 Agent 的结论。

### Q16：模型或检索服务挂了怎么办？

A：

- **模型**：多模型按"同厂商最新 → 其他厂商同档"自动降级。
- **检索**：超出延迟上限就用缓存，或者转为澄清，不会无限等待。

### Q17：知识库以后谁来维护，成本高不高？

A：规则用 YAML 或表格写，业务人员自己就能改。条款按版本管理，旧版本保留，方便追溯。知识更新只需要增量入库，不用重新训练模型。规则改完先跑回归评测再发布。

### Q18：怎么持续保证质量？

A：除了赛题要求的准确率和时延，还加了两类测试：

- **行为回归测试**：从真实长对话里抽出关键场景，检查 Agent 有没有守住边界、有没有调用正确的工具。
- **成对画像测试**：同一个问题换不同画像，检查回答是否随画像正确变化。

### Q19：合规方面还考虑了什么？

A：录音告知与同意、敏感信息脱敏、禁止承诺性话术（比如"一定能赔"）和医疗诊断。全量对话留痕，并关联到当时的条款版本，方便审计。
