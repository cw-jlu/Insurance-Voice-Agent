> 本文按问答形式说明：赛题要求了什么、方案如何解答，以及赛题未要求但从业务角度补充的设计。

## 一、赛题明确要求的

### Q1：这个命题的具体场景是什么？

A：赛题数据给出的场景是**电销外呼促投保**：用户在媒体渠道看过尊享e生·百万医疗2026 的广告但没买，AI 坐席打电话过去，讲清保障、报价，引导完成健康告知和投保。被问到"是人工还是 AI"时必须承认是 AI，再自然地把话题拉回来。

所以方案不只是答疑，还要推进投保流程，并满足销售合规。

### Q2：首响 ≤3 秒怎么保证？（KR1）

A：开口和给结论分开做：

- **首句快车道**：用户一句话说完，立刻出一句承接语，比如"好的，我帮您看一下"。它不调工具，提示词走缓存，0.8 秒超时就放弃，不拖累主链路。
- **只说不含事实的话**：快车道不许报数字、不许给结论、不许承诺，所以快而不会错。
- **目标定得更严**：外呼用户沉默两三秒就可能挂断，首响目标定为 ≤2 秒。

### Q3：复杂问题 10 秒内答完怎么做到？（KR1）

A：三个办法：

- **边听边查**：用户话还没说完，识别到"多少钱 + 年龄"或"能报吗 + 病名"，就开始预取报价或条款。
- **流式播报**：LLM 边生成边按句切给 TTS；一句超过 60 字还没出现句号，就在逗号处先切出来播。
- **检索限时**：条款检索限时 1.5 秒，超时就用缓存结果，或者转为追问。

### Q4：怎么支持自然打断？（KR2）

A：分两层判断：

- **声学层**：播报中检测到用户开口超过 300 毫秒，立即停播。
- **语义层**：判断是真打断（"不对""等一下"、新问题），还是"嗯""对"这类附和；附和就继续播。

外呼用户常开免提，所以还加了防回声：回声消除，加上播报期间与当前播报内容高度相似的识别结果当作回声丢弃。

### Q5：打断后上下文怎么不丢？（KR2）

A：用"播报账本"记录每一句的状态：已播、在播、未播。

- **打断时**：已播的写入对话历史；未播的作废并挂起；正在生成的回答立即取消。
- **用户纠正信息**（比如"我没有社保"）：更新条件 → 作废旧答案 → 重新查表 → 只播差异："没有社保的话，一年是 679 元。"
- **用户问了新问题**：先答新问题，再判断挂起的内容是否还需要，需要就问"刚才的价格还没说完，要我继续吗？"

### Q6：准确率 ≥90%、每条回答可追溯，怎么做？（KR3）

A：核心原则是"**数字和结论来自表，LLM 只负责说清楚**"：

1. **报价表**：4 张费率表，程序按年龄段、有无社保、年缴月缴、加油包、家庭单查价，LLM 不参与计算。
2. **责任规则表**：16 项责任（R01–R16）拆成保额、免赔额、赔付比例、等待期、医院范围等字段，直接查。
3. **条款检索**：投保须知、责任免除按条切片，只用来解释和引用原文，不从里面推导数字。
4. **数字与引用护栏**：播报前检查每个金额、比例、天数都能在查表结果里找到，找不到的句子删掉换成模板句。

每条知识都保留出处（Excel 单元格坐标或 PDF 页码），所以每个数字都能追溯到原件。

### Q7：怎么做到条件化、个性化？（KR4）

A：

- **按条件查表**：同样问"30 岁多少钱"，有社保一年 318 元，没社保 679 元；31 岁就到下一档 423 元。
- **只追问必需的条件**：每个问题声明它必需哪些条件，比如报价必需年龄和有无社保，重疾关爱加油包还需要性别。缺了才问，一次只问一个，不像填问卷。
- **分条件回答**：比如高血压的问题，分成"能不能买（看核保）""高血压相关的不赔""无关的过了等待期能报"三种情况说。

### Q8：不确定时怎么转人工、保证不编造？（KR5）

A：

- **数据缺口清单**：数据里没有健康告知问卷和疾病核保规则、续保规则、条款全文、社保报销能否抵扣免赔额。这些问题 Agent 一律不下结论。
- **结论拦截**：缺口问题的回答里如果出现"能买""能续""可以抵扣"，整句拦截，换成兜底话术，比如"需要先做健康告知，以核保结果为准"。
- **三级置信度**：高置信直接答并说明依据；条件缺失就追问；命中缺口、规则冲突或用户情绪激动就不下结论，用兜底话术或转人工。

### Q9：赛题的红线怎么避开？

A：

| 红线 | 方案对策 |
|---|---|
| 纯 FAQ 匹配 + 固定话术 | 报价和责任按用户条件查表计算，回答按条件分支生成 |
| 不支持打断或打断后上下文丢失 | 两层打断判断 + 播报账本 + 纠正信息后取消重算 |
| 回答无法追溯或存在编造 | 每个数字有出处；数字护栏；缺口问题结论拦截 |

### Q10：五个子项目怎么覆盖？

A：命题要求整体完成，五个子项目全部纳入方案：

| 子项目 | 方案中的做法 |
|---|---|
| 全双工语音交互引擎 | 流式 ASR/TTS、两层打断、防回声、播报账本 |
| 快思考意图识别 | 首句快车道、外呼意图体系、必需条件追问、边听边查 |
| 慢思考知识检索 | 报价引擎、责任规则表、条款混合检索、护栏 |
| 条件化回答生成 | 按条件分支回答、销售流程状态机、合规规则、三级兜底 |
| 保险知识库建设 | 赛题数据提取与校验、报价表、责任规则表、条款切片、缺口清单 |

## 二、赛题没要求、从业务角度补充的

### Q11：为什么报价不交给 LLM？

A：报价涉及年龄段边界、有无社保、年缴月缴（月缴 ×12 = 372 元，比年缴 318 元贵）、加油包年龄限制、家庭单折扣。LLM 做这类计算容易出错，而电销报错价格就是合规问题。所以报价完全由程序查表，并且可以把全部组合自动枚举测试，目标是 100% 正确。

### Q12：为什么用状态机控制销售流程？

A：外呼要推进投保，但用户随时会插问题。用显式状态机（开场 → 需求 → 保障 → 报价 → 健康告知 → 投保），任何一步都可以被提问打断，答完再回到原步骤。这样既不会强推销，也不会让对话停在原地，而且流程可测。

### Q13：被问"你是 AI 吗"为什么要做成硬规则？

A：赛题明确要求必须承认是 AI。如果只写在提示词里，LLM 在被追问或诱导时可能含糊其辞。所以这条做成独立规则层，LLM 不能改写；回答之后再自然拉回话题，比如"我是 AI 助理，刚才的价格我已经帮您查好了……"

### Q14：销售合规还考虑了哪些？

A：

- 禁用"什么病都能报""保证续保""肯定能赔""高血压没关系"等表述。
- 讲保障时必须同时说主要限制：1 万免赔额、30 天等待期、医院范围、既往症不赔。
- 涉及病史时必须提醒如实告知，不代替核保下结论。
- 用户明确拒绝或要求不再来电，礼貌结束，不纠缠。

### Q15：转人工会不会太多？

A：数据缺口是有限且固定的，大部分缺口问题用固定兜底话术就能回应，不必都转人工。目标转人工率 ≤15%。转人工时推送工单，包括通话摘要、用户条件、已报价格、用户顾虑和完整转写，坐席接手不用重复问。

### Q16：用户考虑一下、没当场买怎么办？

A：发送产品介绍和投保链接短信，说明投保成功后次日零时生效、首年 30 天等待期。通话摘要留存，便于后续跟进。

### Q17：赛题数据本身有问题怎么办？

A：数据处理时发现了几处源文件瑕疵，比如责任免除 PDF 正文中混入了页码数字（"胃内水**1**囊"）、Excel 里有重复的字和重复的段落。原件保持原样入库保证可追溯，向用户引用原文时由清洗层去掉混入的数字。

### Q18：怎么证明知识库里的数字和原件一致？

A：数据管线可验证：原件记录哈希；PDF 用两套提取引擎逐页比对；清洗前后检查非空白字符完全一致；费率图片人工转录后用 OCR 逐格交叉校验。Agent 引用的每个数字都能追溯到原件的单元格或页码。

### Q19：模型或检索服务挂了怎么办？

A：

- **模型**：设调用超时，主模型不可用时自动切换备用模型；再不行就降级为模板回答加转人工。
- **检索**：超时用缓存或转为追问；高频问题配置固定的条款引用，不经过检索。

### Q20：病史这类敏感信息怎么保护？

A：病史属于《个人信息保护法》规定的敏感个人信息。只采集投保必需的内容，不写入长期画像，存储加密、按最小权限访问；录音和转写按监管要求留存和脱敏；演示环境全部使用模拟数据。

### Q21：还有哪些需要业务方确认？

A：家庭单折扣是否也作用于加油包、折后金额怎么取整，数据里没写。确认之前，涉及家庭单的报价统一说"约 XX 元，以投保页面显示为准"。
