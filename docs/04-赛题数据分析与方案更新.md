# OPEN-JS-01 赛题数据分析与方案更新建议

> 数据说明与校验方法见 [data/README.md](../data/README.md)。本文分析数据对方案的影响，并列出 [02-命题解决思路.md](02-命题解决思路.md) 需要修改的地方。

---

## 一、最重要的变化：场景是"电销外呼促投保"，不是"呼入咨询"

`场景及问题说明.md` 原文：

> 场景：媒体渠道X浏览未投保 → 电话外呼促投
> 坐席身份：众安电销坐席，引导完成投保+健康告知，如果问到人工还是AI，需要承认是AI但是可以吸引用户继续往下走。

V1 方案默认是**客户主动来问**，覆盖投保、理赔进度、保单查询等。实际赛题是：

| 维度 | V1 假设 | 赛题实际 |
|---|---|---|
| 谁先开口 | 用户 | **Agent 外呼**，需要开场白、确认身份、说明来电原因 |
| 对话目标 | 答疑 | **答疑 + 推进转化**：讲清保障 → 报价 → 健康告知 → 完成投保 |
| 用户状态 | 已有问题 | 浏览过广告但没买，可能随时挂断，也可能有顾虑 |
| 产品范围 | 多产品 | **单一产品**：尊享e生·百万医疗保险2026版 + 8 个加油包 |
| 理赔进度/保单查询 | 核心意图 | 用户还没投保，**基本用不到**，可以降为次要 |
| 身份 | 未涉及 | 被问到"是人工还是 AI"时**必须承认是 AI**，然后自然地把话题拉回来 |
| 合规重点 | 不编造 | 不编造 + **销售合规**：不夸大、不承诺赔付、主动说明免责、提醒如实告知 |

**方案主线要改为**："快思考维持外呼对话节奏 + 慢思考保证每个事实有出处 + 状态机推进投保流程"。

## 二、数据里有什么

| 知识 | 来源 | 结构化程度 | 用途 |
|---|---|---|---|
| 16 项保险责任（保额、免赔额、赔付比例、等待期、医院范围、人群） | Excel → `clean/保险责任.json` | 高，字段化 | 规则引擎直接读取；"能报什么"类问题 |

| 投保须知：投保年龄、被保人关系、职业、等待期、一人限 1 份、次日零时生效 | PDF → `clean/text/` | 中，条款文本 | 投保条件核对 |
| 责任免除：既往症、等待期内确诊、非合规医院、补偿原则等 | PDF → `clean/text/` | 中 | 免责说明、"能不能报"类问题 |

## 三、5 道示例题的回答路径

每道题列出：需要的槽位、确定性依据、LLM 能说什么、不能说什么。

### a. "刷到广告说几百万保额，具体都能报什么？"

- **类型**：产品介绍，不需要槽位。
- **依据**：投保须知第 9 条"本产品国内医疗总保额为600万元"；`R01` 一般医疗 300 万（与门急诊共享）、`R03` 重疾医疗 300 万、`R05` 恶性肿瘤先进疗法 600 万、`R06` 特定药品 600 万 等。
- **回答要点**：先说"总共 600 万"和"一般医疗 300 万、重疾 300 万"这几个最好记的数，再用一句话讲清**1 万免赔额**和**二级及以上公立医院普通部**这两个前提，最后问一句"您比较关心住院还是大病？"，把话题引向个性化。
- **不能说**："什么病都能报""几百万随便报"。

### b. "我有高血压好几年了，一直在吃降压药，买这个以后住院能报吗？"

- **类型**：既往病史 + 条件化，是本题最难的一道。
- **依据**：
  - 责任免除摘要第 3 条："初次投保前……的既往症或先天性疾病，不予理赔"；个人住院医疗保险类（一）2)"被保险人所患既往症……引起的相关费用"不赔。
  - 投保须知七.2：需要履行如实告知义务，未如实告知可依《保险法》第十六条解除合同。
- **缺的数据**：高血压能不能投保、是否除外，要看**健康告知和核保**，数据里没有。
- **回答要点**（条件分支）：
  1. 能不能买：要先做健康告知，以核保结果为准；Agent 不给结论。
  2. 买了以后，**高血压本身及相关的住院费用**属于既往症，不赔；
  3. 和高血压**无关**的疾病或意外住院，等待期后符合条件的可以报；
  4. 提醒如实告知，否则影响理赔。
- **不能说**："高血压没关系，能报""控制得好就能买"。
- **追问槽位**（可选，用于之后的健康告知）：确诊时间、是否有并发症、最近是否住院。

### c. "我30岁多少钱？"

- **类型**：报价，**必须查表，不能让 LLM 算**。
- **槽位**：年龄（30 → 年龄段 `[26,30]`）、有无社保（**缺失时必须追问**）、年缴/月缴、是否加加油包、重疾关爱加油包还要性别。
- **依据**：`年缴_必选.csv` `[26,30]`：有社保 318 元、无社保 679 元；`月缴_必选.csv`：有社保 31 元/月、无社保 67 元/月。
- **回答要点**："30 岁有社保的话，基础版一年 318 元，也可以按月交，每月 31 元。"如果是家庭一起投保，再补充家庭单优惠。
- **注意**：年龄段边界（30 岁属于 26–30 岁，31 岁就是另一档 423 元）；月缴 ×12 = 372 元，比年缴贵，不要说"一样"。

### d. "以后每年都这个价吗？"

- **依据**：投保须知三.3"您每次投保应交纳的保费会随着您的年龄增长而变化"；三.4 保险期间 1 年。费率表按年龄段递增。
- **回答要点**：不是固定价，价格按投保时的年龄段计算；可以举例"到 31 岁这一档是 423 元"。费率 PDF 另有一条：上一张保单期满后，在指定期限内通过指定路径重新投保、且在众安没有理赔记录的，适用优选体价格（原文没有给出优惠幅度，不能报具体数字）。
- **缺的数据**：续保规则（是否保证续保）。用户问"能不能一直续"时，要说明以条款为准或转人工，**不能说"保证续保"**。

### e. "我自己先掏1万，剩下全报？"

- **类型**：纠正用户误解，是条件化回答的典型。
- **依据**：`R01`/`R02` 一般医疗和门急诊共享 1 万年免赔额，扣除后 100%，有社保但没用社保结算的是 60%；`R03` 重疾医疗**无免赔额**；责任免除摘要第 2 条补偿原则（医保等已报销的部分不赔）、非合规医院不赔；等待期 30 天；既往症不赔。
- **回答要点**："不完全是"——
  1. 一般住院：一年累计超过 1 万免赔额的部分，符合条件的按 100% 报；但如果是以有社保身份投保、看病时却没用社保结算，只按 60% 报；
  2. 如果是 100 种重大疾病，**没有 1 万免赔额**；
  3. 前提：二级及以上公立医院普通部、合理且必要的费用、不是既往症、过了 30 天等待期；已经被医保报销的部分不会重复报。
- **缺的数据**：社保报销的部分能否抵扣 1 万免赔额——**不能下结论**。

### 补充：被问到"你是人工还是 AI"

- **要求**：必须承认是 AI；然后自然地回到用户的问题上，例如"我是众安的 AI 助理，刚才您问的价格我已经帮您算好了……"。
- 这一条应做成**不可被 LLM 改写的硬规则**，并放入评测集。

## 四、对 [02-命题解决思路.md](02-命题解决思路.md) 的修改建议

### 需要改的

| 章节 | 修改 |
|---|---|
| 一、一句话方案 | 改为外呼促投场景：加入"开场 → 需求挖掘 → 讲保障 → 报价 → 健康告知 → 投保引导"的流程推进 |
| 三、总体架构 | 编排层增加**销售流程状态机**；知识层把"保单/理赔 API"改为"**费率表 + 保险责任表 + 条款文本**"三类，前两类走确定性查询 |
| 4.2 意图体系 | 替换为外呼场景的意图：保障范围、价格、价格变化/续保、免赔额与报销比例、既往病史、投保条件（年龄/职业/关系）、等待期、身份询问（AI/人工）、异议（太贵/考虑一下/已有保险）、拒绝/挂断、要求人工 |
| 4.3 规则引擎 | 示例从虚构的"甲状腺结节 UW-THY-02"改为数据里真实存在的规则：**报价规则**（年龄段 × 社保 × 缴费方式 × 性别 × 家庭单）、**免赔额/赔付比例规则**（R01–R16）、**免责规则**（既往症、等待期、医院范围）。病种核保规则数据里没有 → 一律"以健康告知/核保为准" |
| 4.4 画像槽位 | 改为：年龄、性别、**有无社保**、缴费方式、为谁投保（本人/配偶/子女/父母）、家庭成员数、职业、既往病史、意向加油包 |
| 4.5 安全兜底 | 增加销售合规：必须承认 AI 身份、主动提示免责和等待期、提醒如实告知、禁止"保证续保""一定能赔""什么都报" |
| 六、典型对话 | 换成本产品的外呼对话，覆盖 a–e 五道题 + AI 身份 + 打断纠正（例如"不对，我没有社保"→ 重新报价） |
| 七、评测方案 | 以 5 道示例题为种子扩展：年龄段边界（30/31 岁）、有无社保、年缴/月缴、家庭单人数的**报价准确率**应达到 100%；病史类题目以"不下核保结论 + 说对免责"为正确标准 |

### 可以保留的

全双工引擎（流式 ASR/TTS、打断、防回声、播报账本）、首句快车道、快慢双车道、事实护栏、转人工工单：这些和场景无关，继续使用。

### 新增的亮点

1. **报价零误差**：费率表结构化 + 确定性查表，LLM 只负责把数字说出来；数字护栏检查播报里的每个金额都能在表里找到。
2. **打断后自动重新报价**：用户纠正"没有社保""是给我妈买"时，槽位更新后慢车道取消并重新查表。
3. **数据缺口显式化**：对数据里没有的内容（健康告知、续保）有固定的兜底话术，把"不编造"做成可测试的行为。
4. **可审计的数据管线**：原件哈希 + 双引擎提取 + 清洗不变式 + OCR 交叉校验，每个答案可追溯到单元格坐标或 PDF 页码。
