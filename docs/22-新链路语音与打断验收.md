> 当前跨版本指标见[当前指标与验收口径](24-当前指标与验收口径.md)：文字出处有效100%，整轮语义支持95.1%，含安全转交正确处理91.6%，自动回答内容正确89.8%。下文各实验原分数按当时版本、样本和口径保留；exp38快车道连续对话及exp39短答试验不替代全量验收。

## 这次测的是哪一版

此前按逐段口径135/143语义引用通过（后续exp40整轮复核136/143）、必须核实13题转交12题，是2026-10-11 **新候选的文字结果**；此前首响、播完、打断数字来自旧exp21，不是新候选语音验收。此次将`EvidencePipeline`接入实际语音实验入口，重新执行真实ASR、流程理解/分类、DS生成、TTS及播放，未使用缓存答案或模拟模型。

- 12道诊断题×男/女两种合成用户音色＝24个新语音回合，包含复合保障、病史、报价、津贴、资料冲突与缺失。
- 实时输入腾讯ASR；真实Qwen TTS，Cherry、speech_rate=1.2；使用本机Realtek WASAPI输出设备，记录实际排入DAC的首个有声采样及末采样时间。
- 不播放中性承接语；测业务回答或与问题相关的追问首响。回答JSON完整校验后才交给TTS；TTS首包抵达即送播放器，不等整段合成结束。
- 模拟位于咨询阶段，已报价/讲限制/健康告知的流程标记置为true；画像从题目已知条件开始。流程仍可能因画像纠正重新报价，或者追加年龄询问、链接及生效说明，这些都计入口播时间。
- 20个真打断、10个附和、8个纯回声，实时执行ASR事件→现有打断控制器→真实播放缓冲取消。麦克风输入是合成语音加3%回声注入，没有读取房间麦克风，也没有测试真实电话网络或物理AEC。
- 另测4次真实DS在途准备取消，以及2次同一会话实际停播后的语音条件纠正。

WASAPI时间戳是播放设备排程实测，**不是旧脚本按音频长度累加模拟**，也不是电话远端或声学回录测量。保存的WAV是输入和TTS原始音频，不是房间录音。旧打断脚本等ASR结束后再判断，本轮在接收事件时立即调度判断，计入真实判断等待与设备缓冲。

- 有效回合实际音频时长中位24.93秒，口播正文中位146字符，P90为339字符。说明播完慢不只因为多等一次生成，回答本身仍然很长。

### 一条真实时间线：C01/r1

用户问62岁母亲的住院、门诊和ICU补贴。实际口播356字符，包括模型保障说明和流程追加的年/月缴报价。

```mermaid
flowchart LR
    A[用户说完 0秒] --> B[ASR确认 0.669秒]
    B --> C[全部文本就绪 4.590秒]
    C --> D[TTS首包 5.238秒]
```

本例DS生成3.117秒，实际音频61.193秒。生成速度不是主要的播完瓶颈；长责任名称、重复解释、比例/额度细则及流程追加报价占了大量口播时间。

## 打断：正式成功率与内部诊断分开

仅执行最低3%回声条件的38例。真打断未达到当时内部500毫秒快速停播目标（该时限不是赛题硬门槛），所以没有扩大到预计划的10%/30%回声压力组76例；未执行部分不报成功率。首次并发打开输出流发生`PortAudioError`，保留启动失败记录；随后串行完成38例，无服务或设备错误，没有重采样覆盖有效结果。

| 指标 | 新候选结果 | 判断 |
|---|---:|---|
| 真打断，在自然播放结束前确实丢弃剩余缓冲 | **20/20（100%）** | 本样本识别并停播达到95% |
| 真打断/附和/回声三类的正确停或不停动作 | **32/38（84.2%）** | 额外动作分类观察，不能直接替代赛题打断成功率，且未含历史连贯性 |
| 用户开口后500毫秒内完成停播 | **3/20（15%）** | 未达到内部500毫秒优化目标，非赛题独立门槛 |
| 停播时延 | 中位0.82秒，P90 1.21秒，最大1.77秒 | 仍偏慢 |
| 附和误停 | **5/10（50%）** | 超过内部≤5%误停优化目标，非题面独立门槛 |
| 纯回声误停 | **1/8（12.5%）** | 未达内部误停优化目标，非题面独立门槛 |

“20/20能停”不等于整条打断链路达到95%：还要不误停、更新条件、取消旧答，并只保留用户实际听过的历史。

两条实际错误记录：

- 用户说“收到”，ASR首先给“收”，模型将这个未完成片段判为打断，发生误停。
- 用户说“好的”，开始正确判为附和；约10秒后只剩回声，ASR输出“左右五”，模型判为打断。纯回声例也复现了“左右五”误停。当前引用刚播内容的窗口只有3秒，整段长回答仅在起点记一次；后续噪声/回声片段不能可靠识别。

这些定位依据保存的实时ASR与决策时间戳，不是把源音频字幕当成识别结果。回声与播放硬件没有声学闭环，3%只是固定注入条件，不代表真实AEC消除率。

## 取消、条件纠正与会话历史

4次准备取消都等到真实DS请求已经开始，再使旧候选失效并确认新条件。4/4未释放旧候选，年龄、医保身份或缴费方式更新后，正确报出679元、517元、31元/月、3316元。取消为协作式丢弃旧结果，旧HTTP请求仍可能继续完成，不表示取消了服务端计算或费用。

另2次在同一`CallSession`中真实播放旧答、接收混音ASR插话、停播，然后将识别出的纠正语音交给同一会话：

|---|---|---|
| 30岁有社保改为无社保，首次年缴 | 679元，画像has_social=false | 金额及画像正确 |
| 30岁改为40岁，有社保首次年缴 | 517元，画像age=40 | 金额及画像正确 |

当时**2/2都把未播完的旧回答全文保留为已说历史**。exp41已修复，下一轮未混入未播全文0/2，改口报价2/2正确；本段保留exp36原结果。当时`CallSession._finish`保存全文，外部播放器停播没有同步裁剪历史。这不证明两次新金额错了，但完整上下文连贯验收失败，后续可能误认为客户听过后半段说明。两次纠正还出现模型报价后程序再次报价的重复：候选路由是`证据-answer`，流程没有识别已完成报价，画像纠正后自动再报一次。

## 新语音的内容与来源复核

主agent阅读24条实际口播及原文，未使用模型自动裁判，无独立第二复核。题组有已知错题及材料边界题，**不把它合并进143题或解释为真实客户准确率**。

| 新语音诊断口径 | 结果 |
|---|---:|
| 实际口播内容正确，含是否漏答 | 18/24 |
| 实际调用DS的回合，模型逐段引用语义支持 | 20/23 |
| 整段口播的保险事实全部进入统一逐段来源记录且支持完整 | 16/24 |
| 完整语音回合正确、可溯源并按核实边界处理 | 12/24 |
| 按此前冻结标签必须外部核实的回合实际请求人工 | 4/6，漏C19两轮 |

“20/23”审计模型回答；“16/24”还检查程序追加的口播。C01两轮追加的报价、C26两轮追加的生效说明可以在原始资料/报价代码中复算，但没有写入当条统一逐段引用记录，不能用模型claims覆盖整段实际语音。H04/r1没有调用DS，因输入被截在病史陈述处，仅追问年龄；不能算来源通过。

具体问题：

- C02两轮只答靶向药与质子重离子，漏独立的住院责任及一般/重疾免赔分支。
- C09/r1把意外一概说成不受既往免责，还笼统追加等待期；r2改为否定“有高血压就整体排除”，事实可接受，但该段缺支持因果边界的免责引用。
- C19两轮仍漏主体检测1万元及适用核实；r2还把特药申请短信流程扩成基因检测流程，并泛化未医保结算60%比例。按预先冻结的冲突核实边界，两轮都漏转。
- H04/r1用户先说“我现在有肾囊肿，下周才买保险”，ASR先确认这句；后面费用问题成为第二个final，实验入口只处理首个final，最终没答赔付。H10/r1也被拆成两句，提前开始追问。两轮保留为语音协议失败。
- E13两轮按先扣3天、再限给付30天算出3000元，内容和引用都正确。这是同版本新生成的表现，不能据此称此前该类错误已被彻底修复。

能回答却转人工仍按用户口径计正确；这里4次实际转交前的内容、来源与请求都通过。尚未验证电话供应商实际接通人工。

## exp36当时结论与后续修复

exp36当时首响、播完、快速停播、误停、历史同步及全口播引用覆盖未通过。后续exp38快车道首次出声7/7≤3秒；exp41历史同步两次实测通过，当前55项单元测试通过。其余原始实验数据保留；当前状态见[指标汇总](24-当前指标与验收口径.md)。剩余工作：

1. 语音入口收集完整用户轮次；继续说话时取消旧答，不能忽略后续ASR段。
2. 已完成停播同步播放回执及已听历史；继续对短、不完整ASR片段保持待判，改善附和/回声识别。
3. 压缩责任名称和重复说明，避免模型报价后流程再报；在事实/引用可校验的边界内接入分段释放及TTS重叠。
4. 将程序追加的报价、生效/限制说明也纳入来源记录；继续修漏答、跨子路径套条件和资料冲突时的漏转。

本轮增加了TTS音频包观察回调，默认`synth(text)`行为保持；声卡依赖写入`experiments/requirements-voice.txt`。exp36当时42项单元测试通过。提示词、证据和事实策略未按本轮结果修改，未以规则修答或再次生成择优覆盖错误。
