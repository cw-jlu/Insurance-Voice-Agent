## 3分钟总结呈现：可直接照读

**0:00–0:25 自我介绍**

各位评委好，我是陈为，个人参赛。我负责这个项目的知识库处理、咨询链路、语音交互、实验评估和网页演示。我的命题是保险复杂咨询语音 Agent，重点是用户一次问多个问题，或不断补充和更正条件时，系统能持续回答，并保留可核查的依据。

**0:25–1:10 问题与实现**

保险咨询不能只匹配FAQ。比如用户先说有医保，之后改成没有医保，之前的保费就需要重算；问到理赔，还需要区分投保身份、实际结算、剩余免赔和费用是否符合保障范围。我把材料整理为带定位的证据，快模型负责理解当前问题和条件，DeepSeek负责业务生成；生成后检查来源、条件和咨询待办，再允许发布。

**1:10–1:50 连续咨询与溯源**

系统为每个问项保留待办，区分已回答、缺条件和需要人工核实。改口后重新打开依赖旧条件的问题。语音停止时，下一轮只带入已确认播完的句子，生成但没播完的答案保留在审计记录里。网页可以看到识别文本、各阶段耗时、答句引用和原始证据，也能导出完整记录。

**1:50–2:35 实测结果与边界**

最近完整批次有143题，正确处理133题，整体93.0%；明确的30题复杂子集正确处理26题，为86.7%，还没有达到复杂题90%的目标。固定承接首声在0.68到0.83秒，但复杂完整口播仍超过10秒。来源结构有效不等于语义全部支持，安全路由与附和、回声误停也仍有缺口。因此我把已实现能力、未达标指标和修复后未复验的部分分开呈现。

**2:35–3:00 转入演示**

接下来我先展示语音提出一个新问题，再做条件更正和多问项咨询，最后展开原文、阶段耗时与完整记录。评委也可以直接提出新问题。当前现场使用DeepSeek，历史回放只作为网络或服务异常时的备用，界面会明确标注。

回答较长时可调到1.25×或1.5×帮助展示，但正式验收的原速成绩不因此改变。演练计时器按3分钟总结、7分钟演示、5分钟提问运行，每段剩余一分钟提示。一次新问题可能包含缺条件追问或安全人工请求，应如实展示，不能保证每个现场问题都自动答完。

“说完自动发送”在腾讯ASR返回句段完成后提交，较长停顿可能提前结束本轮。复杂长问题可关闭此选项，点击结束录音后检查文字再发送。需要每轮主动开始录音；当前页面的录音按钮是显式打断，不作为持续开放麦克风的自然全双工验收。

## 5分钟评委提问：准备回答

| 为什么用完整证据而不是动态RAG？ | 当前材料规模可放入上下文，完整责任组减少漏条件；动态检索召回和真实历史接口尚未验收，规模扩大时需要分组检索与召回验证。 |
| 为什么整体93%还说未达标？ | 混合题与复杂子集分母不同。复杂题26/30低于90%，追问或正确人工请求不等于自动解决。 |

| 人工真的接通了吗？ | 没有。保存问题、条件和来源形成转接请求；实际客服通道需要接口和回执，演示明确说明。 |
| 怎么复现？ | 解压资料包，安装依赖，验证清单和冻结核心，启动网页；无需密钥可回放原始失败与成功记录，配置服务后可现场自由提问。外部模型变化可能导致新结果不同。 |
