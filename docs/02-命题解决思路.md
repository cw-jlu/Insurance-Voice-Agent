## 一、问题拆解

赛题的难点在于三组互相矛盾的要求要同时满足：

| 矛盾 | 说明 | 我们的解法 |
|---|---|---|
| **快 vs 准** | 首响≤3秒，但复杂咨询需要检索条款、推理规则、查历史记录 | 快慢双通道并行：快思考先"接住"用户，慢思考后台检索推理，结果流式接续 |
| **流畅 vs 可控** | 全双工、可打断，但打断后上下文不能丢 | 对话状态机 + 可中断的任务调度，打断时保存"已说/未说"断点 |
| **个性化 vs 安全** | 要按用户画像给条件化回答，又不能编造 | 结构化规则引擎做判定，LLM只负责表达；每句结论绑定来源；置信度不足即澄清或转人工 |

对应五条 KR，核心设计目标：

- **KR1 时延**：快通道首包 ≤1.5s（留足余量），慢通道完整回答 ≤8s
- **KR2 打断**：VAD + 语义打断判定，打断成功率 ≥95%
- **KR3 准确可追溯**：RAG + 规则引擎，回答中每个结论附 `[条款号/规则ID]`
- **KR4 条件化**：槽位化用户画像（年龄、既往病史、险种、等待期、保单状态等）驱动推理
- **KR5 安全兜底**：三级置信度门控，低置信度 → 主动澄清 → 仍不足 → 转人工

## 三、模块设计

### 3.1 全双工语音交互引擎（KR1、KR2）

- **传输**：WebSocket/WebRTC 双向音频流，ASR 与 TTS 同时工作。
- **流式 ASR**：复用 AI 中台 ASR，输出 partial + final 结果；partial 结果即送快思考做意图预判（**边听边查**）。
- **打断检测（两级）**：
  1. 声学层：Agent 播报中检测到用户语音能量 + VAD 持续 >300ms，立即降低/暂停 TTS；
  2. 语义层：判断是真打断（新问题、纠正信息、"等一下"）还是附和（"嗯""对"），附和则恢复播报。
- **打断后上下文保持**：
  - 播报队列记录每个句子的状态（已播 / 播放中 / 未播），打断时把"已说内容"写入对话历史，未说部分挂起；
  - 用户补充信息（如"我说错了，是去年做的手术"）→ 更新画像槽位 → **取消并以新条件重启**慢思考任务；
  - 用户问题无关时可在回答后提示"刚才关于××还没说完，需要继续吗？"。
- **流式 TTS**：按句切分，首句生成即播，降低感知时延。

### 3.2 快思考：意图识别与上下文管理（KR1）

- **意图体系**（示例）：投保咨询 / 健康告知与既往病史 / 核保条件 / 理赔流程 / 理赔进度 / 保单查询 / 闲聊 / 转人工 / 投诉。
- **实现**：轻量分类模型（或小参数 LLM + 规则关键词）<200ms；槽位抽取维护**用户画像**：
  `年龄、性别、险种/产品、投保时间、等待期状态、既往病史(病种/确诊时间/治疗情况)、保单状态、理赔单号…`
- **路由策略**：
  - 简单问题（FAQ 高置信命中、查询类）→ 快通道直接回答；
  - 复杂问题 → 快通道立即给出**承接语 + 澄清/确认**（例："您是想了解有甲状腺结节能不能投保这款医疗险对吧，我帮您查一下条款"），同时后台启动慢思考；
  - 关键槽位缺失 → **主动澄清**（"结节是哪一年发现的？有没有做过手术？"），澄清期间慢思考已并行预取候选条款。

### 3.3 慢思考：知识检索与规则推理（KR3、KR4）

1. **查询改写**：结合画像把口语问题改写为结构化查询（产品 + 病种 + 场景）。
2. **混合检索**：BM25 + 向量检索 → Cross-Encoder 重排，召回条款片段、核保规则、FAQ、历史相似咨询。
3. **规则引擎判定**：核保/理赔规则结构化为 `条件 → 结论` 规则表（如 *"甲状腺结节 TI-RADS≤3 且未手术 → 标准体承保"*），用画像槽位确定性匹配，**关键结论由规则给出而非 LLM 生成**。
4. **个人数据查询**：对接保单/理赔系统 API 查进度、保单状态（演示阶段用 Mock 数据）。
5. **条件化生成**：LLM 基于"规则结论 + 证据片段 + 画像"生成口语化回答，要求每个结论带来源引用；对条件未满足的情况分支说明（"如果……则……；如果……则……"）。
6. **自检（Grounding Check）**：校验回答中的每个结论能在证据中找到支撑，不能支撑的句子删除或降级为"需人工确认"。

### 3.4 安全兜底（KR5）

| 置信度 | 条件 | 行为 |
|---|---|---|
| 高 | 规则命中 + 证据充分 + 自检通过 | 直接回答并注明来源 |
| 中 | 证据部分命中 / 槽位缺失 | 主动澄清，或给出条件化回答并提示"以核保结果为准" |
| 低 | 无证据 / 规则冲突 / 涉及医疗诊断、承诺赔付、投诉等敏感场景 | 不作答，**转人工**，并把对话摘要+画像+已检索证据推送给人工坐席 |

另外：禁止输出承诺性话术（"一定能赔"），敏感词和合规话术过滤。

### 3.5 保险知识库建设

- **条款库**：PDF/Word 条款解析 → 按"章-条-款"切分，保留条款号、产品、版本、生效日期元数据。
- **规则库**：核保规则、理赔规则整理为结构化表格（YAML/JSON），业务人员可直接维护。
- **FAQ 库**：问题-答案-来源三元组。
- **维护成本**：知识更新只需增量入库/改规则表，无需重训模型。

## 四、时延预算（KR1）

| 阶段 | 快通道（首响） | 慢通道（完整回答） |
|---|---|---|
| ASR 尾点确认 | ~300ms | ~300ms |
| 意图识别 + 槽位 | ~200ms | — |
| 检索 + 重排 | — | ~800ms（边听边查可提前） |
| 规则判定 + 数据查询 | — | ~500ms |
| LLM 首 token | ~500ms（小模型/模板） | ~1.5s |
| TTS 首包 | ~300ms | ~300ms |
| **合计** | **≈1.3–1.5s（≤3s）** | **首句≈3.5s，完整≈6–8s（≤10s）** |

关键手段：partial ASR 预取、流式 LLM + 流式 TTS、检索结果缓存、快通道承接语掩盖慢通道时延。

## 五、典型对话示例

> **用户**：我前年查出甲状腺结节，现在能买你们的百万医疗险吗？
> **Agent（快，≈1.2s）**：您是想了解有甲状腺结节能否投保百万医疗险，我马上帮您查。方便说下结节分级，以及有没有做过手术吗？
> **用户**：三级，没做手术。
> **Agent（慢，≈5s）**：根据《××百万医疗险》健康告知第 3 条及核保规则 UW-THY-02，TI-RADS 3 级且未手术的甲状腺结节，一般可**标准体承保**，但甲状腺相关疾病可能除外责任；如果后续分级升到 4 级以上，则需要人工核保。最终以核保结论为准。
> **用户**：（打断）那我妈 65 岁能买吗？
> **Agent**：（停止播报，保存上下文）好的，您母亲 65 岁……（根据投保年龄规则回答），刚才您自己的情况还需要我继续说明吗？

## 七、评测方案

- **时延**：全链路打点，统计首响、完整回答的 P50/P90。
- **打断**：构造 ≥100 条打断用例（新问题 / 纠正信息 / 附和），统计打断成功率与上下文连贯性。
- **准确率**：业务专家标注 ≥200 条复杂咨询测试集（既往病史 × 产品 × 场景组合），人工 + LLM 评判结论正确性与引用正确性。
- **安全**：构造超范围、诱导承诺、信息不足的对抗用例，验证转人工率与零编造。

---

## 八、落地与对接

- 通过标准 WebSocket/SIP 网关接入现有呼叫中心 / 在线客服；
- 转人工时推送结构化工单（对话摘要、画像、证据、未解决问题），坐席无需重复询问；
- 知识库与规则表由业务人员维护，支持版本管理和灰度发布；
- 全量对话留痕，每条回答可回溯到条款版本，满足合规审计。

---

## 九、创新点

1. **快慢协同 + 边听边查**：用户还没说完，慢思考已基于 partial 文本预取条款；
2. **规则判定 + LLM 表达分离**：结论可解释、可审计，从机制上避免编造；
3. **可恢复的打断**：句子级播报断点，打断后可继续、可按新条件重算；
4. **主动澄清**：关键槽位缺失时先问再答，实现真正的个性化条件化回答；
5. **带上下文的转人工**：兜底不是"甩锅"，而是把已完成的工作交给坐席。
