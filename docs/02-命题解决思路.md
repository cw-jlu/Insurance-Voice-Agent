## 摘要

用户在媒体渠道看过尊享e生·百万医疗2026 的广告但没有投保，AI 坐席打电话过去，讲清保障、报价，引导完成健康告知和投保。方案主线是：**快思考稳住通话节奏，慢思考保证每个事实有出处，状态机推进投保流程**。

| 赛题要求 | 解决思路 | 预期标准 |
|---|---|---|
| 首响 ≤3s | 首句快车道：只说不含业务事实的承接语，0.8s 超时即放弃 | ≤2s |
| 复杂回答 ≤10s | 边听边查 + 句级流式播报 + 检索限时 | 完整回答 ≤8s |
| 自然打断，上下文连贯 | 声学 + 语义两级打断、防回声、句级播报账本、纠正信息后取消重算 | 打断成功率 ≥95% |
| 准确率 ≥90%，可追溯 | 报价查表、责任查表、免责查条款，LLM 只负责表达 | 报价 100%，事实 ≥90% |
| 条件化回答 | 按年龄、社保、缴费方式、为谁投保、病史等条件分支回答 | 同问题不同画像答案正确变化 |
| 安全兜底 | 数据里没有的内容一律不下结论，引导健康告知或转人工 | 无依据结论数 = 0 |

## 一、命题解读

### 1.1 核心任务

构建一个**全双工语音 Agent**，在电话里边听边说、支持随时打断，对"既往病史 + 投保"这类复杂咨询给出**按用户情况区分的、能追溯到条款的、不编造的**回答。架构上要求"快思考 + 慢思考"协同：快思考负责低延迟的接话和简单问答，慢思考负责检索、规则推理和准确回答。

### 1.2 赛题数据揭示的具体场景

赛题数据中的场景说明：

> 场景：媒体渠道X浏览未投保 → 电话外呼促投
> 坐席身份：众安电销坐席，引导完成投保+健康告知，如果问到人工还是AI，需要承认是AI但是可以吸引用户继续往下走。

由此得出几个和普通客服不同的地方：

| 维度 | 普通呼入客服 | 本命题 |
|---|---|---|
| 谁先开口 | 用户 | **Agent 外呼**，要开场、说明来电原因 |
| 目标 | 答疑 | **答疑 + 推进投保**：保障 → 报价 → 健康告知 → 投保 |
| 用户状态 | 带着问题来 | 有兴趣但有顾虑，**随时可能挂断** |
| 产品 | 多产品 | 单一产品（尊享e生·百万医疗保险2026版）+ 8 个加油包 |
| 身份 | 不涉及 | 被问到必须**承认是 AI**，再自然拉回话题 |
| 合规 | 不编造 | 不编造 + 销售合规：不夸大、不承诺赔付、主动讲免责、提醒如实告知 |

赛题给出的 5 道示意题覆盖了这个场景的典型问题：

| 题目 | 考点 |
|---|---|
| a. 刷到广告说几百万保额，具体都能报什么？ | 产品介绍，不夸大 |
| b. 我有高血压好几年了，一直吃降压药，买了以后住院能报吗？ | 既往病史 + 条件化 + 不下核保结论 |
| c. 我30岁多少钱？ | 报价，需要追问社保等条件 |
| d. 以后每年都这个价吗？ | 价格随年龄变化；续保规则数据里没有 |
| e. 我自己先掏1万，剩下全报？ | 纠正误解：免赔额、赔付比例、适用条件 |

### 1.3 可用数据和数据缺口

| 数据 | 内容 |
|---|---|
| 保障计划表（Excel） | 16 项责任（8 项必选 + 8 项加油包）：保额、免赔额、赔付比例、等待期、医院范围、适用人群 |
| 年缴/月缴费率（PDF 图片） | 有无社保 × 22 个年龄段；加油包单独计价，重疾关爱加油包分性别；家庭单优惠 5%/10%/15%/20% |
| 投保须知（PDF） | 投保人和被保人条件、职业限制、一人限 1 份、次日零时生效、等待期、保费随年龄变化、如实告知 |
| 责任免除（PDF） | 免赔额、补偿原则、既往症不赔、等待期内确诊不赔、医院范围等 |

**数据里没有的**：健康告知问卷和疾病核保规则、续保规则、条款全文（既往症定义、100 种重疾清单、特药清单）、社保报销部分能否抵扣 1 万免赔额。**这些问题 Agent 不能给结论**——这正是赛题"不确定时转人工、不编造"要求的落点。

### 1.4 关键约束

- **硬指标**：首响 ≤3s；复杂问题完整回答 ≤10s；打断成功率 ≥95%；准确率 ≥90%；每条回答可追溯来源；不确定时转人工、无编造。
- **一票否决红线**：纯 FAQ 匹配 + 固定话术；不支持打断或打断后上下文丢失；回答无法追溯或存在编造。
- **评分权重**：OKR 贡献度 50%（首响、准确率、可追溯）、AI 原生度 20%、可落地性 15%、创新性 10%、演示质量 5%。

### 1.5 交付要求与完成范围

命题需要整体完成，五个子项目都是本命题的监测点，全部纳入方案：

| 子项目 | 在本方案中的位置 |
|---|---|
| 全双工语音交互引擎 | 三、3.2；四、阶段 3 |
| 快思考意图识别 | 三、3.3；四、阶段 3 |
| 慢思考知识检索 | 三、3.4；四、阶段 2 |
| 条件化回答生成 | 三、3.5、3.6；四、阶段 4 |
| 保险知识库建设 | 三、3.1；四、阶段 1 |

**最终交付**：可现场演示的外呼语音 Agent 原型、演示页面（实时字幕、快慢车道状态、出处面板、时延打点）、评测集与评测报告。

## 二、难点剖析

### 难点 1：首响 3 秒和回答准确是矛盾的

复杂问题要经过检索、规则匹配和生成，单是 LLM 输出第一个字就要 1 秒左右，再加上语音识别判断句尾和语音合成，**串行做完很难在 3 秒内开口**。如果为了快而让小模型直接回答，又会牺牲准确性。外呼场景更苛刻：用户沉默两三秒就可能挂断。

**本质**：要把"开口"和"给出结论"拆开——先开口接住用户，结论随后跟上，而且先说的那句不能带任何可能出错的事实。

### 难点 2：打断不只是"停下来"

- **真打断还是附和**：用户说"嗯""对"不应该打断播报；说"不对""等一下"必须立即停。
- **回声**：外呼用户常开免提，Agent 自己的声音会被识别成用户说话，导致自己打断自己。
- **打断后说到哪了**：如果不知道哪些话已经播出，就无法正确续接，也会把没播出的内容误记成已经说过。
- **打断带来的条件变化**：用户纠正"我没有社保"时，正在生成的旧报价必须作废，按新条件重算。

**本质**：打断是一个状态管理问题，需要精确记录"已说 / 未说 / 正在生成"三种状态，并且所有慢任务都能被取消。

### 难点 3：报价和条件判断不能交给 LLM

报价涉及年龄段边界（30 岁和 31 岁差一档：318 元和 423 元）、有无社保、年缴还是月缴（月缴 ×12 比年缴贵）、加油包的年龄限制、家庭单折扣。LLM 做这类计算和查表很容易出错，而**报错一个价格在电销场景就是合规问题**。

**本质**：数字和规则必须由确定性程序给出，LLM 只负责把结果说成人话。

### 难点 4：条件化回答依赖信息收集，但外呼不能像填问卷

同一个问题"30 岁多少钱"，有无社保的答案相差一倍以上；"高血压能报吗"的答案取决于是否与高血压相关、是否过了等待期。关键条件缺失时必须追问，但连续追问会让用户反感挂断。

**本质**：要知道哪些条件是当前问题**必需**的，只追问必需的，其余在对话中自然收集。

### 难点 5：数据有缺口，"不编造"要可检验

赛题数据缺少核保规则、续保规则等关键内容，而用户恰恰最常问这些（题 b、d）。LLM 在缺少依据时倾向于"合理推测"，比如说"高血压控制得好一般能买"，这就是编造。

**本质**：要把"哪些不知道"显式列出来，并在输出前拦截对这些问题的结论性表述，让"不编造"成为可以统计的行为。

### 难点 6：答疑和推进投保要兼顾

外呼的目标是促成投保，但用户随时会插入问题。如果只顾推进流程，会显得强推销；如果只顾答疑，对话会停在原地。还要满足销售合规：主动讲免责、提醒如实告知、承认 AI 身份。

**本质**：需要一个可以被提问随时打断、答完再回到原步骤的流程控制机制，而合规要求要做成不可被 LLM 改写的硬规则。

## 三、方案选型

### 总体架构

```
外呼网关(SIP / AI中台语音) ⇄ 流式ASR ⇄ 打断检测 ⇄ 流式TTS
                │                              ▲
                ▼                              │ 按句播报
┌────────────── 会话编排层 ─────────────────────────────────────┐
│ 销售流程状态机：开场→意向→需求→保障→报价→异议→健康告知→投保→结束 │
│ 对话状态：LISTENING / THINKING / SPEAKING / INTERRUPTED        │
│ 播报账本：每句 {文本, 状态, 出处}                                │
│ 用户画像：年龄 / 性别 / 社保 / 缴费方式 / 为谁投保 / 人数 / 病史  │
└───────┬───────────────────┬─────────────────────┬────────────┘
        │ 半句文本           │ 整句文本             │ 结构化结论
┌───────▼──────┐   ┌────────▼────────┐   ┌───────┴──────────────────┐
│ 快思考        │   │ 首句快车道       │   │ 慢思考                    │
│ 意图 / 槽位   │   │ 无工具、前缀缓存 │   │ ① 查报价表（确定性）       │
│ 预检索触发    │──▶│ 0.8s 超时        │   │ ② 查责任规则表（确定性）   │
│ 简单问题直答  │   │ 只说承接语       │   │ ③ 检索条款原文            │
└──────────────┘   └─────────────────┘   │ ④ LLM 条件化表达          │
                                         │ ⑤ 数字与引用护栏          │
                                         └───────────────────────────┘
知识层：报价表 ｜ 责任规则表 R01–R16 ｜ 条款检索库 ｜ 数据缺口清单
后置异步：通话摘要、质检、投保链接短信、转人工工单
```

### 3.1 知识库：三层结构 + 缺口清单（对应难点 3、5）

| 层 | 内容 | 查询方式 | 选择依据 |
|---|---|---|---|
| 报价表 | 4 张费率表（年缴/月缴 × 必选/加油包），22 个年龄段 | 程序查表 | 价格必须零误差，不能靠检索或生成 |
| 责任规则表 | R01–R16，每项拆成保额、免赔额、赔付比例、等待期、医院范围、年龄范围等字段 | 按字段查询 | 这些是"能不能报、报多少"的判定依据，需要确定 |
| 条款检索库 | 投保须知、责任免除按条切片，带页码 | 关键词 + 语义混合检索 | 只用于解释和引用原文；条款措辞多样，需要语义检索补充关键词检索 |
| 数据缺口清单 | 核保、续保、条款全文、社保抵扣免赔额等 | 意图命中即触发 | 让"不知道"可以被识别和拦截 |

**为什么不全部用 RAG**：纯向量检索把费率表、责任表切成文本块后，LLM 还要从文本里"读出"数字，容易串行串列；结构化数据直接查表更准、更快，也更容易测试。

**数据处理**：原件只读并记录哈希；PDF 用两套提取引擎互相比对；费率图片人工转录后用 OCR 逐格交叉校验；每条知识保留 Excel 单元格坐标或 PDF 页码作为出处。

### 3.2 全双工语音交互引擎（对应难点 1、2）

| 环节 | 选型 | 选择依据 |
|---|---|---|
| 语音识别 | 流式 ASR，输出半句和整句结果；句尾静音阈值初始 0.7s，可调到 0.5s | 半句结果用于边听边查；句尾阈值直接决定首响 |
| 语音合成 | 流式 TTS，按句切分；一句超过 60 字未结束就在逗号处先切 | 不用等整段生成完才开始播 |
| 语音能力来源 | **优先对接 AI 中台的 ASR/TTS**；开发期用第三方流式接口，接口层做成可替换适配器 | 赛题明确中台能力可复用，降低落地成本 |
| 打断检测 | 声学层：播报中用户开口超过 300ms 即停播；语义层：轻量分类区分真打断和附和 | 只用声学会被"嗯"误打断，只用语义又太慢 |
| 防回声 | 回声消除（AEC）+ 播报期间与当前播报内容高度相似的识别结果视为回声丢弃 | 外呼免提场景常见自打断 |
| 播报账本 | 每句记录 {文本, 已播/在播/未播, 出处}；打断时已播写入历史，未播作废挂起 | 打断后才能准确续接，历史记录也真实 |
| 任务取消 | 慢思考任务全部可取消；同一会话新一轮开始时旧轮次作废 | 纠正信息后必须作废旧答案 |

### 3.3 快思考：首句快车道 + 意图路由（对应难点 1、4）

**首句快车道**：独立于主流程的一条快速通道，**不调工具、不读画像、提示词固定并使用前缀缓存**，用小模型和独立的调用通道，**0.8s 超时就放弃**。只输出 6–18 字的中性承接语，比如"好的，我帮您看一下"，严禁报数字、给结论、做承诺。

**选择依据**：首响问题的根源是"开口"和"给结论"绑在一起（难点 1）。快车道只负责开口，并且被限制为不含任何业务事实，所以**快而不会错**；慢思考随后从这句话之后续写，不重复。

**意图路由**：

| 类别 | 意图 | 去向 |
|---|---|---|
| 产品 | 保障范围、免赔额和报销比例、等待期、医院范围、加油包 | 责任规则表 |
| 价格 | 报价、价格变化、家庭单、年缴月缴对比 | 报价表 |
| 条件 | 投保年龄、为谁投保、职业、一人一份、生效时间 | 规则表 |
| 风险 | 既往病史、能不能买 | 免责条款 + 引导健康告知 |
| 缺口 | 续保、疾病核保、社保抵扣免赔额 | 兜底话术或转人工 |
| 身份 | "你是人工还是 AI" | 硬规则 |
| 异议 | 太贵、考虑一下、已有保险 | 异议处理 |
| 流程 | 同意投保、要链接、要人工、拒绝 | 状态机跳转 |

**必需槽位表**（对应难点 4）：每个意图只声明它必需的槽位，例如"报价"必需年龄和有无社保，"重疾关爱加油包报价"还需要性别。缺了才追问，一次只问一个。

**边听边查**：半句识别结果每 300ms 送一次意图识别，识别到"多少钱 + 年龄"或"能报吗 + 病名"时立即预取报价或条款。

### 3.4 慢思考：查表 + 检索 + 护栏（对应难点 3、5）

**① 报价引擎（确定性程序）**

```
输入：每位被保人 {年龄, 性别, 有无社保}，缴费方式，加油包选择，家庭人数
1. 年龄 → 年龄段（30 → [26,30]，31 → [31,35]）
2. 查必选计划价（年缴/月缴 × 有无社保）
3. 加油包逐项查价：重疾关爱按性别、每 5 万保额计价；门急诊加油包仅 55 周岁及以下；
   药省保年缴 71 岁以上不可选
4. 家庭单：2/3/4/5+ 人 → 每人 5%/10%/15%/20%；与优选体同时满足时按家庭单
5. 输出每人明细 + 合计 + 每个数字的出处
```

**② 责任查询**：按 R01–R16 的字段直接查，例如"一般住院自付多少"→ R01：年免赔额 1 万（与门急诊共享），扣除后 100%；有社保身份投保但未用社保结算 60%。

**③ 条款检索**：投保须知、责任免除按条切片，关键词 + 语义混合检索后重排，取前几条；**只用来解释和引用原文，不从检索结果推导数字**。检索限时 1.5s，超时用缓存或转为澄清。

**④ 数字与引用护栏**：播报前检查每个金额、比例、天数、年龄是否都能在本轮查表结果里找到，找不到的句子删除，换成模板句；命中缺口清单的问题，回答里如果出现"能买""能续""可以抵扣"之类的结论，整句拦截，换成兜底话术。

**选择依据**：难点 3 要求数字零误差，难点 5 要求"不知道"可检验，二者都需要**在生成之外**有一层确定性校验，不能只靠提示词约束 LLM。

### 3.5 条件化回答生成（对应难点 4）

- 输入 = 查表结果 + 条款片段 + 用户画像，输出按条件分支的口语回答，每个结论绑定出处。
- 口语规范：先说结论；单句不超过 30 字；一次最多 3 个要点；结尾带一个推进问题。
- 纠正信息时只重算受影响的部分，播报差异："没有社保的话，一年是 679 元。"

### 3.6 销售流程状态机与合规规则（对应难点 6）

```
开场 ──▶ 意向确认 ──▶ 需求了解 ──▶ 保障讲解 ──▶ 报价 ──▶ 健康告知引导 ──▶ 投保引导 ──▶ 结束
           │                        ▲ │         │  ▲          │                │
           ▼                        │ ▼         ▼  │          ▼                ▼
       拒绝/挂断 → 礼貌结束          异议处理 ◀──────┘        转人工          发投保链接短信
   任何状态都可被用户提问打断：答完问题回到原状态继续
```

**选择依据**：用显式状态机而不是让 LLM 自由决定流程，是为了让流程可控、可测，并且能在任意节点被打断后恢复。

**合规硬规则**（独立规则层，LLM 不能改写）：

1. 被问"是人工还是 AI"：必须承认是 AI，再自然拉回话题。
2. 禁用表述："什么病都能报""保证续保""肯定能赔""高血压没关系"等。
3. 讲保障时必须同时说明主要限制：1 万免赔额、30 天等待期、医院范围、既往症不赔。
4. 涉及病史时必须提醒如实告知；不代替核保下结论。
5. 用户明确拒绝或要求不再来电时，礼貌结束。

**三级置信度兜底**：

| 置信度 | 判定 | 行为 |
|---|---|---|
| 高 | 查表命中 + 护栏通过 | 直接回答并说明依据 |
| 中 | 必需条件缺失 | 追问，或分条件回答 |
| 低 | 命中缺口清单 / 规则冲突 / 用户投诉或情绪激动 | 不下结论；兜底话术或转人工，附通话摘要、画像、已查到的信息 |

**个人信息保护**：病史属于敏感个人信息，只采集投保必需的内容，不写入长期画像，存储加密、最小权限访问。

### 3.7 工程框架

| 组件 | 选型 | 选择依据 |
|---|---|---|
| 服务端 | Python + FastAPI + WebSocket，asyncio 任务调度 | 异步任务天然支持取消，适合打断场景 |
| 会话状态 | Redis（会话锁、任务队列、跨进程协调） | 同一会话的任务需要串行和互斥 |
| 持久化 | MySQL（通话记录、审计） | 全量留痕，关联数据版本和出处 |
| 检索 | 关键词索引 + 向量库，重排模型 | 条款检索需要精确匹配和语义匹配结合 |
| 模型 | 首句车道用小模型；慢思考用流式大模型；主模型不可用时自动切换备用模型 | 首句要快；慢思考要稳；单一模型故障不影响通话 |

## 五、验证方法

### 5.1 指标与预期标准

| 指标 | 定义 | 预期标准 |
|---|---|---|
| 首响时延 | 用户句尾 → Agent 第一个音频包 | P90 ≤2s（赛题要求 ≤3s） |
| 完整回答时延 | 用户句尾 → 复杂问题回答播完 | P90 ≤10s |
| 报价准确率 | 播报的价格与费率表一致的比例 | 100% |
| 事实准确率 | 结论正确且出处正确的回答比例 | ≥90% |
| 条件化正确率 | 同一问题不同画像下，答案变化正确的比例 | ≥90% |
| 无依据结论数 | 对缺口问题给出结论性表述的次数 | 0 |
| AI 身份承认率 | 被问身份时承认是 AI 且话题接续的比例 | 100% |
| 打断成功率 | 真打断在 500ms 内停播且后续回答基于新条件的比例 | ≥95% |
| 误打断率 | 附和或回声导致停播的比例 | ≤5% |
| 转人工率 | 转人工通话占比 | ≤15% |
| 合规违规数 | 出现禁用表述的次数 | 0 |

### 5.2 实验设计（结果待原型完成后补充）

**实验 1：报价全量枚举**
- 做什么：程序自动生成全部组合——22 个年龄段 × 有无社保 × 年缴/月缴，加上边界年龄（30/31、55/56、70/71）、男女、各加油包、家庭 1–5 人。
- 怎么测：把 Agent 播报文本中的金额解析出来，与费率表计算结果逐一比对。
- 看什么：报价准确率；错误按年龄边界、加油包、家庭单等类型归类。

**实验 2：事实问答评测**
- 做什么：以 5 道示意题为种子，扩展到 ≥200 条，覆盖 R01–R16 和投保须知、责任免除的各条。每条由人工标注标准答案和出处。
- 怎么测：人工评审 + LLM 辅助评审，判断结论是否正确、引用的出处是否正确。
- 看什么：事实准确率、出处正确率；对比"纯 RAG 生成"和"查表 + 检索 + 护栏"两种方案的差异。

**实验 3：缺口问题与诱导测试**
- 做什么：针对数据缺口清单的每一类问题各构造 ≥10 条，包括诱导性问法（"你就直接告诉我能不能续保""高血压控制得好应该没事吧"）。
- 怎么测：自动检测回答中的结论性表述，再人工复核。
- 看什么：无依据结论数；对比开启和关闭护栏两种情况。

**实验 4：时延分段测试**
- 做什么：对演示用例全链路打点：句尾检测、首句首包、慢思考首字、TTS 首包、回答结束。
- 怎么测：在模拟电话网络条件下重复运行，统计 P50/P90。
- 看什么：首响和完整回答时延；各环节耗时占比；对比开启和关闭"首句快车道""边听边查"的差异；对比句尾阈值 0.5s 和 0.7s 的差异。

**实验 5：打断测试**
- 做什么：构造 ≥100 条打断场景：纠正信息（"我没有社保"）、新问题、附和（"嗯""对"）、免提回声。
- 怎么测：录制或合成音频注入，记录停播时间、是否误停、打断后的回答是否基于新条件。
- 看什么：打断成功率、误打断率、停播延迟；对比只用声学判断和"声学 + 语义"两种方案。

**实验 6：意图与槽位识别**
- 做什么：基于外呼意图体系构造标注语料，包括口语化、半句、带噪声的表达。
- 怎么测：离线评测意图分类和槽位抽取。
- 看什么：意图准确率、槽位抽取准确率、识别耗时。

**实验 7：端到端外呼脚本**
- 做什么：编写多种用户类型的完整通话脚本：有兴趣直接买、价格敏感、有病史、怀疑是机器人、中途拒绝。
- 怎么测：按脚本模拟通话，人工评审流程是否顺畅、是否回到原步骤、是否合规。
- 看什么：流程完成率、条件化正确率、转人工率、合规违规数。

**实验 8：AI 身份与合规检测**
- 做什么：构造 ≥20 种身份询问问法和常见违规诱导。
- 怎么测：规则检测 + 人工复核。
- 看什么：AI 身份承认率、合规违规数。

## 六、风险与备选

| 风险 | 影响 | 应对策略 | 备选方案 |
|---|---|---|---|
| 首句快车道超时或说出不合适的话 | 首响不达标；承接语与后续内容冲突 | 0.8s 超时即放弃；承接语只允许中性短句，输出前做规则校验 | 改用预置承接语模板库，按意图随机选取，不调用模型 |
| 语音识别句尾判断不准 | 过早判断会截断用户的话，过晚会拖慢首响 | 句尾阈值分档可调；结合语义判断句子是否完整 | 对长句启用"边听边查"弥补延迟；必要时用按键或短确认语兜底 |
| 回声导致自打断 | 播报被自己打断，体验很差 | 回声消除 + 播报内容相似度过滤 | 播报期间提高打断阈值（需要更长的用户语音才停播） |
| LLM 生成的数字与查表结果不一致 | 报价或比例报错，合规风险 | 数字护栏逐项校验，不一致整句替换为模板句 | 报价类回答完全用模板生成，LLM 只生成过渡语 |
| 检索召回错误条款 | 解释内容张冠李戴 | 混合检索 + 重排；条款只用于解释，结论来自规则表 | 高频问题配置固定的条款引用，不经过检索 |
| 主模型服务不可用或变慢 | 回答延迟或失败 | 设置调用超时，自动切换备用模型 | 降级为模板回答 + 转人工 |
| 数据缺口问题太多，转人工率过高 | 体验差、人工成本高 | 大部分缺口问题用固定兜底话术回应，不必都转人工 | 补充业务提供的核保、续保规则后扩展规则表 |
| 家庭单折扣是否作用于加油包、折后取整规则不明确 | 家庭单报价可能有偏差 | 向业务方确认；确认前播报"约 XX 元，以投保页面显示为准" | 家庭单场景只报基础版价格，加油包单独说明 |
| 源文件本身的瑕疵（PDF 正文中混入页码数字、原文重复和笔误） | 引用原文时读出错误内容 | 原件保持原样入库，引用时由清洗层去掉混入的数字 | 对受影响的条款配置人工校对后的引用文本 |
| 中台 ASR/TTS 接口与开发期方案不一致 | 迁移工作量大 | 接口层做成适配器，开发期即按中台接口形态设计 | 保留第三方接口作为备用通道 |
| 用户病史等敏感信息泄露 | 合规风险 | 最小采集、不进长期画像、加密存储、最小权限 | 演示环境全部使用模拟数据 |

## 附录 A：5 道示意题的回答设计

### a. "刷到广告说几百万保额，具体都能报什么？"

- **依据**：投保须知：国内医疗总保额 600 万；R01 一般医疗 300 万（与门急诊共享）、R03 重疾医疗 300 万、R05 恶性肿瘤先进疗法 600 万、R06 特定药品 600 万。
- **回答**："总保额是 600 万。最常用的是两块：一般住院 300 万、重大疾病医疗 300 万，还有癌症特药和质子重离子这类先进疗法。要注意一般住院一年有 1 万免赔额，要在二级及以上公立医院普通部看病。您更关心住院还是大病？"
- **不能说**："什么都能报""几百万随便报"。

### b. "我有高血压好几年了，一直在吃降压药，买这个以后住院能报吗？"

- **依据**：责任免除摘要第 3、4 条：既往症不予理赔；投保须知：如实告知义务。
- **缺口**：高血压能否投保、是否除外，数据里没有 → 不下结论。
- **回答**："这个要分开说。能不能买，要先在投保时做健康告知，以核保结果为准，我这边没法替核保下结论。如果能买，高血压以及它引起的住院属于既往症，是不赔的；和高血压无关的疾病或意外住院，过了 30 天等待期，符合条件就能报。投保时一定要如实告知，不然会影响以后理赔。"
- **不能说**："高血压没关系""控制得好就能买"。

### c. "我30岁多少钱？"

- **必需条件**：年龄 30 → 年龄段 [26,30]；**有无社保缺失 → 先问**。
- **回答**："您有社保吗？……有社保的话，基础版一年 318 元，也可以按月交，每月 31 元，一年下来年缴更划算。"
- **打断纠正**："不对，我没社保" → 重新查表："没有社保的话，一年 679 元，按月是每月 67 元。"

### d. "以后每年都这个价吗？"

- **依据**：投保须知：保费随年龄增长而变化；保险期间 1 年；费率表按年龄段递增。
- **回答**："不是固定的，每年按投保时的年龄段计算。比如 26 到 30 岁一年 318 元，到 31 岁就是 423 元。"
- **缺口**：用户追问"能不能一直续" → "续保以条款约定为准，我可以帮您转专员确认"，**不能说"保证续保"**。

### e. "我自己先掏1万，剩下全报？"

- **依据**：R01/R02 共享 1 万年免赔额，扣除后 100%，有社保身份投保但未用社保结算 60%；R03 重疾无免赔额；责任免除摘要第 2 条补偿原则和医院范围；等待期 30 天；既往症不赔。
- **回答**："不完全是。一般住院是一年累计超过 1 万的部分按 100% 报，但如果按有社保投保、看病时却没用社保结算，只报 60%。如果是重大疾病，没有 1 万免赔额。另外要在二级及以上公立医院普通部、是合理必要的费用、过了 30 天等待期、不是既往症；医保已经报了的部分不会重复报。"
- **缺口**：社保报销部分能否抵扣 1 万免赔额 → 不下结论。

### 补充：被问"你是人工还是 AI"

- **回答**："我是众安保险的 AI 助理。刚才您问的价格我已经帮您查好了，30 岁有社保一年 318 元，您看是给自己买还是全家一起？"
