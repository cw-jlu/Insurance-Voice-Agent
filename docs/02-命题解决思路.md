# OPEN-JS-01 保险复杂咨询全双工语音Agent —— 命题解决思路（V1）

> 项目仓库：https://github.com/cw-jlu/Insurance-Voice-Agent
> 对应赛题：赛道二 · 语音交互与智能体 · OPEN-JS-01（原始要求见 [01-赛题原始要求.md](01-赛题原始要求.md)）
> 版本说明：V1 基于团队已落地的两套生产系统沉淀方案——**实时语音 Copilot**（流式 ASR→LLM→流式 TTS、打断、RAG、多模型容灾，线上运行）与 **语音优先的对话 Agent 框架**（首句快车道 + 主 Agent 双通道、会话调度、事实护栏、行为回归测试）。本方案的核心链路均有可复用的工程原型，而非从零设计。

---

## 一、一句话方案

**"首句快车道 + 证据慢车道 + 规则裁决"**：用户一开口，流式 ASR 的 partial 结果就驱动意图识别与条款预检索；句尾一到，≤0.8s 超时的"首句快车道"先说出一句不含任何业务事实的承接语（首响 ≈1.5s），与此同时慢车道完成"检索→规则引擎裁决→LLM 条件化表达→证据自检"，以句子为单位流式接续播报；任意时刻用户开口即打断，已播/未播内容按句保存，新条件触发慢车道取消重算；置信不足则主动澄清或带上下文转人工。

## 二、问题拆解与对应策略

| 赛题要求 | 难点 | 策略 | 已有工程基础 |
|---|---|---|---|
| KR1 首响≤3s | 复杂问题检索+推理必然 >3s | 快慢双车道；快车道只"接住"不作答 | 语音 Agent 框架的 First-Token 车道（独立模型/独立 Key/前缀缓存，超时 0.8s） |
| KR1 完整≤10s | LLM 全量生成慢、TTS 等整句慢 | LLM 流式 + 按句切分 TTS + 长句软切分 | Copilot 的句级流式 TTS（首块快发、60 字软切） |
| KR2 打断≥95% | 回声自打断、附和误打断、打断后上下文丢失 | 声学+语义两级打断；句级播报断点；可取消任务 | Copilot 的 barge-in 防回声守卫、`cancel_event` 流中止、会话调度"superseded" |
| KR3 准确≥90% 可追溯 | LLM 幻觉、条款相似度高易串 | 混合检索 + 按文档轮转去重 + 规则引擎给结论 + 引用校验 | Copilot 的 Pinecone RAG（带延迟预算/缓存/元数据过滤） |
| KR4 条件化 | 同一问题因人而异 | 槽位化用户画像 + 条件分支规则 + 主动澄清 | 语音 Agent 框架的画像/动态状态/业务快照记忆 |
| KR5 安全兜底 | "不知道"也要体面 | 三级置信门控；护栏"宁缺毋错"回退骨架；转人工 | 事实护栏（叙述与计算结果矛盾即拒写、回退代码骨架）；客服 Bot "只按文档回答、不会就路由" |

## 四、核心模块设计

### 4.1 全双工语音交互引擎（KR1、KR2）

**流式 ASR 与句尾检测**
- 使用支持 partial/final 的流式 ASR（开发期沿用已接入的 Speechmatics / AssemblyAI 实时接口，落地时替换为 AI 中台 ASR）。
- 句尾参数沿用线上验证值作为初始档：`max_delay=1.0s`、`end_of_utterance_silence_trigger=0.7s`（低延迟档 0.5s、稳妥档 1.0s），按场景可调。
- **边听边查**：partial 文本每 300ms 送快思考做意图/槽位预判，一旦识别出"产品 + 病种/场景"，立即触发慢车道**预检索**，句尾确认后直接进入规则裁决，节省 0.5–1s。
- 双声道/说话人分离：坐席旁听或三方通话场景可用声道分离区分"客户/坐席"。

**流式 TTS（句级）**
- LLM token 流按句切分（中英文句末标点 + 换行）；未出现句号但缓冲超过 **60 字**时在逗号/顿号处软切，避免长首句导致静音。
- 首个音频块立即下发，后续块批量下发，降低首包时延与消息频率。
- 一次回答使用"回答级"音频流（一次 `new` → 多个 `chunk` → 一次 `end`），避免句与句互相打断；回答间加锁串行，锁带超时（防止上一轮卡死导致全会话静音）。
- 播报前做 Markdown/符号清洗（条款号保留、链接去除），保证口播自然。

**打断（Barge-in）**
- **声学层**：播报中检测到用户语音（VAD + 最短时长 300ms）→ 立即淡出/暂停当前音频。
- **防回声自打断**：外放无耳机时 ASR 会把 Agent 自己的声音识别回来。沿用线上"播报中守卫"策略——播报进行时，与当前播报文本高度相似的转写视为回声丢弃；服务端同时开启 AEC。
- **语义层**：判断是"真打断"（新问题 / 纠正信息 / "等一下"）还是"附和"（嗯、对、好的），附和则恢复播报。用轻量分类（关键词 + 小模型，<150ms）。
- **打断后的上下文保持**：
  - 播报账本记录每句状态，打断时把 `played` 句写入对话历史（Agent 实际说过的话），`queued` 句标记 `dropped` 并挂起；
  - 慢车道通过 `cancel_event` 立即中止流式生成，不让残余 token 泄露到下一轮；
  - 会话调度对同 session 的旧轮次标记 `superseded`，新一轮以**合并后的画像**重新执行；
  - 若用户是纠正信息（"不是前年，是去年做的手术"），更新槽位后**取消并重算**慢车道；若用户问新问题，回答完后回收挂起内容："刚才关于您本人投保的说明还没讲完，需要继续吗？"

### 4.2 快思考：首句快车道 + 意图路由（KR1）

**首句快车道（First-Token Lane）**——直接复用已上线的设计：
- 独立于主 Agent 的 ReAct 循环：**无工具、无动态画像、稳定 system prompt 走前缀缓存 + 短对话尾巴**；独立模型与独立 API Key 通道，避免与主链路争抢限流。
- **硬超时 0.8s**，超时直接放弃、不影响主链路。
- **只输出 6–18 字的中性承接语**（"好的，我来帮您看一下。""收到，您稍等。"），严格禁止：给结论、承诺结果（"一定能赔"）、复述业务事实、谎称已查到。这条约束本身就是"不编造"的第一道防线。
- 首句发出后，给主 Agent 注入续写指令："上面的内容已作为第一句播出，从其后继续，不要复述"，保证首句与正式回答无缝衔接。

**意图与路由**
- 意图体系：投保咨询、健康告知/既往病史、核保条件、等待期/免责、理赔流程与材料、理赔进度、保单查询、退保/变更、投诉、转人工、闲聊。
- 路由：
  - **快答**：FAQ 高置信命中（相似度≥阈值且无条件分支）/ 纯查询类 → 快车道直接回答并附来源；
  - **慢答**：涉及病史、条件判断、多条款组合 → 承接语 + 慢车道；
  - **澄清**：关键槽位缺失（病种、确诊时间、治疗方式、险种、保单号）→ 先问再答，澄清期间预检索已并行进行；
  - **直转**：投诉、明确要求人工、高风险意图 → 直接转人工。

### 4.3 慢思考：检索 + 规则裁决 + 条件化表达（KR3、KR4）

1. **查询改写**：把口语改写为结构化查询 `{产品, 场景(投保/理赔), 病种, 时间, 治疗状态}`。
2. **混合检索**：BM25（条款号、病名精确匹配）+ 向量检索（语义）→ 重排；
   - 条款按"章-条-款"切片（初始 chunk 500 字 / overlap 150，条款边界优先），元数据包含 `产品、条款号、版本、生效日期`；
   - 候选 20 条 → 取 4 条，**按来源文档轮转取样**，防止一份文档占满全部名额；
   - 元数据过滤按"用户持有产品/咨询产品"限定范围，避免跨产品串条款；
   - 设**检索延迟预算**（语音场景收紧到 1.5s）+ 按 `(用户, 查询)` 的 TTL 缓存，超预算时用缓存或降级为"澄清/转人工"，绝不无限等待。
3. **规则引擎裁决（确定性）**：核保/理赔规则结构化为 `条件 → 结论 → 依据` 表，例如：
   ```yaml
   - id: UW-THY-02
     product: 百万医疗险A款
     when: {disease: 甲状腺结节, tirads: "<=3", surgery: false}
     then: {decision: 标准体承保, exclusion: 甲状腺相关疾病可能除外}
     basis: [条款第3条健康告知, 核保手册4.2]
   ```
   **结论由规则给出，LLM 只负责表达**。规则未覆盖的组合 → 降级为"需人工核保"，不让 LLM 自由发挥。
4. **个人数据工具**：保单状态、理赔进度通过工具调用查询业务系统（演示期 Mock）；耗时长的查询走异步任务，结果回来后以"系统激活"方式主动推送给用户（沿用框架的异步完成事件 → 会话空闲时再投递的机制）。
5. **条件化生成**：输入 = 规则结论 + 证据片段 + 画像，输出口语化分支回答（"您这种情况……；如果后续……则……"），每个结论句绑定 `evidence_id`，并附"以核保/理赔审核结论为准"。
6. **证据自检 / 事实护栏**：沿用"叙述与计算结果矛盾即拒写、回退骨架"的护栏思路——
   - 回答中的结论、数字（等待期天数、赔付比例、年龄上限）必须与规则/证据一致，不一致的句子**删除并回退为规则模板句**；
   - 找不到证据支撑的句子降级为"这部分需要人工进一步确认"。宁可少说，不可说错。

### 4.4 上下文与用户画像（KR2、KR4）

- **会话记忆**：滚动窗口 + 滚动摘要（窗口约 4K tokens，溢出部分由小模型摘要压缩，摘要上限 1K tokens），异步执行不阻塞回答；断线重连时从持久化记录回放到内存。
- **结构化画像（槽位）**：`年龄、性别、咨询对象(本人/家属)、产品、投保时间、等待期状态、既往病史[{病种, 分级, 确诊时间, 治疗方式}]、保单号、理赔单号`。每个槽位带来源（用户口述/系统查询）与更新时间，纠正信息覆盖旧值并留痕。
- **多对象上下文**：用户在"自己"和"母亲"之间切换时画像分栈，避免把母亲的年龄套到本人的病史上。

### 4.5 安全兜底与合规（KR5）

| 置信度 | 判定条件 | 行为 |
|---|---|---|
| 高 | 规则命中 + 证据充分 + 自检通过 | 直接回答，口播注明来源（"根据条款第 3 条"），界面展示原文 |
| 中 | 证据部分命中 / 槽位缺失 / 规则需额外条件 | 主动澄清；或条件化回答 + "以核保结论为准" |
| 低 | 无证据 / 规则冲突 / 检索超预算 / 医疗诊断、承诺赔付、投诉等敏感意图 | 不作答，**转人工**，推送"对话摘要 + 画像 + 已检索证据 + 未解决问题" |

其他约束：
- **系统消息与回答严格分离**：状态提示（"正在查询条款…"）走独立通道，绝不作为 AI 回答播出或入库。
- **无需回复标记**：用户仅附和/无效输入时模型输出 `NO_REPLY` 标记，编排层吞掉不播报，避免"没话找话"。
- 承诺性话术、医疗诊断、价格承诺等禁用词过滤；全量对话留痕并关联条款版本，满足审计。

### 4.6 保险知识库建设

- **条款库**：PDF/Word 解析 → 章-条-款切片 → 向量 + BM25 双索引；按版本/生效日期管理，旧版本保留可追溯。
- **规则库**：YAML/表格，业务人员可维护；规则变更走评测回归后发布。
- **FAQ 库**：`问题 - 答案 - 来源条款` 三元组，只收"无条件分支"的问题，有条件的问题一律交给规则引擎。
- **历史咨询记录**：脱敏后用于意图样本、评测集和"相似案例"召回。
- **维护成本**：知识更新 = 增量入库 + 改规则表，无需重训模型；删除走限流批量删除，避免误删全量索引。

## 五、时延预算（KR1）

| 阶段 | 首响（快车道） | 完整回答（慢车道） | 依据 |
|---|---|---|---|
| ASR 句尾确认 | 0.5–0.7s | 0.5–0.7s | 线上 `end_of_utterance` 0.5/0.7s 档 |
| 意图 + 首句生成 | ≤0.8s（硬超时） | — | First-Token 车道 0.8s 超时 |
| 预检索（partial 驱动） | — | 与说话并行，句尾后剩余 ≈0.3–0.8s | 边听边查 |
| 规则裁决 + 工具查询 | — | ≈0.3–0.5s | 确定性计算 |
| LLM 首 token（续写） | — | ≈0.8–1.5s | 流式 |
| TTS 首包 | ≈0.3s | ≈0.3s | 首块立即下发 |
| **合计** | **≈1.6–1.8s（≤3s）** | **首句结论 ≈3–4s，完整 ≈6–8s（≤10s）** | |

保底：LLM 主模型不可用时按"同厂最新 → 跨厂商同档"自动降级（线上已有跨 Azure/Bedrock/Gemini/DeepSeek 等多家的降级链）；检索超预算时用缓存或转澄清。

## 六、典型对话（覆盖病史 + 条件化 + 打断 + 纠正 + 转人工）

> **用户**：我前年查出甲状腺结节，现在能买你们的百万医疗险吗？
> *（partial 阶段已识别 `产品=百万医疗 / 病种=甲状腺结节`，预检索开始）*
> **Agent（首句车道，≈1.6s）**：好的，我帮您看一下。
> **Agent（慢车道续写）**：为了判断准确，想确认两点：结节是几级？有没有做过手术？
> **用户**：三级，没做手术。
> **Agent（≈4s）**：根据《百万医疗险A款》健康告知第 3 条和核保规则 UW-THY-02，TI-RADS 3 级且未手术，一般可以标准体承保，但甲状腺相关疾病可能列为除外责任——
> **用户**：（打断）等一下，我记错了，是去年做过射频消融。
> *（停止播报 → 已播句入历史 → 槽位 `surgery=true, 时间=去年` → 取消并重算慢车道）*
> **Agent**：明白，做过消融的话情况不同：根据规则 UW-THY-05，术后不满两年通常需要人工核保，可能加费或除外。这个需要核保专员根据您的病历判断，我帮您转接人工核保，刚才的情况我会一并交给专员，您不用重复说。

## 七、评测方案

| 指标 | 测试集 | 方法 |
|---|---|---|
| 首响 / 完整时延 | 全部用例 | 全链路打点（ASR 句尾、首句首包、慢车道首 token、TTS 首包、回答结束），统计 P50/P90 |
| 打断成功率 | ≥100 条：新问题 / 纠正 / 附和 / 外放回声 | 是否在 ≤500ms 内停播；附和不误停；回声不自打断；打断后回答是否基于新条件 |
| 准确率 & 可追溯 | ≥200 条：病种 × 产品 × 场景 组合，业务专家标注 | 结论正确性 + 引用条款正确性，人工 + LLM 评判 |
| 条件化 | 同问题不同画像的成对用例 | 回答是否随画像变化且变化正确 |
| 安全兜底 | 超范围、诱导承诺、信息不足、规则冲突等对抗用例 | 转人工率、零编造（无证据结论数 = 0） |
| 行为回归 | 从真实长对话抽取"关键行为场景" | 校验"是否守边界、是否调对工具、是否自然承接"，不逐字比对（沿用框架的场景回归测试方法） |

---

## 八、落地与对接（可落地性）

- **接入**：WebSocket（App/Web）+ SIP/媒体网关（呼叫中心），统一 Agent Ingress 接口，渠道差异通过"交付格式"适配。
- **转人工**：推送结构化工单（摘要、画像、证据、未解决问题、完整转写），坐席零重复询问；坐席旁听时 Agent 可切换为"坐席 Copilot"模式实时给出条款提示——这正是团队现有实时 Copilot 产品形态。
- **部署**：FastAPI/Uvicorn + Redis（会话锁、任务队列、跨 worker 协调）+ MySQL（状态与审计）+ 向量库；Docker Compose 单机演示，生产走容器编排，按会话粘性水平扩容。
- **运维**：Admin 调试页可在线查看/修改 prompt、场景、会话状态和任务运行；ASR/TTS/LLM 用量与时延监控告警。
- **合规**：录音告知与同意、敏感信息脱敏、对话与条款版本留痕可审计。

---

## 九、创新点

1. **首句快车道**：独立模型/独立通道/前缀缓存/0.8s 硬超时，"只接话不作答"——既拿下 3 秒首响，又从机制上杜绝快路径编造。
2. **边听边查**：partial 转写驱动预检索，把检索时间藏进用户说话的时间里。
3. **规则裁决 + LLM 表达分离 + 事实护栏**：结论可解释、可审计，矛盾即回退模板，"宁缺毋错"。
4. **句级播报账本**：打断后精确知道"说到哪了"，支持继续、丢弃或按新条件重算；叠加防回声守卫，外放场景也不自打断。
5. **主动澄清 + 分栈画像**：先问再答，本人/家属信息不串，实现真正的个性化条件化回答。
6. **带上下文的转人工 + 坐席 Copilot**：兜底不是"甩锅"，而是把已完成的工作交给坐席。
