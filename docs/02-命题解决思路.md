## 摘要

用户在媒体渠道看过尊享e生·百万医疗2026 的广告但没有投保，AI 坐席打电话过去，讲清保障、报价，引导完成健康告知和投保。方案主线是：**快思考稳住通话节奏，慢思考保证每个事实有出处，状态机推进投保流程**。

## 一、命题解读

### 1.1 核心任务

构建一个**全双工语音 Agent**，在电话里边听边说、支持随时打断，对"既往病史 + 投保"这类复杂咨询给出**按用户情况区分的、能追溯到条款的、不编造的**回答。架构上要求"快思考 + 慢思考"协同：快思考负责低延迟的接话和简单问答，慢思考负责检索、规则推理和准确回答。

### 1.2 赛题数据揭示的具体场景

赛题数据中的场景说明：

> 场景：媒体渠道X浏览未投保 → 电话外呼促投
> 坐席身份：众安电销坐席，引导完成投保+健康告知，如果问到人工还是AI，需要承认是AI但是可以吸引用户继续往下走。

由此得出几个和普通客服不同的地方：

| 维度 | 普通呼入客服 | 本命题 |
|---|---|---|
| 谁先开口 | 用户 | **Agent 外呼**，要开场、说明来电原因 |
| 目标 | 答疑 | **答疑 + 推进投保**：保障 → 报价 → 健康告知 → 投保 |
| 用户状态 | 带着问题来 | 有兴趣但有顾虑，**随时可能挂断** |
| 产品 | 多产品 | 单一产品（尊享e生·百万医疗保险2026版）+ 8 个加油包 |
| 身份 | 不涉及 | 被问到必须**承认是 AI**，再自然拉回话题 |
| 合规 | 不编造 | 不编造 + 销售合规：不夸大、不承诺赔付、主动讲免责、提醒如实告知 |

赛题给出的 5 道示意题覆盖了这个场景的典型问题：

| 题目 | 考点 |
|---|---|
| a. 刷到广告说几百万保额，具体都能报什么？ | 产品介绍，不夸大 |
| b. 我有高血压好几年了，一直吃降压药，买了以后住院能报吗？ | 既往病史 + 条件化 + 不下核保结论 |
| c. 我30岁多少钱？ | 报价，需要追问社保等条件 |
| d. 以后每年都这个价吗？ | 价格随年龄变化；续保规则数据里没有 |
| e. 我自己先掏1万，剩下全报？ | 纠正误解：免赔额、赔付比例、适用条件 |

### 1.3 可用数据和数据缺口

| 数据 | 内容 |
|---|---|
| 保障计划表（Excel） | 16 项责任（8 项必选 + 8 项加油包）：保额、免赔额、赔付比例、等待期、医院范围、适用人群 |
| 年缴/月缴费率（PDF 图片） | 有无社保 × 22 个年龄段；加油包单独计价，重疾关爱加油包分性别；家庭单优惠 5%/10%/15%/20% |
| 投保须知（PDF） | 投保人和被保人条件、职业限制、一人限 1 份、次日零时生效、等待期、保费随年龄变化、如实告知 |
| 责任免除（PDF） | 免赔额、补偿原则、既往症不赔、等待期内确诊不赔、医院范围等 |

**当前数据里没有的**：健康告知问卷和疾病核保规则、续保规则、条款全文（既往症定义、100 种重疾清单、特药清单）、社保报销部分能否抵扣 1 万免赔额。**这些问题 Agent 不能给结论**——这正是赛题"不确定时转人工、不编造"要求的落点。

**官方补充说明**（见 [05-官方补充QA.md](05-官方补充QA.md)）：
- 正式数据包会包含**产品条款**。所以知识库的入库流程要做成通用的：条款到了直接切片入库，缺口清单随之缩小，不需要改代码。
- 数据包中的示例问题**不会出现在测试集中**。所以不能只针对 5 道示例题调优，评测集要覆盖全部责任、投保须知和条款，并留出一部分题目不参与调优，用来检验泛化能力。

### 1.4 关键约束

- **硬指标**：首响 ≤3s；复杂问题完整回答 ≤10s；打断成功率 ≥95%；准确率 ≥90%；每条回答可追溯来源；不确定时转人工、无编造。
- **一票否决红线**：纯 FAQ 匹配 + 固定话术；不支持打断或打断后上下文丢失；回答无法追溯或存在编造。
- **评分权重**：OKR 贡献度 50%（首响、准确率、可追溯）、AI 原生度 20%、可落地性 15%、创新性 10%、演示质量 5%。
- **验收方式**（官方补充）：打断和时延**通过录音验证**；回答准确率用**官方准备的测试集**测试。
- **资源与环境**（官方补充）：不提供 ASR、TTS、LLM 等能力，需要自行接入第三方服务（如腾讯云 ASR、阿里云大模型和 TTS 的免费额度）；不指定开发平台；不提供服务器和 GPU，运行环境自定，但必须能**现场交互**；现场可以联网。

### 1.5 交付要求与完成范围

命题需要整体完成，五个子项目都是本命题的监测点，全部纳入方案：

| 子项目 | 在本方案中的位置 |
|---|---|
| 全双工语音交互引擎 | 三、3.2；四、阶段 3 |
| 快思考意图识别 | 三、3.3；四、阶段 3 |
| 慢思考知识检索 | 三、3.4；四、阶段 2 |
| 条件化回答生成 | 三、3.5、3.6；四、阶段 4 |
| 保险知识库建设 | 三、3.1；四、阶段 1 |

**最终交付**：在自己的笔记本上运行、可现场交互的外呼语音 Agent 原型；演示页面（实时字幕、快慢车道状态、出处面板、时延打点）；通话录音及时间戳记录，供验收时核对打断和时延；文本批量问答接口，供跑官方测试集；评测集与评测报告。

## 二、难点剖析

### 难点 1：首响 3 秒和回答准确是矛盾的

复杂问题要经过检索、规则匹配和生成，单是 LLM 输出第一个字就要 1 秒左右，再加上语音识别判断句尾和语音合成，**串行做完很难在 3 秒内开口**。如果为了快而让小模型直接回答，又会牺牲准确性。外呼场景更苛刻：用户沉默两三秒就可能挂断。

**本质**：要把"开口"和"给出结论"拆开——先开口接住用户，结论随后跟上，而且先说的那句不能带任何可能出错的事实。

### 难点 2：打断不只是"停下来"

- **真打断还是附和**：用户说"嗯""对"不应该打断播报；说"不对""等一下"必须立即停。
- **回声**：外呼用户常开免提，Agent 自己的声音会被识别成用户说话，导致自己打断自己。
- **打断后说到哪了**：如果不知道哪些话已经播出，就无法正确续接，也会把没播出的内容误记成已经说过。
- **打断带来的条件变化**：用户纠正"我没有社保"时，正在生成的旧报价必须作废，按新条件重算。

**本质**：打断是一个状态管理问题，需要精确记录"已说 / 未说 / 正在生成"三种状态，并且所有慢任务都能被取消。

### 难点 3：报价和条件判断不能交给 LLM

报价涉及年龄段边界（30 岁和 31 岁差一档：318 元和 423 元）、有无社保、年缴还是月缴（月缴 ×12 比年缴贵）、加油包的年龄限制、家庭单折扣。LLM 做这类计算和查表很容易出错，而**报错一个价格在电销场景就是合规问题**。

**本质**：数字和规则必须由确定性程序给出，LLM 只负责把结果说成人话。

### 难点 4：条件化回答依赖信息收集，但外呼不能像填问卷

同一个问题"30 岁多少钱"，有无社保的答案相差一倍以上；"高血压能报吗"的答案取决于是否与高血压相关、是否过了等待期。关键条件缺失时必须追问，但连续追问会让用户反感挂断。

**本质**：要知道哪些条件是当前问题**必需**的，只追问必需的，其余在对话中自然收集。

### 难点 5：数据有缺口，"不编造"要可检验

赛题数据缺少核保规则、续保规则等关键内容，而用户恰恰最常问这些（题 b、d）。LLM 在缺少依据时倾向于"合理推测"，比如说"高血压控制得好一般能买"，这就是编造。

**本质**：要把"哪些不知道"显式列出来，并在输出前拦截对这些问题的结论性表述，让"不编造"成为可以统计的行为。

### 难点 6：答疑和推进投保要兼顾

外呼的目标是促成投保，但用户随时会插入问题。如果只顾推进流程，会显得强推销；如果只顾答疑，对话会停在原地。还要满足销售合规：主动讲免责、提醒如实告知、承认 AI 身份。

**本质**：需要一个可以被提问随时打断、答完再回到原步骤的流程控制机制，而合规要求要做成不可被 LLM 改写的硬规则。

### 难点 7：全部依赖第三方云服务，时延和可用性不可控

官方不提供 ASR、TTS、LLM，也不提供 GPU，所有能力都要调用第三方云服务（如腾讯云、阿里云）。一次回答至少经过 ASR、LLM、TTS 三次网络调用，每次的时延都有波动；免费额度有上限，还有调用频率限制；现场网络情况也不确定。验收又是通过录音直接看时延和打断，没有调整余地。

**本质**：时延预算要按"网络调用 + 波动"来留余量，每个外部服务都要有超时、备用和降级方案，并且时延要在每个环节可测量。

### 难点 8：一问一答做对了，不等于整通电话做对了

单轮问答准确率高，整通电话里仍会出问题：前面说过的条件要记住、纠正后要重新算、用户一句话里既给信息又提问、问完身份不能丢掉刚说的年龄、同意要识别、缺口问题被反复追问时要升级而不是机械重复、不能承诺系统做不到的事。这些都发生在"轮与轮之间"，单轮测试测不出来。

**本质**：需要一个贯穿整通电话的会话层（画像、历史、阶段、已说事项、风险），每轮调度规则由程序决定；评测也必须用整通电话的剧本，而不只是逐题问答。

## 三、方案选型

### 总体架构：两层链路

外呼推销分两层：**大链路**是整通电话的销售流程（这通电话往哪走），**小链路**是每一轮的回答流水线（这一句怎么答）。大链路决定这一轮的目标，小链路执行；用户中途插问，小链路先答，再回到大链路原来的步骤。

```
演示：浏览器模拟通话(WebRTC + 回声消除) ｜ 落地：SIP外呼网关
                │
流式ASR(腾讯云) ⇄ 打断控制 ⇄ 流式TTS(阿里云，3条持久连接并行 + 固定句预合成)
                │                        ▲
                ▼                        │ 逐句播报（写入播报账本）
┌──────────────── 大链路：CallSession（一通电话一个，全局上下文）──────────────────┐
│ 用户画像（条件 + 来源 + 纠正记录） ｜ 对话历史（实际播出的话） ｜ 已说事项 ｜ 风险记录 │
│ 销售状态机：开场 → 需求 → 报价 → 讲限制 → 健康告知 → 投保 → 收尾                   │
│ 门禁：条件齐才报价；已报价、已讲限制、已提示如实告知、用户同意 才发投保链接          │
│ 任何阶段：提问/异议 → 小链路回答后回到原阶段；要人工/投诉 → 转人工；两次拒绝 → 结束    │
└──────────────────────────────┬────────────────────────────────────────────────┘
                               │ 本轮目标 + 画像 + 最近对话
┌──────────────── 小链路：每一轮的回答 ──────────────────────────────────────────┐
│ 首句承接(规则,预合成)                                                          │
│ 并行：理解(意图+缺口 / 责任+主题 / 条件 三个短调用) ｜ 对话作用 ｜ 缺口检测 ｜ 原话检索 │
│ → 门禁 → 程序能答的直接成句(报价/折扣/合计/等待期/年龄资格/续保与清单兜底)          │
│ → 其余：按责任分组取依据(理解层一次最多选5项) → 组织回答(大模型) → 护栏 → 播报      │
└───────────────────────────────────────────────────────────────────────────────┘
知识层：报价表 ｜ 责任规则表 R01–R16 ｜ 固定条款 ｜ 条款检索库 ｜ 数据缺口清单
后置异步：通话摘要、质检、投保链接短信、转人工工单
```

### 3.0 分工原则：workflow 管门禁，Agent 管理解和表达

| 方式 | 含义 | 优点 | 缺点 |
|---|---|---|---|
| Workflow | 路线事先画好，步骤之间有门禁，程序决定走哪一步 | 快、可控、可复现、合规有保证 | 接不住流程外的说法 |
| Agent | 模型决定下一步，可以一直叠 step（调工具、看结果、再决定） | 灵活 | 每多一步约多 1 秒；路径不可预测；可能走偏 |

本方案以 workflow 为骨架，只在需要"听懂人话""说人话"的节点交给模型：

| 交给程序（workflow） | 交给模型（Agent 节点） |
|---|---|
| 报价金额、保额、免赔额、等待期 | 把这些数字组织成口语 |
| 阶段跳转和门禁（报价前要有年龄和社保，发链接前要提示如实告知并获得同意） | 判断用户这句话的作用（提问 / 提供信息 / 同意 / 拒绝 / 异议 / 要人工） |
| 数据缺口一律兜底，同一主题反复追问时询问是否转人工 | 判断这句话是不是缺口问题 |
| 身份必须承认 AI、开场说明录音 | 承认之后怎么自然地拉回话题 |
| 能力边界（只能报价、讲保障、发投保链接短信、转人工） | 一次选出本问题涉及的全部责任（最多 5 项） |

**选择依据**：实验中规则类的语言理解在新说法上普遍失效（条件抽取年龄 36%、附和误判 18%），必须交给模型；而模型自由发挥的环节错误最多（跨责任混淆、对缺口下结论、承诺做不到的事），必须由程序设门禁（见实验 3、6、8）。

**当前实现**：第五轮曾让 Agent 在复合问题上自行叠 step 补依据；第九轮实验（30 道复合题）表明，让理解层一次最多选 5 项责任、不用 Agent，准确率持平而耗时 P50 少约 2 秒，因此默认不启用 Agent（exp14）。

**下一版候选：并行小模型判断是否需要补查**。Agent 的用途仅是补取依据，不决定销售流程，也不写最终回答。让独立小模型从用户原话列出回答必需的责任（最多 5 项），与现有理解、原话检索并行；把结果与实际已取到的责任逐项比对。有缺项就启动证据 Agent。模型超时、调用失败或输出不合格式才使用旧关键词规则兜底；规则不得否决模型的触发。具体数字、局限和选型理由见 5.6。该方案尚未接入 `CallSession`，不能把离线触发率当作回答准确率。

### 3.1 知识库：三层结构 + 缺口清单（对应难点 3、5）

| 层 | 内容 | 查询方式 | 选择依据 |
|---|---|---|---|
| 报价表 | 4 张费率表（年缴/月缴 × 必选/加油包），22 个年龄段 | 程序查表 | 价格必须零误差，不能靠检索或生成 |
| 责任规则表 | R01–R16，每项拆成保额、免赔额、赔付比例、等待期、医院范围、年龄范围等字段 | 按字段查询 | 这些是"能不能报、报多少"的判定依据，需要确定 |
| 条款检索库 | 投保须知、责任免除按条切片，带页码 | 关键词 + 语义混合检索 | 只用于解释和引用原文；条款措辞多样，需要语义检索补充关键词检索 |
| 数据缺口清单 | 核保、续保、条款全文、社保抵扣免赔额等 | 意图命中即触发 | 让"不知道"可以被识别和拦截 |

**为什么不全部用 RAG**：纯向量检索把费率表、责任表切成文本块后，LLM 还要从文本里"读出"数字，容易串行串列；结构化数据直接查表更准、更快，也更容易测试。

**数据处理**：原件只读并记录哈希；PDF 用两套提取引擎互相比对；费率图片人工转录后用 OCR 逐格交叉校验；每条知识保留 Excel 单元格坐标或 PDF 页码作为出处。

### 3.2 全双工语音交互引擎（对应难点 1、2）

| 环节 | 选型 | 选择依据 |
|---|---|---|
| 语音识别 | 流式 ASR，输出半句和整句结果；句尾静音阈值初始 0.7s，可调到 0.5s | 半句结果用于边听边查；句尾阈值直接决定首响 |
| 语音合成 | 流式 TTS，**3 条持久连接同时合成一段回答里的各句**；流程话术、模板、兜底话术等固定句在通话前合成好，播放时不再合成；连接被服务端关闭时自动重连 | 持久连接每句首包约 0.2 s（新建约 1 s）；逐句串行合成曾使一段回答合成 3–7 s（第六轮），并行 + 预合成后"音频全部合成完"不再逐句累加（第九轮） |
| 语音能力来源 | ASR 用**腾讯云实时语音识别**，TTS 用**阿里云流式语音合成**；接口层做成可替换的适配器，各自准备一个备用服务 | 官方不提供语音能力，需要自行接入；两家都有免费额度，且支持流式（见官方补充 QA） |
| 演示形态 | 浏览器页面模拟通话（WebRTC 采集麦克风、播放音频），服务跑在自己的笔记本上 | 官方要求现场可交互、不提供服务器；落地时把浏览器换成 SIP 外呼网关，后端不变 |
| 录音与打点 | 服务端同时录下用户和 Agent 两路音频，记录句尾、首包、停播等时间戳 | 官方通过录音验收打断和时延，需要能从录音里核对 |
| 打断检测 | 声学层：播报中检测到用户开口先**降低音量**继续听；语义层：第一段识别结果出来后，明确的附和或叫停词由规则直接判断，其余交给小模型判断是附和还是打断 | 只用声学会被"嗯"误打断；只用规则会把"然后呢""你说"误判为打断（见实验 5、第四轮） |
| 防回声 | **以回声消除（AEC）为主，且为必选项**（无 AEC 时附和和回声全部误停，见实验 5 真实音频）；文本层再做补充：播报期间与当前播报内容高度相似的识别结果视为回声丢弃，**但用户话里出现播报中没有的否定或纠正词（"没有""不是""不对"）时一律不丢** | 外呼免提场景常见自打断；纠正语天然重复 Agent 的用词，只按相似度过滤会把"我没有社保"当成回声删掉（见实验 5） |
| 播报账本 | 每句记录 {文本, 已播/在播/未播, 出处}；打断时已播写入历史，未播作废挂起 | 打断后才能准确续接，历史记录也真实 |
| 任务取消 | 慢思考任务全部可取消；同一会话新一轮开始时旧轮次作废 | 纠正信息后必须作废旧答案 |

### 3.3 快思考：首句快车道 + 意图路由（对应难点 1、4）

**首句快车道**：独立于主流程的一条快速通道。用户一句话说完，由**规则从少量固定的中性承接语中选一句**（如"好的，我帮您看一下"），直接播放预合成的本地音频；身份询问等有固定回答的问题直接播放固定回答。承接语不含任何业务事实，严禁报数字、给结论、做承诺。小模型只用于理解用户意图，不用于生成承接语——承接语不需要模型，规则选择更快也更可控（见实验 4）。

**承接语音频预合成**：承接语是少量固定短句，全部预先合成并缓存在本地，首句直接播放本地音频，不经过 TTS 网络调用。这样首响只取决于语音识别的句尾判断，不受模型和云端 TTS 时延影响（见实验 4）。

**选择依据**：首响问题的根源是"开口"和"给结论"绑在一起（难点 1）。快车道只负责开口，并且被限制为不含任何业务事实，所以**快而不会错**；慢思考随后从这句话之后续写，不重复。

**意图路由**：

| 类别 | 意图 | 去向 |
|---|---|---|
| 产品 | 保障范围、免赔额和报销比例、等待期、医院范围、加油包 | 责任规则表 |
| 价格 | 报价、价格变化、家庭单、年缴月缴对比 | 报价表 |
| 条件 | 投保年龄、为谁投保、职业、一人一份、生效时间 | 规则表 |
| 风险 | 既往病史、能不能买 | 免责条款 + 引导健康告知 |
| 缺口 | 续保、疾病核保、社保抵扣免赔额 | 兜底话术或转人工 |
| 身份 | "你是人工还是 AI" | 硬规则 |
| 异议 | 太贵、考虑一下、已有保险 | 异议处理 |
| 流程 | 同意投保、要链接、要人工、拒绝 | 状态机跳转 |

**必需槽位表**（对应难点 4）：每个意图只声明它必需的槽位，例如"报价"必需年龄和有无社保，"重疾关爱加油包报价"还需要性别。缺了才追问，一次只问一个。

**理解拆成三个短调用并行**（第十轮消融方案 C）：意图 + 缺口、涉及的责任 + 主题、条件抽取，各自一个短提示词同时调用，每个 3 秒超时、重试一次、失败用默认值；与对话作用分类、专用缺口检测、原话检索四路并行，最慢一路决定耗时。理解 P50 0.89 → 0.5–0.7 s。

**条件抽取与复述确认**：条件由 LLM 从对话中抽取，规则抽取作为兜底；年龄、有无社保等决定价格的关键条件，报价前复述确认（"您是 29 岁、有社保，对吧？"），同时纠正语音识别错误（见实验 6）。抽取结果写入画像前做校验（第十轮回归）：年龄须在原话中以年龄形式出现（"636 一年"不能读成 63 岁）；假设句（"等我七十多了"）、比较句（"比有社保贵"）、提到家人生病（"我父亲得过肺癌"）不改对应条件。

**缺口判定**：理解模块、专用缺口检测、关键词规则三路中两路一致才算缺口（单路误报：专用检测 46/221，理解模块 10/221；两路一致 1–3/221，exp12）；续保、社保抵扣在问题明确提到"续/到期/停售""医保报销与免赔额"时一路即可，因其兜底话术本身无害。

**边听边查**：半句识别结果每 300ms 送一次意图识别，识别到"多少钱 + 年龄"或"能报吗 + 病名"时立即预取报价或条款。

### 3.4 慢思考：查表 + 检索 + 护栏（对应难点 3、5）

**① 报价引擎（确定性程序）**

```
输入：每位被保人 {年龄, 性别, 有无社保}，缴费方式，加油包选择，家庭人数
0. 资格校验：被保人出生满 30 天至 70 周岁（门急诊加油包至 55 周岁），以投保须知为准。费率表中还列有续保价格（70 岁以上、门急诊加油包 56–70 岁），不能据此给首次投保的人报价（见实验 1）
1. 年龄 → 年龄段（30 → [26,30]，31 → [31,35]）
2. 查必选计划价（年缴/月缴 × 有无社保）
3. 加油包逐项查价：重疾关爱按性别、每 5 万保额计价；门急诊加油包仅 55 周岁及以下；
   药省保年缴 71 岁以上不可选
4. 家庭单：2/3/4/5+ 人 → 每人 5%/10%/15%/20%；与优选体同时满足时按家庭单
5. 输出每人明细 + 合计 + 每个数字的出处
```

**② 责任查询**：按 R01–R16 的字段直接查，例如"一般住院自付多少"→ R01：年免赔额 1 万（与门急诊共享），扣除后 100%；有社保身份投保但未用社保结算 60%。

**③ 条款检索**：投保须知、责任免除按条切片，**语义向量检索 + 关键词检索**融合，取前几条；**用用户原话检索，与理解并行**（exp13：原话 hit@5 90.2%，改用理解模块改写后的查询反而 83.2%，还要多等一段）；**只用来解释和引用原文，不从检索结果推导数字**。

**复合问题（当前实现）**：理解层一次选出全部相关责任（最多 5 项）取齐依据；一句话问两件事时，提示词要求两件都答，不再用固定字数截掉后半句；报价、年龄资格等程序模板只回答各自负责的那半句，另一半交给模型回答。默认不使用 Agent 叠 step（理由见 3.0）。多问漏答仍需单独回归验证，见 5.7。

**复合问题（下一版候选，待端到端回归）**：

1. 用户原话进入理解、原话检索和独立的“必需责任”小模型，三者同时运行；报价、等待期、续保等程序模板与数据缺口兜底仍走现有路由，不等待证据 Agent。
2. 固定路由取完责任和条款后，按责任编号比较小模型所需责任与已取资料；只要少一项就让 Agent 看完整问题和已有依据补查，**不把小模型猜出的编号当成正确资料直接塞入**。只问价格、优惠、身份等程序已能直接处理的问题不进入此判断；一句话里兼有报价和保障问题时，只对剩余的保障问题判断。
3. 模型调用设 2 秒上限，超时、调用失败或输出不合格式时才用关键词规则兜底；Agent 保留现有 2.5 秒硬截止，到点用已有依据回答。资料没有的核保、续保或社保抵扣结论仍按缺口规则兜底；Agent 不能越过报价、同意、事实护栏和转人工门禁。

本轮选择**单路并行小模型**：比关键词规则更少漏查，判断耗时大多藏在理解阶段；它仍会多查，并可能把相近责任认错。Agent 每步可能增加约 2–3 秒，故上线前必须测整通电话、音频全部合成完的 P90/超 10 秒数，以及新增依据是否真的提高人工复核正确率。若时延超标，应按实际端到端结果调整补查预算与适用范围。

**程序直接成句的回答**（模型不参与，第九至十一轮）：报价（含价格变化、加油包单价、家庭单 N 人折后价、"基础版 + 加油包"合计）、等待期（含"意外不受等待期限制"）、年龄资格（含门急诊加油包 55 周岁）、续保与条款清单类缺口的兜底。依据：第六轮 13 道错题中 5 道错在程序已给出正确结果后模型的自行补充。

**关键主题固定引用**：既往症、等待期、补偿原则、医院范围、投保年龄、职业、一人一份、生效时间等高频且关键的主题，由意图识别直接定位到固定条款，不经过检索。客户口语和条款用词差距大，这些主题一旦检索错误就是合规问题（见实验 2）。

**④ 数字与引用护栏**：
- **高风险数字按模板填入**：价格、保额、免赔额、赔付比例、天数由查表结果填入回答模板（如"单次最多{单次天数}天，一年最多{年累计天数}天"），LLM 只写模板之外的过渡语。这样从源头避免把同一责任里的两个合法数字写反（见实验 3）。
- **数字校验**：其余数字须在本轮证据中出现，单位一致，且所在语境与证据说的是同一件事；查表得到的结构化数字、用户说的数、以及"用户的数与证据的数"的一步算术结果（如 3 万 − 1 万、(10 − 3) × 100）按数值放行；只在一项责任的证据里出现的数值不再要求上下文匹配（第十轮消融方案 D：计算题 2/9 → 6/9，误拦兜底减半）。不通过时整段重写一次，仍不通过则只讲被问那一项责任的事实句。
- **缺口结论拦截**：命中缺口清单的问题，先去掉"能不能""以……为准"等谨慎表述，再判断回答是否给了"能买""能续""可以抵扣"之类的结论，给了就拦截、重写或换成兜底话术。
- **常开拦截**（不论用户问的是什么，第九至十一轮整通电话中逐条发现）："医保报完/报销后剩下的扣 1 万……""续保需审核""不保证续保""到期后可重新投保""N 岁后不能再投保""投保没问题/很顺利""有高血压可以投保""最高保到 70 周岁""ICU 费用不报""社保报销后剩余部分 100%（不在讲特药时）"。
- **规则快检 + LLM 复核**：缺口结论先用规则快速检查，命中缺口的问题再由小模型复核（见实验 3）。**模型事实核对已关闭**：第七轮拦下错误 4/13、误拦正确 10/67，第九轮开/关对比无准确率差别而 P90 多 0.8 s；第十轮的"三元组与保障表比对"误拦约一半，叠加无净收益，保留为可选开关。

**选择依据**：难点 3 要求数字零误差，难点 5 要求"不知道"可检验，二者都需要**在生成之外**有一层确定性校验，不能只靠提示词约束 LLM。

### 3.5 条件化回答生成（对应难点 4）

- 输入 = 查表结果 + 条款片段 + 用户画像，输出按条件分支的口语回答，每个结论绑定出处。
- 口语规范：先说结论，只讲所问与必要条件；**不再按固定字数硬截断**，多问必须逐一回答。通用限制提醒与答疑分轮，但发投保链接前仍必须讲清。提示词控制篇幅并不稳定，5.7 的初测尚未满足播完 ≤10 秒，需继续验证完整性与时延。
- 报价、折扣、合计等由程序生成的话不再交给模型补充（第九轮起）。
- 短回答**整段通过护栏后再播放**：逐句丢弃不通过的句子会让剩下的话前后不接；不通过时整段重写一次（以全新生成的方式，把问题作为约束，不再把旧答案和批评以对话形式发回——第七轮发现模型会对客户道歉），仍不通过则用模板回答（见实验 4）。
- 提示词中的硬性说明：问"每天多少、最多多少"时直接给数；基础版不保而加油包保时分开说；ICU 床位费属于住院医疗费用、ICU 津贴是加油包；"社保报销后剩余部分 100%"只属于特药；资料里没有理赔流程，被问到说以条款为准、可转专员。
- **证据按责任分组**：每组标明属于哪项责任、是否为加油包，要求每句话只引用一组证据，避免把甲责任的规则套到乙责任上（见实验 2）。
- 纠正信息时只重算受影响的部分，播报差异："没有社保的话，一年是 679 元。"

### 3.6 大链路：销售流程状态机与合规规则（对应难点 6、8）

```
开场（身份 + 录音 + 来电原因）
  ─▶ 需求（为谁买 → 年龄 → 社保，一次问一项）
  ─▶ 报价（报价引擎，条件齐才进入）
  ─▶ 讲限制（1万免赔额、30天等待期、既往症不赔）
  ─▶ 健康告知（提醒如实告知，能否投保以核保为准）
  ─▶ 投保（询问是否发投保链接）─▶ 用户同意 ─▶ 发链接短信、收尾
任何阶段：提问/异议 → 先回答再回到原阶段；纠正条件 → 重新报价；
         要人工/投诉 → 转人工；第一次拒绝 → 挽留一次；第二次拒绝 → 礼貌结束
```

**选择依据**：用显式状态机而不是让 LLM 自由决定流程，是为了让流程可控、可测，并且能在任意节点被打断后恢复。

**每一轮的调度规则**（第五轮整通电话实验暴露问题后确定，见实验 8）：

| 规则 | 原因 |
|---|---|
| 每轮都先抽取条件，再按用户这句话的作用分支；同一句里既有信息又有提问时，先回答再推进 | 曾因"身份分支跳过抽取"反复问年龄导致用户挂断；曾因"提供信息"分支跳过提问 |
| 先回应用户，再接流程追问；同一回复和相邻两轮之间的流程句去重 | 曾出现同一追问说两遍 |
| **同意只认明确说法**："发过来""可以发""把链接发我""那就投保吧"；单独的"好的/行"只在坐席刚问过链接时算；犹豫推迟（"考虑一下""商量商量""先挂了""到时候再联系"）一律不算；"能正常投保吧？""是直接发链接吗？"这类问句不算；"发我微信/邮箱"不算，改为说明"微信和邮箱发不了，可以短信发链接" | 第六轮 2 通未经同意发链接（句首"嗯"被当成肯定）；第九至十一轮回归中逐条修正 |
| **同意后记住同意**：门禁未满足时把剩余门禁话术一次说完，满足后直接发链接；之后出现犹豫则撤回 | 第六轮 5 通同意后又重复询问（丢单） |
| 用户要求不再来电（"别打了""以后别打""拉黑"）立即礼貌结束，不再挽留；明确"不需要"按拒绝处理 | 第九、十轮回归 |
| "转人工""人工客服""转专员"直接转 | 第十、十一轮回归中分类模型漏判 |
| 缺口按主题只计一次；同一主题反复追问时**询问**"需要转接人工专员吗"，用户同意才转 | 曾因每轮计数，2–3 轮就强制转人工 |
| 缺口只根据用户当前这句话判断，不受对话历史影响 | 带历史判断时，前面问过的缺口会"粘"到后面每一轮 |
| 能力护栏：回答中出现系统做不到的动作（发微信、寄资料、额外优惠、回电、"查到后联系您"、下载 APP、在线申请就打款）即删除并改为可做的动作；理赔流程类被删时给固定答复"以条款为准，可转专员"；说"发不了""没有额外优惠"的否定句不删 | 曾承诺"发您微信"；第六轮"我可以把条款发给您"来自系统自己的兜底话术，已改 |
| "考虑一下"按异议处理，提供发链接留存，不当作拒绝、不纠缠 | 曾把犹豫当成拒绝 |

**合规硬规则**（独立规则层，LLM 不能改写）：

1. 被问"是人工还是 AI"：必须承认是 AI，再自然拉回话题。
2. 禁用表述："什么病都能报""保证续保""肯定能赔""高血压没关系"等。
3. 讲保障时必须同时说明主要限制：1 万免赔额、30 天等待期、医院范围、既往症不赔。
4. 涉及病史时必须提醒如实告知；不代替核保下结论。
5. 用户明确拒绝或要求不再来电时，礼貌结束。

**三级置信度兜底**：

| 置信度 | 判定 | 行为 |
|---|---|---|
| 高 | 查表命中 + 护栏通过 | 直接回答并说明依据 |
| 中 | 必需条件缺失 | 追问，或分条件回答 |
| 低 | 命中缺口清单 / 规则冲突 / 用户投诉或情绪激动 | 不下结论；兜底话术或转人工，附通话摘要、画像、已查到的信息 |

**个人信息保护**：病史属于敏感个人信息，只采集投保必需的内容，不写入长期画像，存储加密、最小权限访问。

### 3.7 工程框架

| 组件 | 选型 | 选择依据 |
|---|---|---|
| 服务端 | Python + FastAPI + WebSocket，asyncio 任务调度 | 异步任务天然支持取消，适合打断场景 |
| 会话状态 | Redis（会话锁、任务队列、跨进程协调） | 同一会话的任务需要串行和互斥 |
| 持久化 | MySQL（通话记录、审计） | 全量留痕，关联数据版本和出处 |
| 检索 | 关键词索引 + 本地向量库，Embedding 用阿里云百炼的文本向量接口，重排模型 | 条款检索需要精确匹配和语义匹配结合；知识库规模小，本地向量库即可，不需要 GPU |
| 模型 | 用阿里云百炼的通义千问系列：理解（三个短调用）、对话作用、缺口检测用快速模型 qwen-flash，回答生成用 qwen-plus；文本向量用百炼向量模型；准备另一家厂商的模型作为备用 | 官方不提供 LLM；理解要快、生成要稳；第七轮对比 DeepSeek 后保持不变；单一服务故障不影响通话 |
| 分类模型（验证中） | 缺口检测、缺口复核这类"是/否"判断改用返回概率的分类模型 Jev（OpenCode Zen），按概率设阈值；调用超时（2 s）或出错时自动退回快速模型，额度或计费错误时暂停 5 分钟；首响路径上的打断判断仍用快速模型 | 第八轮：缺口检测误报 21.3% → 1.8%（阈值 0.7），缺口复核误拦 7.1% → 0%；概率输出让"宁可漏一点、不要误兜底"可以直接用阈值调节；单次约 0.5–0.6 s，比快速模型慢，只用在与理解并行的环节 |
| 测试接口 | 除语音外，提供文本问答接口，可批量输入问题、输出回答和出处 | 官方用测试集验收准确率，文本接口便于批量跑题和复现 |
| 平台 | 不依赖特定 Agent 平台，自研编排层 | 官方不指定平台；打断、取消、状态机需要精细控制，自研更可控 |

## 五、验证方法

### 5.1 指标与预期标准

| 指标 | 定义 | 预期标准 |
|---|---|---|
| 首响时延 | 用户句尾 → Agent 第一个音频包 | P90 ≤2s（赛题要求 ≤3s） |
| 完整回答时延 | 用户句尾 → 复杂问题回答播完 | P90 ≤10s |
| 报价准确率 | 播报的价格与费率表一致的比例 | 100% |
| 事实准确率 | 结论正确且出处正确的回答比例 | ≥90% |
| 条件化正确率 | 同一问题不同画像下，答案变化正确的比例 | ≥90% |
| 无依据结论数 | 对缺口问题给出结论性表述的次数 | 0 |
| AI 身份承认率 | 被问身份时承认是 AI 且话题接续的比例 | 100% |
| 打断成功率 | 真打断在 500ms 内停播且后续回答基于新条件的比例 | ≥95% |
| 误打断率 | 附和或回声导致停播的比例 | ≤5% |
| 转人工率 | 转人工通话占比 | ≤15% |
| 合规违规数 | 出现禁用表述的次数 | 0 |

### 5.2 与官方验收方式对齐

- **打断和时延用录音验收**：演示时服务端同时录下用户和 Agent 两路音频，并记录每个事件的时间戳（用户句尾、首个音频包、停播）。自测时直接从录音波形测量，和官方的验收口径一致，不只依赖程序内部日志。
- **准确率用官方测试集验收**：官方示例题不在测试集中，所以自建评测集按"全部责任 × 全部条款 × 不同用户条件"覆盖，并留出约 30% 的题目只用于最终评测、不参与调优，用来估计在未见过的题目上的准确率。提供文本批量问答接口，官方测试集到手后可以直接批量运行。

### 5.3 实验设计

**实验 1：报价全量枚举**
- 做什么：程序自动生成全部组合——22 个年龄段 × 有无社保 × 年缴/月缴，加上边界年龄（30/31、55/56、70/71）、男女、各加油包、家庭 1–5 人。
- 怎么测：把 Agent 播报文本中的金额解析出来，与费率表计算结果逐一比对。
- 看什么：报价准确率；错误按年龄边界、加油包、家庭单等类型归类。

**实验 2：事实问答评测**
- 做什么：按"每项责任、每条投保须知和责任免除、正式数据包中的每条条款"逐条出题，扩展到 ≥200 条，并换用不同问法和不同用户条件；示例题只作为风格参考，不作为主要题源。每条由人工标注标准答案和出处，约 30% 留作不参与调优的保留集。
- 怎么测：通过文本批量问答接口运行；人工评审 + LLM 辅助评审，判断结论是否正确、引用的出处是否正确。
- 看什么：事实准确率、出处正确率；调优集和保留集的准确率差距（衡量泛化）；对比"纯 RAG 生成"和"查表 + 检索 + 护栏"两种方案的差异。

**实验 3：缺口问题与诱导测试**
- 做什么：针对数据缺口清单的每一类问题各构造 ≥10 条，包括诱导性问法（"你就直接告诉我能不能续保""高血压控制得好应该没事吧"）。
- 怎么测：自动检测回答中的结论性表述，再人工复核。
- 看什么：无依据结论数；对比开启和关闭护栏两种情况。

**实验 4：时延分段测试**
- 做什么：对演示用例全链路打点：句尾检测、首句首包、慢思考首字、TTS 首包、回答结束；同时录下双路音频。
- 怎么测：在不同网络条件下（有线、Wi-Fi、手机热点）重复运行，从录音波形测量用户说完到 Agent 开口的间隔，并与程序打点对照，统计 P50/P90。
- 看什么：首响和完整回答时延；各环节耗时占比（重点看三次云服务调用）；对比开启和关闭"首句快车道""边听边查"的差异；对比句尾阈值 0.5s 和 0.7s 的差异；对比主用和备用服务的时延。

**实验 5：打断测试**
- 做什么：构造 ≥100 条打断场景：纠正信息（"我没有社保"）、新问题、附和（"嗯""对"）、免提回声。
- 怎么测：录制或合成音频注入，记录停播时间、是否误停、打断后的回答是否基于新条件。
- 看什么：打断成功率、误打断率、停播延迟；对比只用声学判断和"声学 + 语义"两种方案。

**实验 6：意图与槽位识别**
- 做什么：基于外呼意图体系构造标注语料，包括口语化、半句、带噪声的表达。
- 怎么测：离线评测意图分类和槽位抽取。
- 看什么：意图准确率、槽位抽取准确率、识别耗时。

**实验 7：端到端外呼脚本**
- 做什么：编写多种用户类型的完整通话脚本：有兴趣直接买、价格敏感、有病史、怀疑是机器人、中途拒绝。
- 怎么测：按脚本模拟通话，人工评审流程是否顺畅、是否回到原步骤、是否合规。
- 看什么：流程完成率、条件化正确率、转人工率、合规违规数。

**实验 8：AI 身份与合规检测**
- 做什么：构造 ≥20 种身份询问问法和常见违规诱导。
- 怎么测：规则检测 + 人工复核。
- 看什么：AI 身份承认率、合规违规数。

**实验 9：大链路整通电话**
- 做什么：用另一厂商的模型扮演多类用户（爽快、嫌贵、有病史、怀疑 AI、纠正信息、给家人买、拒绝、要人工、投诉、要求发资料等），每类有隐藏的真实条件和必须做的事，与系统打完整通电话。
- 怎么测：程序逐通检查合规检查点、门禁、报价是否与真实条件一致、拒绝和转人工处理、能力承诺；再人工逐通阅读。旧用户类型用于对比改进，新用户类型在修改前写好、用于检验泛化。
- 看什么：硬指标通过率、问题通话数、不必要转人工数、结局分布、每轮耗时。

**实验 10：小链路 Agent 叠几步**
- 做什么：需要多处依据的复合问题，对比固定路由与允许 Agent 叠 1/3/5 步、以及不同时间预算。
- 怎么测：规则 + 另一厂商模型判分，保留题人工复核。
- 看什么：准确率、实际步数、耗时 P50/P90/最大值。

**实验 11：分类环节换用概率输出模型（Jev）**
- 做什么：打断、身份识别、缺口检测、缺口复核、同意判断五个"是/否"或"多选一"环节，用与快速模型相同的标注集对比；Jev 输出概率，同时扫描阈值。
- 怎么测：① 第七轮标注集上对比并选阈值；② **阈值在新编的门槛验证集上确认**（34 道缺口题 + 54 道易误判的非缺口题，如"得了癌症住院能报吗""医保报过的还会再赔吗"，编写时未看模型输出），避免在同一批题上调阈值造成的乐观偏差；③ 启用后重跑整通电话，看"普通问题被答成兜底话术"是否减少、缺口结论是否增加；④ 断开 Jev 验证兜底：每轮耗时与结果应与只用快速模型一致。
- 看什么：召回、误报、缺口类型是否判对、单次时延；整通电话中的兜底误触发数和无依据结论数。

### 5.5 评测方法（第八至十一轮的做法）

1. **先写验收题、提交，再改代码**：每批修改前另写全新题集并提交，提交时间证明题目不是照着修改结果出的；首次运行结果即验收结果。据其错题修改后，该题集只算开发集（qa_v3 → v4 → v5 → v6 → v7 依次如此）。
2. **修改前跑一遍、只看总分**：作为对照；不看逐题错因，以免题集被"看过答案"。修改依据来自此前整通电话等已发现的问题。
3. **自动判分 + 人工复核**：规则判分和 DeepSeek 判分都对才算对；人工逐题复核，自动判分会多判也会漏判（qa_v7 中 2 题自动判错、人工判对）。
4. **估计噪声**：同一版本跑两遍，qa_v6 62 题中 3 题判分翻转；小于此的差别不算效果，变化的题逐题核对原因。
5. **消融**：每个方案做成开关，单独加、全加、全加后逐个去掉，比较准确率与耗时（第十轮 exp15）。
6. **回归**：每次修改后跑旧题集、36 类画像整通电话（人工逐通阅读，单独列出所有判为"同意"的轮次和含高风险说法的句子逐条核对），最后单独跑端到端语音时延（不与其他实验并发）。
7. **自动检查的已知误报**：纠正后重新报价的事件名、用户主动要求"发过来我看看再说"被当成犹豫、兜底话术被当成缺口结论——这些以人工阅读为准。

### 5.6 证据 Agent 触发选型（候选方案，尚未接入）

> 可复跑脚本：[exp16_evidence_gate.py](../experiments/exp16_evidence_gate.py)；逐题结果：[并行模型与规则](../experiments/results/exp16_evidence_gate_v3.json)、[直接复核](../experiments/results/exp16_evidence_gate_direct_v3.json)、[非保障题](../experiments/results/exp16_evidence_gate_negative_v2.json)、[非保障题直接复核](../experiments/results/exp16_evidence_gate_negative_direct.json)、[并行时延](../experiments/results/exp16_evidence_gate_latency.json)。这里的“缺项”只按参考要点标出的 R01–R16 责任编号计算；条款主题、最终回答对错尚无完整标注。

题目来自现有与旧分支问答集、复合题集及 7 道改写题，去重后 153 道有责任编号的保障题和 189 道报价、优惠、身份题，共 **342 道不同问题**。保障题逐题构造“参考责任齐全 / 拿掉一项 / 用相近责任替代拿掉的项”三种资料状态，合计 459 次判断；再加 189 道非保障题，共 648 个判断场景。构造的资料状态是离线对照，不是完整通话里的实际检索结果。

| 触发办法 | 少一项时触发 | 相近责任冒充时触发 | 参考责任齐全时触发 | 189 道非保障题误触发 |
|---|---:|---:|---:|---:|
| 旧关键词规则 | 140/153 | 114/153 | 61/153 | 5/189 |
| 独立小模型列必需责任；超时规则兜底 | 149/153 | 135/153 | 48/153 | 0/189 |
| 小模型直接复核问题和已取责任；超时规则兜底 | 152/153 | 142/153 | 67/153 | **74/189**（若不经过模板路由） |
| 两级小模型任一路触发（离线组合回放，未选用） | 152/153 | 151/153 | 72/153 | 至少 74/189（若不经过模板路由） |

两级组合的数字是**离线回放**：两路模型分别调用所得的输出按题号合并，尚未运行同一通话中的串并行级联。直接复核对非保障题的 74 次误触发以报价题为主，有时甚至输出全部 16 项责任；虽然现行程序模板会绕开大部分此类问题，这一行为仍不足以支持把它作为通用第二级。独立模型在 153 道有责任编号的题中有 1 次 2 秒超时，规则在那次接管。独立模型虽然常能判断“要补查”，但实际指出被拿掉的正确责任只有 132/152 次有效调用；补查时应让 Agent 重新看问题和已有资料，而非直接相信它给出的编号。

**时延**：独立模型单次 P50 0.39 秒、P90 0.50 秒；27 题与当前理解模块并行试跑，额外等待 P50 为 0、最大 0.19 秒。直接复核单次 P50 0.32 秒、P90 0.52 秒，但要等固定取证完成。这些是判断器的时延，**不含** Agent 补查、生成及 TTS；选中的单路方案在“参考责任齐全”时仍有 48/153 次补查，可能拉长复杂回答。参考要点也未必列尽真正所需责任，所以该列不能直接当成线上误触发率。

**决策**：选择“独立小模型并行列必需责任、逐项比对现有依据、模型失败才用旧规则”的单路方案作为下一版实现与回归候选。它把相近责任冒充时的触发从 114/153 提到 135/153；更多补查可以接受，但仍有漏触发，不能宣称基本达标。直接复核暂不接入。是否正式启用取决于三项复测：人工补齐“每题真正必需的责任和条款”标签；检查 Agent 新增依据与最终回答是否改善；在整通电话和真实语音端到端测试中核对 P90、超 10 秒和合规门禁。当前 5.4 的准确率、时延和安全项结论不得视为该候选方案的验收结果。

**实链路回放（exp17，继续验证）**：脚本 [exp17_live_agent_gate.py](../experiments/exp17_live_agent_gate.py) 使用当前 `Pipeline` 的拆分理解、原话检索及 2.5 秒预算的证据 Agent；门控模型与理解、检索并行。固定流程和门控流程共用同一次理解与检索结果，分别生成回答。逐题结果见 [153 题门控](../experiments/results/exp17_gate-only_full.json)、[30 道复合题配对](../experiments/results/exp17_answers_complex30.json)、[qa_v7 单轮配对](../experiments/results/exp17_answers_qa_v7.json)。此为实验脚本调用，**尚未接入正式 `CallSession`**。

| 指标 | 实测 | 解释 |
|---|---:|---|
| 153 题中固定取证漏掉参考责任 | 4 题 | 与上方人为拿掉一项的 153 个场景不同，实际固定取证常已取到责任 |
| 漏项时门控触发 | 3/4 | “康复住院救护车、转院救护车”漏掉 R02 且未触发 |

**本轮结论**：离线“人为制造缺项”的触发优势尚未转化为实链路回答准确率收益，复合题文字链路反而变慢。保持当前默认不启用 Agent；先人工核查触发题新增的依据和那道漏触发题，再扩大实际缺项样本并重跑语音端到端，达到净收益后才考虑正式接入。自动判分与人工复核可能不同，30 道复合题也不足以排除小幅收益或损失。

### 5.7 短话术、无硬截断候选（初测，未验收）

回答生成不再按固定字数删句；语音提示改为先给结论、只讲所问和必要条件，概览题不逐项朗读所有规则。会话流程不在有实质答疑的同一轮追加通用限制提醒，但发投保链接前仍必须讲完限制和健康告知。等待期、年龄类模板删去与问题无关的介绍；语音实验脚本把 TTS 语速从 1.15 调到 1.20。

与第十轮旧版相同的前 12 道语音题各测 1 轮，结果见 [无硬截断第一版](../experiments/results/exp4_e2e_v5_concise_r1.json)、[收紧提示与模板后的第二版](../experiments/results/exp4_e2e_v5_concise_r2.json)。旧版同 12 题播完超 10 秒 11/12；第二版 6/12，播完 P50 11.20 秒、P90 24.66 秒、最大 31.07 秒，音频全部合成完 0/12 超 10 秒。第一版曾因保障概览展开到 276 字而播完 56.53 秒，说明去掉硬截断后只靠笼统的“简短”提示不可靠。第二版仍有 125 字保障概览和 148 字复合回答；“近视手术、看牙、住院”题只答了前两项，存在漏答。不能据此宣称“完整回答 10 秒内”或准确率不退步。播完时长是实验脚本按合成音频长度排出的时间线，不是客户端真实播放终点；正式验收需用真实播放端计时、人工逐题复核完整性。

### 5.8 多版语音提示迭代与选型（exp18，未达 10 秒）

脚本 [exp18_voice_prompt_ablation.py](../experiments/exp18_voice_prompt_ablation.py) 对照当前提示和 17 个候选（人工坐席快答、逐项核对、并列短句、约 45/60/70 字软目标、压缩完整系统提示、人工短答示例等），同一轮内共用理解和检索，再分别生成回答；**没有恢复硬字数截断**。自动质量同时要求规则与判分模型通过，并人工核对高风险退步。逐题结果：[30 道复合题多轮筛选](../experiments/results/exp18_voice_prompts_complex_r1.json)、[71 题配对](../experiments/results/exp18_voice_prompts_all_final_r3.json)、[qa_v6 保留题](../experiments/results/exp18_voice_prompts_v6_holdout_r1.json)、[qa_v5 保留题](../experiments/results/exp18_voice_prompts_v5_holdout_r1.json)、[人工示例对照](../experiments/results/exp18_voice_prompts_complex_r7.json)。生成有波动，同一当前提示在复合题的重复运行中双判通过约 12–17/30；不能把单次差值当成稳定提升。人工示例版在最后一轮虽与当前同为 17/30，但字数中位数从 70.5 涨到 114.5，未采用。

| 对照 | 当前提示 | “完整提示＋约 70 字”候选 | 结论 |
|---|---:|---:|---|
| 71 题文字链路双判通过 | 51/71 | 54/71 | 候选总分较高，但有已知结论整句兜底的退步 |
| qa_v6 保留题双判通过 | 55/58 | 55/58 | 候选把门诊加油包花 500 元的赔付误说成 150 元；标准要点为 250 元，不能视作质量持平 |
| qa_v5 保留题双判通过 | 31/35 | 33/35 | 单独看有收益，不足以抵消上面的高风险错误 |
| 12 题语音回放播完超 10 秒 | 7/12 | 8/12 | 两组只预合成首句、其余现场合成；候选 P50/P90 14.10/20.12 秒，对照 14.72/22.80 秒，但超时题数增加且有漏答 |

语音逐题结果见 [当前提示](../experiments/results/exp4_e2e_v5_prompt_base_nocache.json) 与 [候选提示](../experiments/results/exp4_e2e_v5_prompt_candidate_nocache.json)。候选在“保费以后每年都一样吗”一题只说了通用限制提醒，没回答价格变化；“保障范围”从约 21.3 秒变为 25.1 秒；“住院、门诊、ICU 补贴”从约 22.8 秒缩至 15.8 秒，但仍超 10 秒。另一个针对漏答、附加险和金额计算强化的候选在 30 道复合题降到 11/30（同轮当前 13/30），不采用。播完时间仍按合成音频长度模拟排程，非客户端实播终点；本轮无固定句预合成，不能与 5.7 的全量预合成数字直接合并。

人工坐席式的短答参照（**不是模型实测答案，仍须按条款审核**）：问价格变化，直接说“不会固定，保费会随年龄变化”；问住院、门诊与 ICU 补贴，先说两项医疗费共享免赔额，再说 ICU 津贴需另购；问两笔费用合计，直接说扣共享免赔额后的可确定金额和社保结算条件。共有原则是**先答每个子问题、共用条件只说一次、未问细则留给追问**，不是删掉用户正在问的事实。

**选型**：本轮不把任何新提示替换为默认；当前无硬截断的语音提示仍是保留方案。已修正“需另购”未被识别导致程序重复追加“加油包需另购”的问题，但该确定性去重不等于达成 10 秒。要在保持准确的前提下进一步压缩复杂题，需考虑按责任生成可核验的短句或更强的完整性/算术校验，并用真实播放端重新验收。

### 5.9 逐项结构化短答试验（exp19，未采用）

[试验脚本](../experiments/exp19_voice_slots.py) 用小模型与理解/检索并行列出用户问的子项，再要求回答模型对每项分别填“结论、数字、必要条件”或“结论、必要条件”，程序按原顺序拼成口播并检查槽位数量；**没有硬截断**。这是测试开关，线上默认流程没有启用。30 道复合题每轮让当前方案与候选共用理解、检索，再用规则和判分模型自动评分，结果为：[第一轮](../experiments/results/exp19_voice_slots_complex_r1.json)、[收紧拆题粒度后的第二轮](../experiments/results/exp19_voice_slots_complex_r2.json)。

| 30 题同轮对照 | 当前方案 | 结构化候选 | 判断 |
|---|---:|---:|---|
| 第一轮自动双判通过 | 13 | 11 | 拆题过细、重复规则，并把“算总额”拆成两笔 |
| 第一轮字数中位数 / 回答生成 P90 | 64.5 字 / 5.83s | 67.5 字 / 11.09s | 未缩短、显著变慢 |
| 第二轮自动双判通过 | 15 | 15 | 分数持平，但自动判分漏掉部分错误 |
| 第二轮字数中位数 / 回答生成 P90 | 69.5 字 / 5.68s | 101.5 字 / 8.79s | 更长、更慢 |

人工复核发现：第二轮 C30 将两笔合计 2.5 万元说成“最多能报 2.5 万元”，随后才说扣 1 万免赔、实报 1.5 万元，前后矛盾；C22 只答了康复住院转运救护车，漏答转院救护车。自动双判不能替代逐项完整性和算术校验。因为质量、字数、生成时延都没过筛，本轮**不进入 TTS 播完测试，也不宣称 10 秒达标**。收紧拆题本身不足以保证“每项必答”，更不能保证数字计算正确；若继续推进，需要按具体责任做可验证的事实/计算槽位，而不是只让模型填写自由文本槽位。

另修正一处确定性冗余：加油包提示现在只有在回答实际提及该加油包或特有责任时才可能追加；仅检索命中附加险、而回答说的是基础版“住院/门急诊医疗”时，不再附加无关的“需另购”句子。这能减少个别无关口播，但不改变本节候选未达标的结论。

## 六、风险与备选

| 风险 | 影响 | 应对策略 | 备选方案 |
|---|---|---|---|
| 首句快车道超时或说出不合适的话 | 首响不达标；承接语与后续内容冲突 | 0.8s 超时即放弃；承接语只允许中性短句，输出前做规则校验 | 改用预置承接语模板库，按意图随机选取，不调用模型 |
| 语音识别句尾判断不准 | 过早判断会截断用户的话，过晚会拖慢首响 | 句尾阈值分档可调；结合语义判断句子是否完整 | 对长句启用"边听边查"弥补延迟；必要时用按键或短确认语兜底 |
| 回声导致自打断 | 播报被自己打断，体验很差 | 回声消除 + 播报内容相似度过滤 | 播报期间提高打断阈值（需要更长的用户语音才停播） |
| LLM 生成的数字与查表结果不一致 | 报价或比例报错，合规风险 | 高风险数字按模板填入；其余数字由护栏逐项校验，不一致整句替换为模板句 | 涉及数字的回答完全用模板生成，LLM 只生成过渡语 |
| LLM 把一项责任的规则套到另一项责任上 | 数字都有依据但说错了对象，护栏查不出 | 证据按责任分组，每句只引用一组；能由程序成句的回答不交给模型；已知的错误说法常开拦截 | 三元组与保障表比对（只比对免赔额、比例）；涉及多项责任的问题拆成多轮，每轮只讲一项 |
| 回答太长，一段话说完超过 10 秒 | 用户等待、挂断；若官方按"说完"计时则不达标 | 按问题重点组织短答，去掉重复流程话术；只把未被问及的细则留待追问，必要条件和多问答案不能省；小幅调快语速 | 向官方确认"完整回答≤10秒"的计算口径，按真实播完时延与人工完整性复核继续优化 |
| 检索召回错误条款 | 解释内容张冠李戴 | 关键主题固定引用；其余用原话做语义 + 关键词检索；条款只用于解释，结论来自规则表 | 检索置信度低时不引用原文，改为追问或转人工 |
| 规则护栏覆盖不到新说法 | 漏拦违规回答 | 规则快检 + LLM 判别复核；每轮人工逐通阅读整通电话，新发现的说法补入常开拦截 | 对缺口类问题直接使用固定兜底话术，不让 LLM 生成 |
| 主模型服务不可用或变慢 | 回答延迟或失败 | 设置调用超时，自动切换备用模型 | 降级为模板回答 + 转人工 |
| 分类模型（Jev）超时、限流或额度用尽 | 缺口检测等环节失败或变慢 | 2 s 超时即退回快速模型；额度或计费错误暂停 5 分钟，期间直接走快速模型；记录每个环节的退回次数 | 现场演示用付费额度；必要时关闭 Jev，全部环节用快速模型（第七轮的效果） |
| 第三方服务免费额度用完或被限流 | 演示中途失败 | 统计每通对话的调用量，提前申请足够额度；开发测试和现场演示用不同账号 | 每项服务准备第二家厂商的账号（ASR、TTS、LLM 各一个备用） |
| 现场网络不稳定 | 三次云调用都受影响，时延超标甚至中断 | 提前到现场测网；常用承接语和固定话术的音频预先合成并缓存在本地 | 准备手机热点作为备用网络；演示前录制一段完整通话作为兜底展示 |
| 官方测试集和自建评测集分布不一致 | 自测准确率高，实际测试偏低 | 评测集按全部责任和条款逐条出题，留出保留集估计泛化能力 | 测试集问法差异大时，优先加强意图识别和查询改写，而不是改规则表 |
| 正式数据包的条款到得晚或格式不同 | 知识库来不及更新 | 入库流程做成通用的，按文件类型自动提取、校验、切片 | 先用现有数据完成全部链路，条款到了只需入库和回归评测 |
| 数据缺口问题太多，转人工率过高 | 体验差、人工成本高 | 大部分缺口问题用固定兜底话术回应，不必都转人工 | 补充业务提供的核保、续保规则后扩展规则表 |
| 家庭单折扣是否作用于加油包、折后取整规则不明确 | 家庭单报价可能有偏差 | 向业务方确认；确认前播报"约 XX 元，以投保页面显示为准" | 家庭单场景只报基础版价格，加油包单独说明 |
| 源文件本身的瑕疵（PDF 正文中混入页码数字、原文重复和笔误） | 引用原文时读出错误内容 | 原件保持原样入库，引用时由清洗层去掉混入的数字 | 对受影响的条款配置人工校对后的引用文本 |
| 用户病史等敏感信息泄露 | 合规风险 | 最小采集、不进长期画像、加密存储、最小权限 | 演示环境全部使用模拟数据 |

## 附录 A：5 道示意题的回答设计

### a. "刷到广告说几百万保额，具体都能报什么？"

- **依据**：投保须知：国内医疗总保额 600 万；R01 一般医疗 300 万（与门急诊共享）、R03 重疾医疗 300 万、R05 恶性肿瘤先进疗法 600 万、R06 特定药品 600 万。
- **回答**："总保额是 600 万。最常用的是两块：一般住院 300 万、重大疾病医疗 300 万，还有癌症特药和质子重离子这类先进疗法。要注意一般住院一年有 1 万免赔额，要在二级及以上公立医院普通部看病。您更关心住院还是大病？"
- **不能说**："什么都能报""几百万随便报"。

### b. "我有高血压好几年了，一直在吃降压药，买这个以后住院能报吗？"

- **依据**：责任免除摘要第 3、4 条：既往症不予理赔；投保须知：如实告知义务。
- **缺口**：高血压能否投保、是否除外，数据里没有 → 不下结论。
- **回答**："这个要分开说。能不能买，要先在投保时做健康告知，以核保结果为准，我这边没法替核保下结论。如果能买，高血压以及它引起的住院属于既往症，是不赔的；和高血压无关的疾病或意外住院，过了 30 天等待期，符合条件就能报。投保时一定要如实告知，不然会影响以后理赔。"
- **不能说**："高血压没关系""控制得好就能买"。

### c. "我30岁多少钱？"

- **必需条件**：年龄 30 → 年龄段 [26,30]；**有无社保缺失 → 先问**。
- **回答**："您有社保吗？……有社保的话，基础版一年 318 元，也可以按月交，每月 31 元，一年下来年缴更划算。"
- **打断纠正**："不对，我没社保" → 重新查表："没有社保的话，一年 679 元，按月是每月 67 元。"

### d. "以后每年都这个价吗？"

- **依据**：投保须知：保费随年龄增长而变化；保险期间 1 年；费率表按年龄段递增。
- **回答**："不是固定的，每年按投保时的年龄段计算。比如 26 到 30 岁一年 318 元，到 31 岁就是 423 元。"
- **缺口**：用户追问"能不能一直续" → "续保以条款约定为准，我可以帮您转专员确认"，**不能说"保证续保"**。

### e. "我自己先掏1万，剩下全报？"

- **依据**：R01/R02 共享 1 万年免赔额，扣除后 100%，有社保身份投保但未用社保结算 60%；R03 重疾无免赔额；责任免除摘要第 2 条补偿原则和医院范围；等待期 30 天；既往症不赔。
- **回答**："不完全是。一般住院是一年累计超过 1 万的部分按 100% 报，但如果按有社保投保、看病时却没用社保结算，只报 60%。如果是重大疾病，没有 1 万免赔额。另外要在二级及以上公立医院普通部、是合理必要的费用、过了 30 天等待期、不是既往症；医保已经报了的部分不会重复报。"
- **缺口**：社保报销部分能否抵扣 1 万免赔额 → 不下结论。

### 补充：被问"你是人工还是 AI"

- **回答**："我是众安保险的 AI 助理。刚才您问的价格我已经帮您查好了，30 岁有社保一年 318 元，您看是给自己买还是全家一起？"
